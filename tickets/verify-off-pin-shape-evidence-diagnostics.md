`compile-extension-spike-fixtures-in-the-gate` decided the rule for spike Cargo workspaces that retain compiler-produced golden artifacts: compile them in the Rust sub-gate when the artifact was captured on the toolchain `rust-toolchain.toml` pins, and record an explicit off-pin exclusion when it was not. `spikes/shapes/shape-evidence` is the sole off-pin case — `measure.py:30` sets `TOOLCHAIN = "1.89.0"`, `Cargo.toml` declares `rust-version = "1.89"`, and its README documents `cargo +1.89.0 test` — so its six retained `.stderr` files are correctly not reproduced by the gate. Reproducing them would need a toolchain `AGENTS.md` forbids installing without Tom's authorization, and re-recording them on the pin would destroy the stable-Rust claim the spike exists to make.

**The gap that leaves.** Excluding a workspace from *reproduction* is not the same as leaving its evidence unchecked, and shape-evidence currently has neither. `spikes/extensions/non-exhaustive-visibility` has both halves: the gate compiles it, and `spikes/extensions/run.py --self-test` verifies each retained diagnostic against a JSON record naming the exact toolchain, the expected first line, the diagnostic code, the fragments that must appear, and the fragments that must not. `spikes/shapes/shape-evidence` has no record at all. Its gated pytest module, `test_shape_evidence_measure.py`, tests the measurement harness's deadline and process-group cleanup paths and reads none of the six diagnostics. `spikes/shapes/nightly-dependent-static-shapes` has the reproduction half but likewise no record; it needs the answer to a narrower question, since compiling it already compares fixture to diagnostic.

**Fact — verified by reading, at `89b2eed`.** `find spikes/shapes/shape-evidence -name '*.stderr' -not -path '*/target/*'` returns six files; no JSON record accompanies them; `grep -rn 'stderr' spikes/shapes/shape-evidence/test_shape_evidence_measure.py` returns nothing. So a `TRYBUILD=overwrite` refresh, a hand edit, or a deleted case under that directory changes checked-in evidence with nothing in the gate reporting it — the same decay `preserve-non-exhaustive-visibility-probe` closed for the extension probe.

**Scope of the work.** Give the off-pin spike the record half of the pattern the visibility probe established: a `results/*.json` capturing the exact stable toolchain each diagnostic was taken on, a verifier that checks first lines, codes, required and forbidden fragments, and fixture-set equality in both directions, and a gate entry that runs it without Cargo. `spikes/shapes/shape-evidence` is already in `testpaths`, so the gate entry costs no `pyproject.toml` change. Reuse `spikes/extensions/run.py`'s `verify_visibility_evidence` shape rather than inventing a second one; note that its channel comparison is against `rust-toolchain.toml`, which is exactly wrong for an off-pin spike, so the off-pin form must compare against the toolchain the record itself names and must not silently accept the repository pin.

**Also decide, and record either way:** whether `spikes/shapes/nightly-dependent-static-shapes` needs a record too. Compiling it already proves fixture and diagnostic agree, so a record would add attribution and a fixture inventory rather than reproduction. That is a smaller gap than the off-pin one and may be worth closing in the same pass or explicitly declining.

Do not weaken `scripts/check_rust.py`'s custody predicate or move `shape-evidence` into `GATED_SPIKE_WORKSPACES` to make this easier; installing a second Rust toolchain for the gate needs Tom's authorization and is a different decision.

## Outcome

**Measurement — 2026-07-24, base `412ceae`, arm64 macOS 27.** The host already carried `1.89.0-aarch64-apple-darwin`, so `cargo +1.89.0 test --locked --manifest-path spikes/shapes/shape-evidence/Cargo.toml` ran once by hand — no toolchain was installed. `rustc 1.89.0 (29483883e 2025-08-04)`, commit `29483883eed69d5fb4db01964cdf2af4d86e9cb2`, `trybuild` 1.0.118 reproduced all six compile-fail diagnostics byte for byte and all three compile-pass contrasts. That identity matches the toolchain provenance already retained in `measurements/summary.json`, so the record below states what the recorded compiler was observed to emit rather than transcribed text.

**The record.** `spikes/shapes/shape-evidence/results/2026-07-24-macos-arm64.json`, schema `tiler-shape-evidence-diagnostics/v1`. Per compile-fail case it pins the expected first line, the ordered sequence of every `error[E….]` code the file emits, the required fragments, and the forbidden fragments; per compile-pass case it requires no retained diagnostic. It also digests every input that determines what those diagnostics say — `Cargo.toml`, `Cargo.lock`, `src/lib.rs`, `tests/ui.rs`, and each fixture and `.stderr`. Four cases carry real negative evidence: the two `E0080` reduction cases forbid each other's assertion message, and the two `E0308` cases forbid each other's evidence class, since each pair shares a code and one pair shares a first line.

**The verifier.** `spikes/shapes/shape-evidence/verify_evidence.py` follows `verify_visibility_evidence`'s shape and invokes no Cargo. Its channel comparison is inverted for the off-pin posture: the recorded channel must *not* be the repository pin, and must equal what `measure.py`'s `TOOLCHAIN` executes with, the release series `Cargo.toml` declares, the selector the README documents, and — for `trybuild`, which normalizes the retained text — the version `Cargo.lock` pins. `measure.py` is parsed with `ast` rather than matched textually. The input digests are the second difference: a compiled spike gets its total check from compilation, and this one never compiles, so nothing else would notice `src/lib.rs` moving under a diagnostic that quotes it.

**The gate entry.** `spikes/shapes/shape-evidence/test_shape_evidence_record.py`, collected through the existing `testpaths` entry with no `pyproject.toml` change — verified by running the gate, not inferred. Twenty-two tamper cases each corrupt a copy of the spike and require the exact refusal. The first test also names the nine-case inventory literally, which is the only statement that rejects a case deleted from the tree and the record at once. Added cost: 23 tests in 0.28 s.

**Live teeth, on the real checked-in files, each reverted.** A message re-recorded under another code — `.stderr` and the record's `first_line` both moved from `E0277` to `E0091` — fails with `tests/ui/fail/implement_evidence.rs now reports diagnostic codes ['E0091'], recorded ['E0277']`. An unrecorded fixture fails with `tests/ui/fail fixtures ['tests/ui/fail/unrecorded.rs'] are present without a record or recorded without a fixture`. A recorded fixture removed fails with `recorded fixture is missing: tests/ui/fail/forge.rs`. Editing `src/lib.rs` fails with `inputs ['src/lib.rs'] no longer match their recorded digest`.

**Sibling decision — `nightly-dependent-static-shapes` gets no record, and one half of the gap is closed instead.** The gate compiles it on the pin every run, so reproduction is its total check and a record's first lines and fragments would have to be re-recorded by hand at each pin migration. The one thing reproduction cannot see is a case deleted from both the tree and the transcript's expectations; `retained_fixture_inventory_is_complete` in `conformance/tests/ui.rs` closes that, and removing `rank_array_length.rs` now fails with `left: ["forge.rs", "implement_evidence.rs", "unequal_shapes.rs"]` against the named list. What remains — compilation proves fixture and diagnostic agree, not that the agreed diagnostic is still ADR 0067's claim — is filed as `record-gated-shape-spike-diagnostic-claims`, because closing it well means lifting the gated-record verifier out of `spikes/extensions/run.py` into shared form, which crosses scopes this ticket did not hold.

**Still unverifiable from inside the gate.** Whether the six diagnostics are what stable 1.89.0 *currently* emits. The record fixes what they were on 2026-07-24 and the digests fix the tree they describe, but only a 1.89.0 compiler compares the two, and the gate has neither that toolchain nor authority to install one. The by-hand run above is that comparison for this commit; it is not a standing guarantee. `scripts/check_rust.py`'s `OFF_PIN_SPIKE_WORKSPACES` also states `"stable 1.89.0"` as free text, a fourth statement of the toolchain that this verifier cannot cross-check because it lives in `implementation/workspace`; the four statements inside the spike are checked against each other instead.
