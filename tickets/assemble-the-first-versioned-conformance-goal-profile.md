# Assemble the first versioned conformance goal profile

## Goal

A decision-ready first conformance goal profile selecting an exact accepted obligation population from the independently derived system universe, with explicit included/excluded scope, applicability authority, required evidence predicates, denominator identity, and no editable support status.

## Work

1. Re-audit every dependency result and the live system universe at this ticket's exact base.
2. Enumerate the status quo, a narrow structural-only profile, an optimizer-first internal profile, a serial-sum vertical profile, a combined fail-closed first slice, further bounded research, and deferral where materially distinct.
3. Eliminate any candidate that omits newly declared features silently, defaults applicability/evidence, conflates goal policy with the universe, or claims full support while a required authority is unresolved.
4. For each survivor state exact feature/obligation/case population; included and excluded families; applicability reasons and owner; required evidence predicates; unsupported and required-refusal populations; profile identity/version/lineage; tombstones; runtime/storage cost; and current expected yellow/red/green distribution.
5. Keep internal optimizer/planner obligations first-class. A profile is not limited to features exposed through the end-user facade.
6. Compare survivors on correctness, fail-closed strictness, maintainability, compatibility, host runtime, and memory. Present only the nondominated frontier with strongest counterarguments and reversal evidence.
7. Specify the exact negative controls and acceptance provenance required before the profile can govern qualification.
8. Produce a verbatim-landable candidate schema/profile under `spikes/verification/` or a decision packet if authority still prevents one; do not implement the harness.

## Non-goals

- Do not derive the system universe from this profile.
- Do not hand-mark current support or use expected failures.
- Do not claim “full” means every theoretical tensor-program combination.
- Do not make the ordinary workspace gate require full qualification.

## Stop conditions

Stop for Tom if more than one nondominated included/excluded population survives, if a required obligation has no owner or independent evidence route, or if profile protection needs an unaccepted external authority.

## Acceptance

- The candidate denominator is exact, finite, versioned, and selected from the owner-derived universe.
- Every gray/`N/A` cell carries an accepted authority-backed reason; missing evidence remains yellow or red as appropriate.
- Internal and user-visible capabilities are visible through orthogonal views of the same profile.
- The packet includes cost, unsupported cases, strongest counterarguments, reversal evidence, and all follow-up dependencies.
- Tom receives one concrete decision only if a genuine Pareto trade-off remains.
