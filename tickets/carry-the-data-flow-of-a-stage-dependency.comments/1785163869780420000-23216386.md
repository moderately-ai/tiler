Withdrawn while implementing `preflight-every-entry-of-a-multi-stage-route`. Three checks killed the proposed remedy, and each is reproducible.

**The slot pair would encode a constant.** Every kernel this profile verifies destructures to `[read_buffer, write_buffer]` in `kernel/verify.rs`, and `StageAccessArity` pins the same shape, so each stage has exactly one read access and one write access. The writer's slot is therefore always 1 and the reader's always 0. Carrying them would be carrying `(1, 0)` and calling it evidence.

**A `Data` edge over a named output is not constructible.** The verifier is role-agnostic, but the schedule profile admits only `Input→Intermediate`, `Intermediate→Output`, and `Input→Output`; `read.tensor` is never `Output`. So every `Data` edge's value is necessarily `Temporary`, hence artifact target `Internal`, and the proposed "only when internal" conditional was vacuous.

**The envelope already carries enough.** Given one read and one write per entry, a `Data` edge A→B *determines* the pairing: B's read binding is A's write binding, and a longer chain resolves each pairing uniquely. The runtime now derives exactly that in `shared_allocations` (`crates/tiler-runtime/src/load.rs`) and refuses with `LoadRejection::UnpairableSharedAllocation` when the ends are not determined, rather than guessing — so the fail-open hazard this ticket correctly identified is closed, and without an envelope change.

Also avoided: adding slots to the IR edge would have stepped `PROGRAM_DOMAIN` in `tiler-ir`, changing the bytes of every program ever encoded.

The hazard analysis in the body remains accurate and worth keeping; only the remedy is withdrawn. `measure-artifact-decoder-allocation-amplification` was unlinked from this ticket first, so closing it does not strand a dependent.
