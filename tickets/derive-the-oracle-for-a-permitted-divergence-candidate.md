## User-visible outcome

A derivation of what checks a candidate compiled under a *permissive* numerical contract, so that a bit-different result is qualifiable rather than unqualifiable. **Correction — 2026-08-10.** Filing-time wording said the reference layer can qualify only the strict contract by refusing construction for anything else. That remains a fair description of `ReferenceNumericalConformance::from_realization` and the index-region bridge (order/structure/signed-zero permissions and unvalidated absence assumptions still refuse without a realization witness). It is no longer a whole-layer claim: declared-order reduction under reassociation is normative via `strict_partitioned_sum` / `strict_partitioned_sum_under`, and after [`apply-the-declared-numerical-conformance-on-every-reference-evaluation-path`](apply-the-declared-numerical-conformance-on-every-reference-evaluation-path.md) the declared contract reaches the semantic evaluator and capability paths (`evaluate.rs` module header: "The declared contract reaches every capability").

## Why this exists, and why its trigger has already fired

**Fact — the whole-program oracle refuses a permissive realization outright.** `ReferenceNumericalConformance::from_realization` (`crates/tiler-reference/src/conformance.rs`, search `pub const fn from_realization`) destructures a `NumericalRealization` and returns an error for each of `contraction`, `reassociation`, `permutation`, and `signed_zero` resolved `Permitted`, and for either exceptional-value assumption resolved `AssumeAbsent`. Its module header states the ground exactly: the evaluator computes a separately rounded multiply and add and a strict left fold, which is one legal realization of a permissive contract, and "an oracle that returned a single value would assert a bitwise equality the contract does not promise. … Refusing names each gap instead of hiding it."

**Fact — this is not a flash-class problem and does not wait on any permission.** `NumericalContract::FLUSH_AND_REASSOCIATE_F32` (`crates/tiler-compiler/src/session.rs`, search that constant) is a registered contract; `crates/tiler-compiler/src/request.rs` resolves it (`NumericalContract::FLUSH_AND_REASSOCIATE_F32.resolve()`), and [`calibrate-and-activate-parallel-reduction-selection`](calibrate-and-activate-parallel-reduction-selection.md)'s 2026-08-02 sweep measured under it. So a reassociating candidate is compilable today and unqualifiable today. That is why this ticket is filed `todo` rather than `deferred`.

**Fact — the machinery a bounded oracle would use exists one layer down and is the right shape.** `CertifiedEnclosure`, `decide_predicate` (`crates/tiler-reference/src/accuracy.rs`, search `pub fn decide_predicate` and `pub enum ConformanceDecision`), and the fail-closed three-way `ConformanceDecision` already answer "does this exact-rational candidate lie inside this enclosure" for one evaluation's accuracy predicate.

**Inference — what is missing is the lift from one evaluation to a program, and it is a derivation rather than a wiring job.** A whole-program enclosure is not the composition of pointwise ones — [ADR 0101](../docs/decisions/0101-treat-elementary-function-identities-as-a-fourth-numerical-dimension.md) decision 7 says exactly that of the accuracy contract — and [the certified-bounds record](../docs/research/numerics/certified-bounds-as-rewrite-permissions.md)'s third obligation says a bound derived for a sequential fold does not admit a tree fold. So the object that bounds a program under a permissive contract has to be derived before anything is built.

## What this ticket must produce

- **What the oracle's subject is.** The contract's result *set* is larger than one value; state whether the checkable object is an enclosure derived from the contract and the schedule, a per-candidate bound the schedule carries, or an exhaustive enumeration over a bounded realization space — with the elimination run against correctness, cost, and maintainability rather than preference.
- **How it composes with what already exists.** Whether `decide_predicate` and `CertifiedEnclosure` lift, or whether a program-level object is a different type, and what each answer costs. State it so the answer can be refuted at the type level.
- **The refusal that survives.** `Undecided` must remain reachable and must remain a non-admission; an oracle that always answers is the failure mode this whole layer distrusts. Name at least one candidate class the derived oracle would refuse to qualify and say what closes that refusal.
- **What this eliminates, with grounds.** Per-contract golden regeneration is the obvious alternative and appears to fail on the same ground the refusal above exists for — a golden pins one member of a set the contract does not promise, moving the wrong claim from the oracle into the fixtures where it is harder to see. Run that elimination properly rather than inheriting this sentence.
- **The measurement boundary**, if any bounded probe is run: exact environment, procedure, and what the run cannot separate.

## Non-goals

Implementing an oracle; changing `crates/tiler-reference/`; admitting any numerical permission; deriving the online-softmax fold's own bound (owned elsewhere); qualifying any device row.

## Closes when

The corpus states what checks a candidate compiled under a permissive contract, the elimination among the candidate oracle shapes is stated so a reader can refute it, the surviving shape's relation to the existing enclosure machinery is derived from a source read, and at least one class the oracle refuses is named with what would close the refusal.

## Outcome — 2026-08-05

**The derivation's headline, and it is a narrowing rather than a construction.** The object that soundly bounds a whole program's permitted result set is not an object over the result set at all: it is the exact evaluation of the *one* realization the physical plan pinned, compared bit for bit. A permissive contract does not widen the comparison; it widens the space of *reference programs*, and the plan names which one it implemented. The oracle's subject is therefore a triple — `(program, contract, plan's realization witness)` — and that is the type-level statement the ticket asked for: `from_realization` does not take a plan realization witness (live signature is `(&NumericalRealization, ArithmeticType)`) and is **correct to refuse** a bare permissive realization, because that pair alone does not determine a value. The repair is a witness argument, never a weaker check. The record is [`docs/research/reference/permitted-divergence-oracle.md`](../docs/research/reference/permitted-divergence-oracle.md).

**Fact — this ticket's own premise is half wrong, and correcting it is the most consequential finding.** The premise that "the whole-program oracle is structurally bit-exact-only" and that "nothing in the graph owns an oracle for a permitted-divergence candidate" is true of the *index-region* oracle and false of the corpus. For the one permissive dimension registered and reachable today, the declared-order oracle already exists as `tiler_reference::strict_partitioned_sum` (`crates/tiler-reference/src/evaluate.rs`, search `pub fn strict_partitioned_sum`), is public, is **normative** in [Correctness and testing](../docs/correctness-and-testing.md)'s reduction matrix ("Under a contract that permits reassociation, the oracle is the strategy's own declared grouping, and it stays bitwise"), is exercised CPU-side in `crates/tiler-compiler/src/pipeline/tests.rs` behind a guard that proves the agreement is evidence about something, and has been carried to the qualified M4 Max row by [`drive-a-grouping-sensitive-numerical-case-through-the-parallel-reduction-strategies`](drive-a-grouping-sensitive-numerical-case-through-the-parallel-reduction-strategies.md) — whose 2026-08-02 Outcome already ran this ticket's elimination over a derived bound, permitted-set membership, and a paired operand set. The record credits all three prior statements and generalizes them from one reduction to a program rather than re-deriving them.

**The elimination, run against correctness, refusal-explainability, and computability at reference-evaluation cost.** Five candidates; exactly one survives as the admission authority, so **no fork reached Tom**. A propagated program enclosure is a category error (it brackets the *real* value while the candidate's distance from it is a rounding accumulation, so it refuses correct implementations; repaired, it is not a distinct candidate). A derived-bound interval is sound as a *refutation* and unsound as an *admission* — the interval is a strict superset of the permitted set, and the record exhibits it admitting a kernel that dropped half its input. Set membership is exactly correct, uncomputable past small `V` (`Catalan(V-1)`), and strictly dominated because it discards the declaration the plan published. **Nothing was discarded for being expensive**, which is the check against the cheap-option failure mode: every elimination names what a candidate would silently accept.

**The worked example, with numbers, all reproducible in one command each.** `FLUSH_AND_REASSOCIATE_F32` at `1x4` on `0x3f400000, 0x3e800000, 0x33400000, 0x33000000`. The five order-preserving groupings produce exactly two values, `{0x3f800000, 0x3f800001}`; the serial fold gives the first and the declared two-by-two split the second, reproducing the M4 Max row by hand. **A kernel that silently dropped the two tail contributors returns `0x3f800000`** — which is a member of the permitted set and inside the `gamma_3` interval. So membership admits it, the derived bound admits it, and the strict serial reference admits it; **only the declared-order oracle refuses it.** The `gamma_3` interval admits four representable binary32 values where the contract permits two, and the superset grows to 768 admitted values at `V = 512`.

**The honest split of freedoms, generated by one rule.** *An interval is a valid admission oracle exactly when the permission is itself stated as a tolerance; every categorical permission is discharged by a witness, never by a bound.* Walked over all eleven canonical dimensions. Three are realization-determining functions rather than freedoms (both subnormal dimensions and `MaterializationRounding`, which has one variant and admits no divergence). Four are order- or structure-shaped and pinned by the plan (reassociation, permutation, contraction, reciprocal transform). One is tolerance-shaped and is where the enclosure machinery *is* the admission authority (`ApproximateIntrinsics`). **Signed-zero elimination is neither, and that is a proof rather than a preference**: every metric `decide_predicate` supports is a function of `|z - r|`, and `|(+0) - (+0)| = |(-0) - (+0)| = +0`, so the metric is constant across the freedom and cannot refuse a signed-zero divergence under *any* tolerance including zero — the honest object is a quotient on the comparison. The two exceptional-value assumptions are preconditions, not result freedoms. **Fact — permutation is granted-but-unspendable**: `ContributorOrder` has one variant and the only admitted `ContributorArrival` returns `requires_permutation() == false`.

**The refusal that survives, with a non-empty population each.** Four `Undecided` classes, `Conforms` never guessed. `OrderNotPinned` — a three-leaf `PointwiseF32Expression` chain compiles under a reassociating contract carrying `ReductionTopology::None`, so no field names its grouping. `RealizationNotEvaluable` — a cooperative tile with `rounds > 1`, a wider declared `accumulation`, or a non-uniform split, none expressible by `strict_partitioned_sum`'s flat `partition * chunk + within`. **`ExecutionOrderNotGuaranteed` is the named class the ticket asked for**: Tiler pins the backend today by *asserting* `-ffp-contract=off` and `-fmetal-math-mode=safe`, and `MetalTargetFacts`' five fields and `CapabilityAxis`' seven declare nothing about it — so under a contraction-permitting contract the pin disappears. It closes with a declared target fact plus a measurement, filed. `AssumptionUnvalidated` — the existing refusal, narrowed to the `CompilerProven` case.

**What the bit-exact oracle keeps owning.** Everything, unchanged: there is only ever one comparison relation. `O1` is the surviving oracle at the trivial witness, because a contract strict on every order and structure dimension leaves the plan no choice to make. The derivation removes only the inference that *bitwise* implies *strict*.
