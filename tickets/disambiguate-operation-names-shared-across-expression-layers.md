`Select` was not the only name denoting several unrelated constructs. It was the worst instance, and closing it in `disambiguate-select-across-ir-layers` required enumerating the operation vocabulary of every expression layer, which surfaced the rest of the class. This ticket carries that enumeration so the sweep is not repeated from nothing.

**Fact — the four vocabularies, read at `43f685f`.**

- *Tensor / semantic.* The adopted [operation conformance matrix](../docs/research/numerics/operation-conformance-matrix.md) rows, plus the four keys the standard registry actually registers (`crates/tiler-ir/src/semantic/registry.rs`).
- *Shape expression.* The accepted decisions in [shape environment contract](../docs/research/shapes/shape-environment-contract.md): `Not`, `Equal`, `Select`, `Add`, `All`, `Any`, `Min`, `Max`, `ExactDiv`, `FloorDiv`, `CeilDiv`, `Compare`.
- *ABI expression.* `crates/tiler-ir/src/program/abi.rs`: `ExprNode::{Root, Unary, Binary, Select}`; `AbiUnaryOp::{Not, NarrowU16, NarrowU32}`; `AbiBinaryOp::{CheckedAdd, CheckedSubtract, CheckedMultiply, Minimum, Maximum, FloorDivide, CeilingDivide, ExactDivide, IsMultipleOf, Equal, LessOrEqual, And, Or}`.
- *Structured kernel IR.* The proposed bounded set in [structured kernel IR and verifier boundary](../docs/research/kernel-ir/structured-kernel-ir-verifier.md) — `Constant Builtin Unary Binary Convert Bitcast CheckedNarrow Select For If Yield Load Store AtomicUpdate Barrier Collective` — against the implemented vocabulary in `crates/tiler-ir/src/kernel/model.rs`, whose `BinaryOp` is only `IndexAdd`, `IndexMultiply`, `IndexDivide`, `IndexModulo`, `F32Add`, `F32Multiply`.

**Fact — the exact-spelling collisions that remain after `Select` is closed.**

| Name | Sense 1 | Sense 2 | Hazard |
|---|---|---|---|
| `Minimum` / `Maximum` | Tensor family: NaN-propagating, deterministic `-0.0 < +0.0` | `AbiBinaryOp::Minimum` / `::Maximum`, documented "Unsigned minimum"/"Unsigned maximum" — a domain with no NaN and no signed zero | Highest. Identical to the `Select` failure: `grep -rnw Minimum crates/` finds an implemented `Minimum` and reads as evidence the tensor family is supported. |
| `Equal` | Shape predicate over `ShapeExpr` | `AbiBinaryOp::Equal`, "Unsigned equality" | Low semantically; still two newtyped domain IRs by the accepted decision on domain-specific expression IRs. |
| `Not` | Shape predicate, stated unary in the solver-exchange decision | `AbiUnaryOp::Not`, "Predicate negation" | Low. |
| `Constant` | Registered `tiler::constant-f32@1` | Proposed structured-kernel operation | Moderate: one is a governed key, the other is unimplemented. |
| `Unary` / `Binary` | `ExprNode::Unary` / `::Binary` | Proposed structured-kernel operations | Moderate. |
| `Add` | Tensor `tiler::add-f32@1`, IEEE rounding contract | Shape `Add`, mathematical-integer semantics that explicitly do not wrap, saturate, or overflow | Moderate. |
| `F32Add` / `F32Multiply` | The public semantic authoring facades over `tiler::add-f32@1` and `tiler::multiply-f32@1` (`crates/tiler-ir/src/semantic/standard_operations.rs:133` and `:51`, re-exported from `crates/tiler-ir/src/semantic.rs:53`) | `BinaryOp::F32Add` / `::F32Multiply`, structured-kernel binary operations (`crates/tiler-ir/src/kernel/model.rs:198` and `:200`), consumed by the Metal emitter | High, and unlike the rest of this table both senses are implemented, public, and live in the same crate. One is how a caller authors a semantic graph; the other is an operation inside a lowered kernel body. Found while closing `reconcile-illustrative-operation-names-with-governed-keys`. |

**Inference — a spelling convention already exists implicitly, and is the reason this list is not longer.** The ABI language spells its addition `CheckedAdd` where the tensor family is `Add`; the shape language spells its extrema `Min`/`Max` where the tensor family is `Minimum`/`Maximum`; the structured-kernel research spells its narrowing `CheckedNarrow`. Each avoids a collision that the obvious name would have produced. Nothing records that this is deliberate, so it is applied unevenly — `AbiBinaryOp::Minimum` took the tensor spelling while `AbiBinaryOp::CheckedAdd` did not, and `Select` took the same spelling in all four layers.

**What closes this.** Decide and record one convention, then apply it. The two coherent options are (a) qualify in the glossary, as `disambiguate-select-across-ir-layers` and `disambiguate-contraction-in-the-glossary` both did, which costs nothing at a call site but relies on a reader looking a term up; or (b) make the spelling itself carry the layer, which is what the implicit convention above already half-does, and which would make `AbiBinaryOp::Minimum` an unsigned-specific spelling. Option (b) touches `implementation/ir`, `implementation/artifact`, and `implementation/compiler`, none of which `contracts/foundation` holds, so choosing it means splitting the rename per crate scope rather than doing it here. Do not adopt both for the same name.

**Do not treat this as a rename ticket by default.** Every one of these names is the correct name for its construct within its own layer, and two of them are fixed by accepted decisions. The defect is that the layer is unrecoverable from the name and undocumented anywhere, not that any individual name is wrong.

## Outcome

**Done.** `docs/glossary.md` carries a new section, *Operation names shared across expression layers*, which enumerates the vocabularies, records the convention, and indexes twenty-eight rows of `name` against layer, construct, implementation spelling, and maturity. Six new term rows carry full definitions for the names whose two senses differ semantically rather than only in location — *Add (shape expression)*, *Add (tensor)*, *`F32Add` / `F32Multiply` (semantic authoring facade)*, *`F32Add` / `F32Multiply` (structured kernel operation)*, *`Minimum` / `Maximum` (ABI expression)*, and *`Minimum` / `Maximum` (tensor)*. `docs/ir.md` gains two pointers so the convention is reachable from where the layers are defined rather than only from the glossary.

**Option (a) was chosen, and the choice is on the merits.** The counterpoint is real and should be stated first: renaming `AbiBinaryOp::Minimum` to an unsigned-specific spelling would make the wrong inference *unreachable*, where a glossary row only makes it *correctable on lookup*. That is strictly stronger for the one hazard the ticket ranks highest. It loses anyway, because a convention that cannot be applied to most of its instances is not a convention. Of the names in the table, the shape `Select`, `Min`, and `Max` spellings are fixed by the accepted 2026-07-19 decisions on typed lazy shape selection and specialized min/max expressions; the structured-kernel `Constant`, `Binary`, `Unary`, and `Select` spellings come from research adopted by ADR 0048; and the tensor `Add` and `Minimum`/`Maximum` names are quoted from the adopted operation conformance matrix. Renaming would fight three accepted decisions to fix a subset, while the glossary index covers every instance uniformly. What did land from option (b) is its forward half: the section records that a *new* operation name entering a layer must be distinguishable by key namespace or qualified spelling. That is not adopting both mechanisms for the same name — existing names are qualified in the glossary, and the spelling rule binds names that do not yet exist.

**The convention was not invented here; it was found already implemented and unrecorded.** The governed key layer does exactly this and states why: `tiler::add-f32@1` is the semantic tensor family and `tiler.scalar::add-f32@1` is the scalar operation it lowers into (`crates/tiler-ir/src/semantic/operation.rs:49` and `crates/tiler-ir/src/index/scalar.rs:39`, whose `governed_scalar_op` builds keys in the `tiler.scalar` namespace). The name component is byte-identical; only the namespace separates them, and `docs/ir.md` already gives the rationale — `ScalarOpKey` is deliberately distinct from `OpKey` because one semantic operation may lower into several scalar ones. That paragraph is the strongest evidence for the ticket's Inference, and it is the paragraph one of the two new `docs/ir.md` pointers hangs from.

**Retraction — there are six vocabularies, not four.** The ticket enumerated tensor, shape, ABI, and structured-kernel. It missed two that contribute collisions. The *index and scalar expression* layer is implemented and public: `IndexExprView::{Constant, Dimension, LinearCombination, FloorDiv, Modulo}` at `crates/tiler-ir/src/index/model.rs:585`, plus the `tiler.scalar` keys. It contributes a `Constant` and a `FloorDiv`. The *reference oracle* contributes a third implemented `Add` — `F32BinaryReference::Add` and `StandardScalarBinaryF32::Add`. Missing the index layer is what made the `Constant` row wrong below.

**Retraction — the `Constant` row's hazard rating and its "unimplemented" claim.** The ticket said `Constant` is "one governed key, the other unimplemented", rated Moderate. The structured-kernel `Constant` is implemented and public: `OperationView::Constant` over `KernelConstant` at `crates/tiler-ir/src/kernel/model.rs:777`, emitted by `crates/tiler-metal/src/emit.rs:715`. `Constant` in fact denotes six things, four of them implemented — the tensor key, the crate-private `ExtentTerm::Constant`, the public `IndexExprView::Constant`, the `tiler.scalar::constant-f32@1` key, the public `OperationView::Constant`, and `AddressSpace::Constant`, which is not an operation at all and is declared in the same file as `OperationView::Constant`. `Constant` is the most-overloaded name in the corpus, not a moderate one.

**Retraction — the `Unary`/`Binary` row conflates two different states.** The ticket paired them as "`ExprNode` versus proposed structured-kernel operations". `Binary` is implemented in both senses — `ExprNode::Binary` and `OperationView::Binary` — plus `MetalOperationFamily::Binary`. `Unary` is implemented in the ABI sense only; the structured-kernel `Unary` does not exist, and `grep -rn Unary crates/tiler-ir/src/kernel/` returns nothing. Splitting them is why the table has separate rows.

**Retraction — the `Equal` rating.** Rated "low semantically". Both senses are implemented inside `tiler-ir`: `ExtentRelation::Equal` at `crates/tiler-ir/src/shape/env/constraint.rs:151` (crate-private) and `AbiBinaryOp::Equal`. The shape side is not the unimplemented `ShapeExpr` predicate the ticket assumed.

**Found by the sweep and not in the ticket: `Compare` and `FloorDiv`.** `Compare` is a shape predicate primitive in the accepted typed-Boolean-predicates decision and, separately, `OperationView::Compare` over `CompareOp::IndexLessThan`, implemented and public. `FloorDiv` is a shape-expression division mode fixed by the accepted explicit-division-modes decision and, separately, `IndexExprView::FloorDiv`, implemented and public. The ABI language avoids both by spelling its own `FloorDivide`, `Equal`, and `LessOrEqual`.

**Verified unchanged from the ticket.** `AbiUnaryOp::{Not, NarrowU16, NarrowU32}` and all thirteen `AbiBinaryOp` variants read exactly as listed, with `Minimum`/`Maximum` documented "Unsigned minimum"/"Unsigned maximum" and `Equal` "Unsigned equality" (`crates/tiler-ir/src/program/abi.rs:254`, `:307`). `ExprNode::{Root, Unary, Binary, Select}` at `:423`. `BinaryOp::F32Add` and `::F32Multiply` at `crates/tiler-ir/src/kernel/model.rs:198` and `:200`. The `F32Add` and `F32Multiply` facades at `crates/tiler-ir/src/semantic/standard_operations.rs:133` and `:51`, re-exported at `crates/tiler-ir/src/semantic.rs:53` — all three citations are exact. The conformance matrix's `Minimum`/`Maximum` row reads "NaN-propagating; deterministic `-0.0 < +0.0`". The structured-kernel research's bounded set reads exactly as quoted.

**Invariants recorded instead of counts, because the sibling ticket's count went stale.** Three hold over `crates/`: every `Unary` is the ABI construct, every `Not` is the ABI construct, and every `Minimum` or `Maximum` that is an identifier rather than English prose in a comment is the ABI construct. The last needs the qualifier — a bare `grep -rnw Maximum crates/` returns mostly `/// Maximum bytes of…` doc comments across twenty-five files, so the ticket's stated failure mode is real but its stated search overstates the signal. The reproducing command is in the glossary row. No such invariant holds for `Constant`, `Binary`, `Equal`, or `Add`, and the section says so rather than implying the list is exhaustive.

**One collision needing a code change was looked for and not found.** Given option (a), every entry closes with a contract row. Nothing in the table requires a rename, a re-export, or a signature change to be correct.

**Split, not skipped.** The sweep surfaced one defect of the inverse class: `ExtentExpr` appears once in the corpus, at `docs/ir.md:876`, with no definition anywhere, beside the ADR-fixed `ShapeExpr` that may or may not be the same construct. No glossary row can fix an undefined name without first settling which construct it denotes, and confirming that needs `research/shapes`, so it is `resolve-the-undefined-extentexpr-name-in-the-ir-contract` with the exact searches attached.
