`spikes/apple-targets/numerical_probe.py` compiles every probe offline through `xcrun metal` and `xcrun metallib`. The outcome of `prototype-metal-numerical-realization` additionally reported that the subnormal flush is identical through runtime compilation — `newLibraryWithSource:options:` with `MTLCompileOptions.mathMode` set to `MTLMathModeSafe`/`Relaxed`/`Fast` — on the same device. That observation is not re-established by the checked-in harness and `docs/research/apple-targets/numerical-behaviour.md` records it as an explicit measurement boundary rather than a claim.

The gap matters because the two paths reach the driver through different front ends. If a future toolchain diverges between them, the offline row would stay green while the runtime row changed, and nothing would notice. It also bounds a question ADR 0076 leaves open about where a delivered realization can be read from.

Add a runtime-compilation mode to `numerical_probe_host.m` that takes MSL source and an `MTLMathMode` instead of a linked metallib, run the same kernels and the same execution-witness guard through it, and record the comparison in the retained record so a divergence between the offline and runtime paths fails the gate. Keep the existing self-skip classification: a host with no `MTLCreateSystemDefaultDevice` still skips.

Note that `MTLCompileOptions` exposes no `-ffp-contract` equivalent, so the contraction findings may not be expressible on the runtime path. If so, record that as a precise limitation rather than working around it.

## Outcome

**Measurement — the two paths agree, case by case, on every case.** All 40 runtime cases — eight kernels across `MTLMathModeSafe`, `Relaxed`, and `Fast`, at both `MTLLibraryOptimizationLevelDefault` and `Size` — return bit patterns identical to their offline counterparts at `-O2`, for every operand in the vector. Findings 2, 3, 4, and 5 and the device-observable half of finding 7 all reproduce through `newLibraryWithSource:options:`. The comparison is retained as `comparison.*` rows in the record and is compared on every gate run whose environment row matches, so a future divergence fails the gate by kernel and mode rather than in aggregate.

**Measurement — the two paths are two different compiler builds on this host, which is the load-bearing discovery.** `xcrun --sdk macosx metal --version` reports `metalfe-32023.883` from the Xcode 26.6 MetalToolchain asset; a library compiled by `newLibraryWithSource:options:` and serialized through an `MTLBinaryArchive` embeds `metalfe-32023.921`, from `/System/Library/PrivateFrameworks/MTLCompiler.framework` (`CFBundleVersion` 382.5), which ships with the OS rather than with Xcode. The agreement above is therefore agreement between two separately built compilers, which makes it a stronger result — and it means an artifact's recorded offline toolchain provenance does not identify the compiler that would compile a runtime-compiled kernel. `environment.runtime_compiler` is now a qualifying environment field so a future divergence between them cannot be silently absorbed.

**Fact — the IR half of the guard is unavailable and is not substituted for.** `newLibraryWithSource:options:` returns an opaque `MTLLibrary`. `Observation.operations` is `None` for a runtime case and never `()`: `()` asserts a measured absence of arithmetic, `None` records a question that could not be asked. `subnormal_verdict` skips layer 1 only for `None`, `record_rows` omits the `case.*.float_operations` row entirely rather than writing an empty one, and portable guard tests pin both distinctions on a host with no Apple toolchain at all. What justifies proceeding on one layer is that layer 2 is device-side and *sufficient* where layer 1 is compile-side and merely *necessary* — anything layer 1 would reject emitted no arithmetic, so the kernel returns its operands and layer 2 rejects it too — and that the converse measurably fails: at `-O0` layer 1 passed with two emitted operations and layer 2 caught the deletion. What replaces it operationally is a live discrimination check: every run must show the surviving layer refusing the trap kernel under `relaxed` and `fast`, on results whose unguarded reading is `preserved`, and admitting it under `safe`.

**Measurement — one compile-side artefact survives, as corroboration only.** Serializing the runtime pipeline into an `MTLBinaryArchive` recovers the compiler version string and the presence of individual `air.compile.*` names; the module-level flags match the offline row for every math mode. The container has no published layout and stores its strings concatenated without separators, so a scan can decide presence but can recover neither the option set nor attachment to the `air.compile_options` node — which is precisely what the offline path resolves rather than substring-matches. Nothing in the guard consults it.

**Fact — the offline flags with no `MTLCompileOptions` counterpart, enumerated by reading the complete `@interface` in `MTLLibrary.h` of macOS SDK 26.5.** `-target` (no target property; the runtime compiler targets the running device and OS), `-ffp-contract` (no contraction property), and `-O0` (`MTLLibraryOptimizationLevel` offers `Default` and `Size` only, so finding 7's `-O0` refinement stays offline-only). `mathMode`, `mathFloatingPointFunctions`, and `languageVersion` are exact counterparts of `-fmetal-math-mode`, `-fmetal-math-fp32-functions`, and `-std`; the second is pinned to `Precise` because its documented default is `Fast`, and the host rejects an unrecognized option rather than compiling with one defaulted.

**Measurement — the contraction axis was measured instead of substituted.** Each runtime case is compared against every offline contraction setting recorded for its kernel and mode, so a kernel on which contraction is unobservable yields a plain agreement and one on which it is observable reports which offline setting the runtime path behaves like. The contraction pair returns the separately rounded `3fc58f9e` for `3eb97ef9` at both runtime optimization levels, matching `-ffp-contract=off` and `=on` and not the fused `3fc58f9d` of `=fast`. Separately: `#pragma METAL fp contract(off)` and `#pragma clang fp contract(off)` are both accepted without diagnostic under `-Wall -Werror` and both strip the `contract` flag from the emitted IR under `-ffp-contract=fast`. That is a source-level control and not an `MTLCompileOptions` counterpart, and using it would have changed the source bytes and destroyed the byte-identical pairing, so it is recorded as the available mechanism and not adopted.

**Fact — a latent harness defect found and fixed.** `_run` raised `FileNotFoundError` for an absent executable, so the `unreported` fallbacks in `record_rows` and `environment` were unreachable and a portable test that renders a record crashed on a host without `git`. It now returns a 127 `CompletedProcess`, which every caller already inspects.

**Fact — cost and skip behaviour.** `pytest spikes/apple-targets` goes from 8.2 s to 11.6 s on the measured host, adding 16 tests (25 to 41). On a host with no Apple toolchain, 21 tests skip with a visible reason in well under a second, 18 portable guard tests still run, and `TILER_REQUIRE_METAL_TOOLCHAIN` turns every skip into a failure. The record schema is bumped to `tiler.apple-numerical-behaviour/v2` because `case.*.compile_options` and `case.*.float_operations` became conditional rather than universal.

**Proposal — what the contracts should now say, for whoever holds them.** `docs/backends/metal.md` (`contracts/artifacts`) should state that the AOT backend's toolchain provenance identifies the offline compiler only, that a runtime-compiled kernel is compiled by a separate and separately versioned compiler outside that provenance, and that finding 9's agreement is a bounded measurement on one host row rather than a property of Metal. ADR 0076 needs no change to its conclusion — finding 9 supports it and finding 8 strengthens its central argument — but if it gains a sentence it should be that a versioned target numerical fact must identify *which* compiler the realization was measured on, because a Metal host resolves two. `repoint-adr-0076-evidence-at-the-numerical-record` holds `contracts/decisions`.
