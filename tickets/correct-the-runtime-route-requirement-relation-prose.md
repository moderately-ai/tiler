The relation-vocabulary sweep that produced [`correct-the-residual-floor-relation-prose-outside-the-artifact-scopes`](correct-the-residual-floor-relation-prose-outside-the-artifact-scopes.md) reached only that ticket's three documentation scopes. Two sentences in `tiler-runtime`'s own documentation still describe the live-device route-requirement relation as a floor, and a third framing — "a capacity comparison" — is now imprecise on both sides of the code/docs boundary. The type-name sweep `rename-the-route-resource-floor-vocabulary-for-its-corrected-relation` ran (`ResourceFloor`, `route_floor`, `PROBE_FLOOR`, …) could not have caught these: they name the relation in prose, not the type.

**Fact — two runtime doc comments still assert a floor.** `crates/tiler-runtime/src/load/route.rs:351` documents `LiveDeviceObservation::Quantity` as "Valid only for a quantitative floor. Answering it for a backend feature row is refused rather than coerced." `crates/tiler-runtime/src/adapter.rs:39` reads "would make `Unrecognized`, a wrong-shaped answer, and an unmet floor one outcome instead of three." Neither is true of the landed vocabulary: `crates/tiler-artifact/src/program/requirement.rs` carries a `required` quantity and `is_satisfied_by` reads `RouteResourceDimension::SubgroupThreads => self.required == observed`, so the row is an exact requirement and the refusal `LoadRejection::UnsatisfiedRouteRequirement` names is the row's own relation failing rather than a bound being undershot. Reproduce with `grep -rn "floor" crates/tiler-runtime/src/`.

**Fact — "a capacity comparison" is the same imprecision under a different word, and it spans four sites in two scopes.** `crates/tiler-runtime/src/load/route.rs:341-342` ("an adapter cannot reverse a capacity comparison on its way to an answer"), `crates/tiler-runtime/src/adapter.rs:38`, `docs/decisions/0090-compose-backends-per-responsibility-rather-than-per-backend.md:69`, and `docs/research/extensions/backend-provider-composition.md:70` all use it. The sentence's point — that the *loader* performs the comparison and an adapter only reports — is correct and must survive; what is wrong is "capacity", which implies an ordering in which more is better. Under an equality relation a wider device fails exactly as a narrower one does, which is the whole content of the correction `correct-the-subgroup-threads-route-dimension-meaning` landed at `77c36d5`.

**Why this was filed rather than absorbed.** The floor-prose ticket held `contracts/decisions`, `research/scheduling`, and `research/extensions`. `crates/tiler-runtime/**` is `implementation/runtime`, which it did not hold, and correcting only the two documentation halves of the "capacity comparison" phrasing would have forked them from the code comment that states the same thing — the failure the paired-sentence discipline exists to prevent. So that ticket corrected only the floor assertions its scopes could reach in full and left this one whole.

## What closes this

No sentence in `crates/tiler-runtime/` describes a route resource requirement as a floor or as a capacity comparison; the four "capacity comparison" sites move together so code and documentation still say the same thing; `LiveDeviceObservation::Quantity`'s doc states what it actually is (a measured quantity for a quantitative row, valid only for `RouteRequirement::Resource`); the three-way split of `Unowned`, `Misanswered`, and `Unsatisfied` is preserved with its reason intact; and the two documentation edits carry a dated marker naming this ticket, in the shape the floor-prose ticket used. No behaviour changes and no public item is renamed — this is doc-comment text and prose only, so `cargo test -p tiler-runtime --doc` and a per-package Clippy run are the checks that can fail.

## Outcome

Nine sentences across five files were corrected in one commit. The filed count was six (two floor assertions plus the four "capacity comparison" sites); reading the two crate files in full found three more of the same defect class that the ticket's own `grep -rn "floor" crates/tiler-runtime/src/` reproduction had returned but the body had not enumerated, and one more in ADR 0090 under a different word.

**Fact — the true semantics were read from the source before a sentence was written.** `crates/tiler-artifact/src/program/requirement.rs` was read in full at base `e2b6b87`. `RouteResourceRequirement` carries `dimension` and `required: u64` and deliberately no relation — the module's own heading is "The relation belongs to the dimension, not to the producer", and it states that "a *producer* never chooses it". `is_satisfied_by` is an exhaustive match on the dimension reading `RouteResourceDimension::SubgroupThreads => self.required == observed`. `crates/tiler-runtime/src/load/route.rs`'s `resolve_live_device_requirements` was read to confirm the refusal: the `(kind, answer)` match is exhaustive on both axes, and `RouteRequirementRefusal` is the three-way `Unowned` / `Misanswered` / `Unsatisfied` split that `LoadRejection::UnsatisfiedRouteRequirement` is reached through. So the row is an exact requirement whose relation lives one type away, and no site may name a direction.

**Sites, each read in full before editing.**

- `crates/tiler-runtime/src/load/route.rs` — `LiveDeviceObservation`'s type doc: "the loader decides, so an adapter cannot reverse a capacity comparison on its way to an answer" → "the loader applies the relation that row's dimension fixes, so an adapter cannot decide a row's own comparison on its way to an answer".
- `crates/tiler-runtime/src/load/route.rs` — `LiveDeviceObservation::Quantity`: "Valid only for a quantitative floor" → "A measurement and not a verdict, and valid only for a [`RouteRequirement::Resource`] row: the loader compares it against that row's required quantity by the relation the row's dimension fixes". The intra-doc link resolves; `RouteRequirement` is already imported in the module.
- `crates/tiler-runtime/src/adapter.rs` — the comparison-table paragraph: "reverse a capacity comparison" → "decide a row's own comparison", and "an unmet floor" → "an unsatisfied requirement", which is the wording the two documentation halves already carried after the predecessor ticket.
- `crates/tiler-runtime/src/adapter.rs` — `RuntimeAdapter::observe_live_device`: "a verdict for a floor" → "a verdict for a quantitative one", and "invent a comparison the producer did not state" → "substitute a comparison for the one the row's own kind fixes". The old clause read as though a producer states comparisons, which `requirement.rs` explicitly denies.
- `crates/tiler-runtime/src/load.rs` — `LoadRejection::MisansweredRouteRequirement`: the byte-identical twin of the previous site, corrected identically. **Not enumerated in this ticket's body**, found by reading the file.
- `crates/tiler-runtime/src/load.rs` — `LoadRejection::UnsatisfiedRouteRequirement`: "cannot tell a missing GPU capability from a capacity floor" → "from a live-device quantity that failed its dimension's own relation". **Not enumerated in this ticket's body.**
- `docs/decisions/0090-…:69` and `docs/research/extensions/backend-provider-composition.md:70` — the shared clause corrected identically in both, each with a second dated marker appended beside the predecessor's, in the same shape.
- `docs/decisions/0090-…:139` — "an adapter allowed to answer its own capacity question" → "its own requirement question", with its own dated marker. **Not enumerated in this ticket's body**, and corrected rather than filed because it is the same defect under a different word, sits in a scope this ticket holds, has no twin to fork from, and leaving it would have reproduced inside one ADR exactly the split this ticket exists to close.

**Fact — the residual population was counted, not assumed.** `grep -rniE "floor|capacit" crates/tiler-runtime/ prototypes/serial-sum-run/ docs/decisions/ docs/research/extensions/ spikes/extensions/ | grep -v with_capacity` returns **85 lines at base and 78 at completion** — the seven corrected crate lines are gone, and the three corrected documentation lines remain in the population because each now quotes its own prior wording inside a dated marker, which is the predecessor's convention. The narrower check is the one that closes the ticket: `grep -rniE "floor|capacity comparison" crates/tiler-runtime/` returns **nothing**, against seven lines at base.

Of the 78 residual lines, none asserts the route-requirement relation. `crates/tiler-runtime/src/adapter.rs`'s two "sizes the dispatch and checks its capacity" sentences and their two twins in `tests/adapter_route/adapter.rs` and `tests/identity_join/adapter.rs` are about `plan_dispatch` comparing byte ranges against the limits a context declares — a genuine storage capacity, and a four-way pair left intact deliberately. `tests/adapter_route/fixture.rs`'s five `capacity_bytes` are a field name. All 31 `prototypes/serial-sum-run` hits are device, pipeline, buffer, or threadgroup capacity, or `proof.rs:3192-3193`'s *rejecting* sentence that no artifact field names a threadgroup or buffer-length floor. The remaining ADR hits are unrelated senses — ADR 0098's deployment-minimum floors, ADR 0057's MSRV floor, ADR 0029/0040/0046/0084's floor division, ADR 0047/0051/0097's memory and storage capacity — and ADR 0094's lines 20, 38, 55, and 76 are the *rejecting* and historical sentences the predecessor ticket's completion note already accounted for and instructed not to sweep.
