## User-visible outcome

Four governing records agree on how the selected direct encoded input is validated: checker capability and every selectable alternative's exact enforcement plan are established before `RoutingCommit`; the selected input's unresolved logical conformance begins after that one-way commit and before the selected alternative's first real consumer or any result work. The fused alternative protects its fused contraction access, while the retained materializing alternative protects its `Dequantize`/materialization stage. Hard feasibility is decided per alternative before their costs are compared, and semantic invalidity is terminal rather than a fallback signal.

This is a contract/research reconciliation only. It does not add a public boundary, decide an identity or schema step in advance, implement enforcement, or create a producer that the selected workload does not have.

## Source-first Fact audit — 2026-08-08

- **Verified — ADR 0033's ordering authority.** [ADR 0033](../docs/decisions/0033-semantic-validation-enforcement.md) says that `RoutingCommit` fixes the prepared variant and fallback, `EnforcementCommit` begins unresolved validation, host scans precede result work, and semantic failure never authorizes another mapping. Its source anchors are `Execution has three explicit boundaries` and `Host scans precede result work`.
- **False — artifact-ABI timing.** In [Artifact ABI](../docs/artifact-abi.md), the `Logical value conformance` table row beginning `whether a bound value implements the complete resolved type` assigns that subject to the pre-routing phase, and the paragraph below says a bound scale `belongs before routing`. That contradicts the adopted post-commit route now assigned to this direct input. Preserve the distinct pre-routing obligations — logical-view reconstruction, checker support/preparation, observability/coherence feasibility, physical carrier canonicality, and hard limits — while moving the unresolved logical content check to `EnforcementCommit`.
- **Imprecise — artifact-ABI content work.** That same `Logical value conformance` row says conformance includes `the inclusive code domain`. For the selected `StorageScalar::U8` component whose declared semantic type is U8, the complete logical carrier domain is already the complete governed code domain: the `LogicalScalar` arm [`UnsignedCode(u8),`](../crates/tiler-ir/src/semantic/conformance.rs) cannot express an out-of-range U8. State that the checked carrier/type/scalar-kind relation proof-elides code and zero-point content scans; retain content inspection for positive-normal F32 scales and retain extent, structure, provenance, view, and coherence checks.
- **Imprecise — numerical-semantics scan claim.** [Numerical semantics](../docs/numerical-semantics.md) says `a bound encoded value's conformance is derived from its type` and that `the scan reaches logical elements only`. The first statement is the authority to preserve. Qualify the second so it does not imply that every derived obligation reads content: the full-domain U8 obligations can be discharged from the checked component type/carrier/scalar-kind relation, while the scale still requires a logical-element scan. Preserve its exact-subject evidence and deterministic diagnostic rules.
- **False — runtime record's subject and prerequisites.** [Runtime execution contract](../docs/research/runtime/runtime-execution-contract.md) currently says ``Governed strict-affine `Quantize` now produces typed residual obligations`` and assigns the first runtime vertical after its `producer, physical-candidate, carrier` prerequisites. The selected program contains no `Quantize` or `Assemble`; replace that stale chain with the delivered direct-binding conformance authority and the selected per-alternative first-consumer plans.
- **False — selected-profile timing and graph.** [The first quantized LM profile](../docs/research/numerics/first-quantized-lm-profile.md) currently says `Before routing commit: every scale positive` and still names the obsolete transitive chain through `admit-strict-affine-quantize-physical-candidate`. Replace both with pre-routing support/preparation plus post-commit conformance, and with the direct-input chain. Preserve its source fact that the graph is `input(compound weight) → DequantizeStrictAffine → Contraction` and its retained, separately costed materializing alternative.
- **Verified — current source makes the proposed U8 negative unreachable.** [`UnsignedCode(u8),`](../crates/tiler-ir/src/semantic/conformance.rs) is the exact `LogicalScalar` arm, and `check_scalar` shows that an arbitrary out-of-range U8 payload cannot cross that checked logical-scalar boundary. [`pub resolved_type: &'a ResolvedValueType,`](../crates/tiler-ir/src/semantic/conformance.rs) is the exact `PresentedComponent` type claim, while [`UnrepresentableScalar,`](../crates/tiler-ir/src/semantic/conformance.rs) is the exact `LogicalViewFault` arm. Together with `check_presented_structure`'s component-type rejection and `check_scalar`'s scalar-kind mismatch, those are reachable fault-injection subjects for carrier/type/kind dishonesty.

## Required reconciliation

- Reconcile exactly `docs/artifact-abi.md`, `docs/numerical-semantics.md`, `docs/research/runtime/runtime-execution-contract.md`, and `docs/research/numerics/first-quantized-lm-profile.md` with the accepted ADR and current source. Quote new searchable anchors from source bytes and verify each one against its named file.
- Describe two plan records over the same direct `ValueConformanceSubject`, one per retained physical alternative. The fused plan binds the fused contraction stage that first reads decoded weight elements. The materializing plan binds the `Dequantize`/materialization stage that first reads the encoded components and produces the F32 temporary. No route-global witness may authorize whichever stage happens to run.
- Preserve separate feasibility and costing. An alternative without a complete checker, authoritative logical view, observability/coherence route, hard-limit disposition, and exact protected first consumer is infeasible before cost. Costs remain separate per alternative; `Unknown` is never zero and an infeasible alternative is never selected merely because its enforcement cost was omitted.
- Preserve the one-way lifecycle: preparation and support checks occur before `RoutingCommit`; unresolved content enforcement begins after it; failure is terminal with no result allocation, publication, dependent effect, or fallback; success authorizes only the selected alternative's exact first consumer.
- Separate proof-elided obligations from content scans. For selected U8 codes and zero points, fault-inject a mismatched physical carrier, presented resolved type, element width, or scalar kind. Scan positive-normal F32 scale content. Continue checking component count/order/roles/types/shapes/maps, selected per-axis extents, origin/provenance, route/view, version/coherence, validator revision, and evidence-to-consumer binding.
- Remove the obsolete `Quantize` candidate and internal-grouping chain without inventing an activation-quantization, requantization, or other internal producer. Do not reopen the deferred grouping ticket absent its named trigger.
- Do not pre-require an identity or schema step. State the fields the future implementation must derive, then let its final producer-filled grammar determine whether a version changes.

## Closes when

All four named records state the same direct-input, post-`RoutingCommit`, per-alternative lifecycle; each exact false or imprecise anchor above has been repaired rather than quoted as live authority; fused and materializing first consumers, hard feasibility, separate costs, proof-elided U8 obligations, reachable negative tests, terminal failure, and unsupported cases are explicit; no public boundary or internal producer is invented; `tkt lint`, `make citations`, `git diff --check`, the exact-base guard, and the applicable documentation gate pass.
