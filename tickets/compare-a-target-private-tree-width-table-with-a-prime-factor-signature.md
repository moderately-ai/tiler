## The question

**Proposal.** On another genuinely fresh contributor-grouped matrix, does a bounded target-private non-parametric tree-width table generalize better than a compact policy using a candidate prime-factor signature of the contributor count whose exact request-known vocabulary this study must freeze and prove before timing?

## Why this is separate

The two 2026-08-11 matrices are opened. The predecessor rejected its predeclared row-regime x divisor-neighbour family.

**Inference.** Because both matrices' fit and sealed held-out results are opened, neither is independent validation for a table or any post-hoc observable.

## Experiment boundary

Before timing, freeze a contributor-grouped fit and sealed held-out matrix whose scoring groups are disjoint from both opened 2026-08-11 matrices. Freeze the target-private table capacity, exact key, interpolation rule, out-of-table default, tie order, and complexity rejection. Freeze the competing prime-factor signature vocabulary and prove every component is available from request-known shape and contributor arithmetic before lowering; at minimum name the exact factorization components, encoding, and behavior at endpoints or missing factors. No result may add a term, bucket, table row, or fallback.

Use the same arithmetic-versus-target-admission separation, production baseline, primary-only selection, repeat diagnostic, noise and support bars, source/ABI/oracle anchors, exact result and environment validation, unretained-binary custody distinction, and qualified-host controls as the predecessor. Report table capacity and every occupied/defaulted/interpolated lookup in retained analysis.

Do not reuse either opened matrix as validation, change capped_tree_partition, add a public request or profile field, move feasibility into cost, or change artifact/cache identity. If production use would require new public, identity, construction-time authority, or unsafe-counter work, stop and file that architecture remainder separately.

**Proposal.** Do not spend a second-profile measurement until a frozen policy first meets this host-specific support bar; this study makes no cross-profile claim.

## Frozen protocol — 2026-08-11, before timing

**Proposal — finite population.** The exact row order is `16,384,1536,6144,12288`. The fit contributor groups are `1080,1215,1320,1512,1638,1890`; the sealed held-out groups are `1050,1155,1274,1430,1575,1925`; and the diagnostic-only anchors are `1024,1729`. All five rows and all fourteen contributors are absent from every retained calibration, excursion, shape-aware, and interaction TSV. Anchors affect no fit, family selection, support clause, or complexity decision.

The proper-divisor width counts are `30,10,30,30,22,30` for fit, `22,14,10,14,16,10` for held out, and `9,6` for anchors. That is 152 fit, 86 held-out, and 15 anchor widths per row: exactly 760 fit, 430 held-out, and 75 anchor variants, or 1,265 attempted variants in 70 cells per run. Every contributor is composite. The widest arithmetic candidate is 945 participants, its source request is 3,780 threadgroup bytes, its expected prepared allocation is 3,792 bytes after the existing 16-byte rounding, and the maximum element count is 23,654,400. The qualified entry should therefore admit and verify all 1,265 variants and decline zero; any other census stops before timing.

**Proposal — target-private table.** The table has exactly 30 occupied `u64` entries, one primary-fit raw-minimum width at each exact `(row, fit-contributor)` key. Raw p50 equality chooses the narrower width by `f64::total_cmp` followed by participant count. On an exact row, an exact knot is occupied; a contributor strictly between adjacent knots linearly interpolates in contributor count between the entries' `log2(width)` values and chooses the admitted width at minimum absolute log-distance, narrower on an exact distance tie. A contributor below 1,080 or above 1,890, or any unlisted row, defaults to current `capped_tree_partition` production. There is no extrapolation or cross-row interpolation.

Held-out lookup classes are exactly ten defaults, at contributors 1,050 and 1,925 on five rows, and twenty interpolations: 1,155 between 1,080/1,215; 1,274 between 1,215/1,320; 1,430 between 1,320/1,512; and 1,575 between 1,512/1,638. Anchors add five defaults at 1,024 and five interpolations at 1,729 between 1,638/1,890. Contributor-group leave-one-out rebuilds the table without all five entries for one fit contributor; its fold lookup classes, in fit order, are default, interpolate 1,080/1,320, interpolate 1,215/1,512, interpolate 1,320/1,638, interpolate 1,512/1,890, and default. Retained analysis reports every lookup kind, key, stored value or bracketing pair, interpolation fraction, predicted log-width, and selected admitted width.

**Proposal — prime-factor signature.** The exact structural record is `(contributors: u64, v2: u8, v3: u8, v5: u8, v7: u8, Omega: u8, omega: u8, smallest_prime_factor: u64, largest_prime_factor: u64)`. Its 30-byte device-free encoding is those fields in order: little-endian `u64`, four single-byte named valuations, two single-byte counts, then two little-endian `u64`s. A missing named factor has valuation zero. Zero contributors are refused before factorization; one encodes zero counts and valuations with smallest and largest both one and is never selectable; a prime has both counts one and both endpoints equal to itself but admits no proper-divisor tree; a prime power has equal endpoints. Trial division uses `factor <= residual / factor`, and checked recomposition plus primality checks must reproduce the input exactly. These bytes are a spike record and never artifact or cache identity.

The signature model predicts `log2` of the raw-minimum width from one observation per fit cell. Before the intercept its exact feature vector is `log2(rows), log2(rows)^2, log2(contributors), v2, v3, v5, v7, Omega, omega, log2(smallest), log2(largest)`: eleven features and twelve fitted coefficients. Rows and reduced-axis extents are normalized request arithmetic; the compiler already derives contributors before `capped_tree_partition`, so every component is available before lowering. That observation does not authorize production threading or a storage owner.

Ridge strengths are exactly `0,0.000001,0.0001,0.01,1`. Contributor-group leave-one-out chooses the aggregate `(worst regret, upper-median regret, plateau misses)` lexicographically by `f64::total_cmp` and integer comparison, then smaller lambda. Standardization, zero-variance columns, unregularized intercept, deterministic Gauss-Jordan solution, `1e-12` pivot refusal, and all-lambdas-singular failure are the predecessor's. The final primary model fits all 30 fit cells and chooses the admitted width nearest its predicted log-width, narrower on an exact tie.

**Proposal — primary-only selection and complexity.** Both families use the same minima, contributor folds, objective, and width tie. At the signature's already-selected aggregate-LOO lambda, a table fold is strictly better only when its objective is componentwise no worse and at least one of worst, upper median, or misses is strictly smaller, with no tolerance. The 30-entry table is eligible only if its aggregate LOO objective is componentwise no worse than the twelve-coefficient signature and it is strictly better in at least four of six folds. If either condition fails, the signature wins the complexity order; if both pass, the table wins. A separately reported repeat refit is diagnostic only. Primary table entries, signature parameters, lambda, and selected family are applied unchanged to both primary and repeat held-out results.

**Proposal — noise and support.** Standard error is `stddev / sqrt(30)`. The noise separation band remains exactly the predecessor's `2 * (SE_a + SE_b)`; this study assigns no new confidence interpretation. A selected width misses the plateau only when `chosen_p50 - best_p50` is strictly greater than that band. Over thirty held cells, report exact worst regret, sorted upper median at index `len / 2`, and misses for table, signature, selected family, and current production. A policy survives only when both primary and repeat independently have worst at most 1.10, upper median at most 1.02, at most three misses, worst strictly below production worst, and median no worse than production median. The table must also pass its complexity gate. The repeat reports all-width and unchanged-selected relative-p50 movement and plateau agreement. Anchors remain diagnostic.

**Proposal — custody and stops.** Use a separate harness mode and analyzer with the predecessor's source, ABI, oracle, arithmetic-admission, prepared-entry, exact-result, exact-environment, and unretained-executable custody controls. Retain exact source and lock digests, result digests, equality-pinned environment/load/occupancy, and timed executable before/after digest, size, and mtime; do not claim a byte-identical rebuild or retain the binary. Before timing, unchanged assertions must fail under independent source, ABI, oracle-input, oracle-result, matrix, table occupied/interpolated/default, signature field/encoding/endpoint, result, environment, and executable-custody subject perturbations.

No result changes production, public API, profile schema, artifact/cache identity, or feasibility. A surviving policy that needs production use stops for a separately reviewed authority and threading ticket: current `capped_tree_partition` receives only contributors, and no admitted target-private table owner exists. The estimated direct primary-plus-repeat window is 24–30 minutes; reserve 35 minutes after every build and device-free check is complete, and run nothing without the coordinator's explicit exclusive grant.

The retained [environment](../spikes/program-planning/reduction-partition-calibration/results/2026-08-11-apple-m4-max-macos27.0-26A5388g-tree-width-table/environment.tsv) distinguishes those observed binary facts from the replay-source digests and claims no byte-identical rebuild.

**Inference.** On this finite qualified-host population, neither the frozen table nor the frozen prime-factor signature supports a replacement. Production selection, target cost rows, feasibility, request/profile surface, artifact/cache identity, and public API are unchanged. This is not a portable profile conclusion.
