## The question

On another genuinely fresh contributor-grouped matrix, does a bounded target-private non-parametric tree-width table generalize better than a compact policy using the explicitly different pre-lowering prime-factor signature of the contributor count?

## Why this is separate

The two 2026-08-11 matrices are opened. The predecessor rejected its predeclared row-regime x divisor-neighbour family, so neither opened matrix can validate a table or a post-hoc observable.

## Experiment boundary

Before timing, freeze a contributor-grouped fit and sealed held-out matrix whose scoring groups are disjoint from both opened 2026-08-11 matrices. Freeze the target-private table capacity, exact key, interpolation rule, out-of-table default, tie order, and complexity rejection. Freeze the competing prime-factor signature vocabulary and prove every component is available from request-known shape and contributor arithmetic before lowering; at minimum name the exact factorization components, encoding, and behavior at endpoints or missing factors. No result may add a term, bucket, table row, or fallback.

Use the same arithmetic-versus-target-admission separation, production baseline, primary-only selection, repeat diagnostic, noise and support bars, source/ABI/oracle anchors, exact result and environment validation, unretained-binary custody distinction, and qualified-host controls as the predecessor. Report table capacity and every occupied/defaulted/interpolated lookup in retained analysis.

Do not reuse either opened matrix as validation, change capped_tree_partition, add a public request or profile field, move feasibility into cost, or change artifact/cache identity. If production use would require new public, identity, construction-time authority, or unsafe-counter work, stop and file that architecture remainder separately. A second target profile becomes discriminating only after one policy survives this host-specific fresh validation.

## Closes when

A fresh sealed population either supports the frozen target-private table or prime-factor-signature policy in both runs, or rejects both and records the next bounded observable without changing production.
