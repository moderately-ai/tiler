UNSAFE RULE FOR THIS TICKET'S DEVICE HALF — decided by Tom 2026-08-07, and it is narrower than "use the prototype's precedent".

Full record on `decide-the-conformance-crate-s-unsafe-lint-level-for-device-buffer-access`. Read it before writing any device code. In short:

- `unsafe_code = "deny"` with named `#[allow(unsafe_code)]` at individual sites. **A crate-level allow is refused outright** and is not a fallback if the sites prove awkward.
- **The only admitted justification right now is FFI memory management with Metal** — concretely the raw pointer `metal::Buffer::contents` returns, because `MTLBuffer` storage is reachable no other way. Not convenience, not performance, not a tidier shape.
- **Isolation is a design constraint, not a preference.** Every unsafe site lives in one narrow module exposing a safe API; the conformance logic itself — corpus, oracle comparison, evidence attribution — contains no `unsafe` and must not need to. `prototypes/serial-sum-run`'s `src/buffer.rs` is the shape: two reasoned sites, everything else safe.
- Each site carries ADR 0079's requirements: no safe foreign-API route, a reasoned `#[allow]`, a bounding assertion, and a `SAFETY` explanation naming the invariant and why the foreign API forces it.
- The site population is **named and counted** where a reader will find it, so a later addition is visible rather than absorbed.
- Replace the crate manifest's comment above `[lints]`, which currently describes this as an open fork. It is closed.

The lint level moves **with the first site that needs it**, in this ticket, not as a standalone relaxation — a level moved with no site under it is a relaxation for nothing.

Also still true and unchanged: a host without the measured environment runs the deterministic reference and structural half and reports the measurement boundary as unavailable — never a silent skip, never a claimed pass.
