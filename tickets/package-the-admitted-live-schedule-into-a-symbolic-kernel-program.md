## User-visible outcome

`compile()` of the admitted same-shape rank-one symbolic elementwise population packages its verified source-bound live plan into a verified kernel program and neutral artifact construction plan, so the `deliver macos;` chain's next wall moves from `program-assembly.named-output-symbolic` into artifact family delivery itself.

## Why this exists

[`admit-symbolic-extents-through-schedule-formation`](admit-symbolic-extents-through-schedule-formation.md) landed real schedule formation for this population: the fieldless source-bound live schedule is formed, intrinsically verified, request-bound, assessed, selected, and lowerable to a verified kernel. What remains is packaging, and it is refused by two deliberate fail-closed owners this ticket exists to lift coherently rather than as an implementation fallback:

- **Fact — the compiler assembler's own gate.** `crates/tiler-compiler/src/program.rs`, anchor `named-output-symbolic`: a symbolic named output has no static shape for physical assembly to size, so `CoverAssembly::from_plan` declines with the typed program-assembly capability refusal the frontend now renders as the next wall.
- **Fact — the shared kernel-program identity property.** `crates/tiler-ir/src/program/error.rs`, anchor `SymbolicInterfaceExtent`: the shared builder refuses a symbolic interface boundary so that "no symbolic program reaches a packaged artifact" stays a property of the type — "a symbolic program cannot reach one and cannot ship with its shape-environment subject unrepresented in the artifact's three carried subjects". Lifting it is an identity decision about the artifact's carried subjects, not a code path.
- **Fact — the operand row already exists.** [`carry-live-extent-operands-through-the-artifact-envelope`](carry-live-extent-operands-through-the-artifact-envelope.md) is `done`: `AbiRoot::InputExtent` rows construct, encode, decode, validate, and bind at preflight. What that ticket deliberately did not do is represent the *interface subject* — the shape environment whose decoded root the live plan is bound to — in kernel-program and artifact identity.

## Required work

- Decide, as a packet for Tom, how a packaged symbolic program represents its shape-environment subject in kernel-program and artifact identity (a fourth carried subject, a folded environment identity, or a narrower spelling), preserving the stated invariant that the subject is never unrepresented and the live extent value never enters identity.
- Under the accepted spelling, lift `SymbolicInterfaceExtent` for exactly the admitted population: interface values sized by the zero-extent convention plus honest `AbiRoot::InputExtent` byte formulas rooted at the decoded input dimension (the input side of `build_cover_core` already does this; the internal/output side must join it).
- Replace the `named-output-symbolic` decline for the admitted population with real packaging; keep it, or a narrower named rule, for every other symbolic shape.
- One packaged program identity across bound extents stays testable; a bound value folded anywhere into program or artifact identity is a defect.

## Non-goals

Metal emission, `deliver` cache identity across extents, and the frontend contract flips — those remain [`deliver-an-artifact-family-from-a-symbolic-region`](deliver-an-artifact-family-from-a-symbolic-region.md)'s. Semantic-interface association proof remains [`associate-live-extent-operands-with-symbolic-semantic-interface-axes`](associate-live-extent-operands-with-symbolic-semantic-interface-axes.md)'s.

## Closes when

The admitted population's `compile()` returns a compiled product whose kernel program and artifact plan carry the represented shape-environment subject, or Tom rejects the representation and this records the retained typed decline.

## Decision packet — the shape-environment subject in packaged symbolic identity

**Status: complete, deliberately unqueued pending independent review; then to Tom.**

### The ground

The admitted population — whole-program same-shape rank-one single-symbol `f32` pointwise with a dense-read `InputDimension` root — compiles through a verified source-bound live schedule and declines only at packaging (`program-assembly.named-output-symbolic`). The artifact already answers half of this ticket's title question: since v17 the envelope carries the complete environment subject losslessly and folds it into identity, invocation values never enter those bytes (`crates/tiler-artifact/src/program/retained.rs`, test anchors `invocation_bindings_do_not_enter_artifact_identity` and `changing C, T, and S must not mint a second artifact`), and an unused environment is identity-bearing by pinned test. What remains undecided is (a) the shape-environment subject in **kernel-program identity**, and (b) the **wire spelling of a symbolic interface**, without which no symbolic artifact can encode or decode at the v20/20.0 grammar.

### Consequences forced by any packaging option (not decision axes, but Tom should see them)

- **A symbolic interface spelling must exist on the wire, and it steps the grammar.** The manifest's interface entries state only literal extents (`docs/artifact-abi.md`, anchor `neither constructible nor loadable`, states the fail-closed consequence). A zero-extent literal spelling cannot be reused: `Extent` documents zero as an empty axis (`crates/tiler-ir/src/shape.rs`, anchor `Zero represents an empty axis`), so a decoded record would either misreport a symbolic axis as `[0]` — a silently wrong answer to any interface reader — or require reinterpreting the pre-existing static-zero population. And the environment subject cannot disambiguate: a root binding names only its root `(key, axis)`, so a non-root symbolic axis (inputs `b`, `c`, and the output in the admitted fixture all wear `n` without rooting it) is symbolic **only in the semantic graph**, which travels as opaque identity bytes no decoder reads structurally. The spelling that preserves decoded honesty is a per-axis sourced interface entry — literal-or-symbol, symbol spelled by name — with the tag unconditional, following the semantic graph's own v2→v3 precedent (`crates/tiler-ir/src/semantic/identity.rs`, anchor `tag is unconditional and why a wholly literal`). That lands inside repeated interface records, so by the codec's own stated rule it is a **major manifest step (20.0 → next major) and an artifact domain step (v20 → next)**; lockstep decode means no reinterpretation question survives the step at all. Decode-side coherence checks come with it: a named interface symbol must be declared in the retained environment, and a root axis's interface symbol must agree with the binding the environment roots there — refusing the only way the two spellings could disagree. Construction takes the interface from the verified semantic program, so producers cannot forge it. **Exact numbers must be rederived by the implementation at its own base**: the contraction-replacement migration is landing concurrently and moves identity values (and possibly numbers) across the same tree.
- **The operand row does not widen.** `{ key, axis, value_type }` remains sufficient; the association landing's derivation stands, and the release trigger on [`accept-the-live-extent-artifact-envelope-row`](accept-the-live-extent-artifact-envelope-row.md) is unaffected by every option below.
- **The kernel-program builder lift is condition-shaped, not population-shaped.** Reading Required work bullet 2 exactly: "exactly the admitted population" binds to the stated conditions — interface values sized by the zero-extent convention plus honest `AbiRoot::InputExtent` byte formulas rooted at the decoded input dimension — which is a typed capability statement the shared builder can own. The rank-one same-shape single-symbol gate stays compiler-owned (`admits_source_bound_live_schedule` in `crates/tiler-compiler/src/physical.rs`), and the artifact's association checks (root agreement, declared symbol, non-static axis) stay the artifact's. The lift must not replicate compiler policy into shared IR; it must make representation total so the type property below holds for the whole symbolic vocabulary, and the implementation must keep the packaging population census equal to the admitted one by counted test.

### Eliminated before ranking (gate rule 3)

- **Fold the environment into the semantic graph subject.** Rejected by the accepted three-identity split the fifth subject exists to preserve: binding provenance is interface-side, and folding it into graph identity makes two programs of identical meaning that source one extent from different inputs report different graph identity (`crates/tiler-ir/src/semantic/identity.rs`, anchor `puts binding provenance on the interface side`). It also moves `tiler.semantic-graph` for every environment-carrying program, packaged or not. Misplaces authority over an accepted subject; eliminated.
- **Transitive-only representation (lift the builder, fold nothing new into kernel-program identity).** The argument runs: the graph bytes carry symbol occurrences, the honest `InputExtent` formulas carry the decoded root, and the artifact separates everything else via the retained run. It fails on constraints and unused bindings: two kernel programs over environments differing only by a `SemanticInputConstraint` (or an unreferenced symbol's binding) would share `CanonicalKernelProgramIdentity`, and that identity is a public stability subject — the ADR 0013 plan-determinism witness binds it (`crates/tiler-ir/src/kernel/determinism.rs`, anchor `self.program.canonical_identity()`), and the artifact builder's proof-bound payload join reads it (`crates/tiler-artifact/src/program/builder.rs`, anchor `held.program.canonical_identity().as_bytes()`). A determinism receipt proven against one environment would transfer to a program whose constraint set a backend could legitimately have specialized against — silent misattribution under a subject whose whole purpose is attested reuse. Conflates identities; eliminated.
- **Zero-extent literal wire spelling (no interface grammar change).** Either misreports symbolic axes as `[0]` in the decoded record or reinterprets the pre-existing static-zero population, per the forced-consequences argument above. Eliminated both ways.
- **Anonymous symbolic tag (interface axis says "symbolic" without naming the symbol).** Mechanically executable for the admitted population because all live formulas root at the one decoded root, but it leaves a non-root axis's symbol identity stated nowhere decodable, collapses differently-symbolled future interfaces into one decoded spelling, and forecloses the multi-symbol population for the price of one name field whose construction is unforgeable and whose decode is checkable. Dominated cosmetic variant of the sourced spelling; eliminated as padding.
- **A separately typed public environment accessor on `VerifiedKernelProgram`.** The artifact builder reads the environment from the `SemanticProgram` it is opened against; no consumer needs a second projection, and an unconsumed public surface is exactly what ADR 0075 tells us not to mint. Dominated cosmetic variant of folding in the identity encoder; eliminated.

### The frontier

**Option A — complete-subject fold (recommended).** Kernel-program identity folds the program's `ShapeEnvIdentity` subject bytes as one framed slice beside the semantic graph in `encode_identity` (`crates/tiler-ir/src/program/model.rs`, anchor `data.semantic_graph.as_bytes()`), total over the vocabulary — a program without an environment folds the empty subject's bytes, the same totality the semantic fifth subject and the artifact's v17 carrier both accepted (`docs/research/shapes/symbolic-semantic-extents.md`, anchor `Optional was eliminated on both grounds`). The subject bytes are domain-prefixed and framed (`crates/tiler-ir/src/shape/env/subject.rs`, anchor `SHAPE_ENV_DOMAIN`), so injectivity is preserved by construction. This steps `tiler.kernel-program.v12` to v13 and moves every kernel-program identity value; by the codec's recorded precedent the nested artifact and envelope domains do not step for that reason alone — their values move without their grammar changing (`docs/artifact-abi.md`, anchor `The nested artifact and envelope domains do not step`). Combined with the forced wire spelling, the complete identity consequence set is: kernel-program v12→v13 (this option), artifact v20→next plus manifest 20.0→next major (forced wire spelling), operand row unchanged, `tiler.schedule.v7` / `tiler.kernel.v7` / `tiler.semantic-graph.v3` / the ShapeEnv subject encoding all unchanged, every identity pin recomputed on the merged tree at the implementation's own base. Construction: the builder already receives the `SemanticProgram`; it reads `semantic_identity().shape_environment()` at `new` and the artifact side is untouched. Validation and decode: the artifact's existing retained-run revalidation and the new interface coherence checks carry the whole load; nothing new is trusted. The packaged-identity-across-bindings property strengthens from transitively-arguable to directly testable: one symbolic program bound at 14 and at 15 packages one kernel program and one artifact with byte-equal identities (env bytes contain declarations, roots, and constraints — never values), with the existing negative controls (`a_compiled_plan_does_not_fold_a_bound_extent_value` in `crates/tiler-compiler/src/request.rs`, `baking_neighbouring_extents_mints_distinct_artifact_subjects` in `crates/tiler-artifact/src/program/tests.rs`, and the retained-carrier invocation test) retained unchanged as the value-never-enters-identity guards.
- *Strongest counterargument.* The total fold moves every kernel-program identity — and through it every artifact identity value and pin — to serve a population that still cannot execute (Metal emission stays with [`deliver-an-artifact-family-from-a-symbolic-region`](deliver-an-artifact-family-from-a-symbolic-region.md)); and for static programs the folded environment slice restates a subject the artifact already separates, so the marginal separation it buys at the kernel-program layer is exactly the constraint/unused-binding cases no current optimizer consumes.
- *What would reverse it.* Evidence that kernel-program identity is not, and will not be, a cross-build reuse subject — i.e. a decision retiring the ADR 0013 witness binding or scoping determinism receipts to envelope digests only — would collapse the elimination argument against transitive-only and make this fold pure cost. A measured `MAX_PROGRAM_IDENTITY_BYTES` pressure problem would reopen the framing (though the slice is tens of bytes).
- *Perturbations that would test it.* Build two kernel programs over environments differing only by one `SemanticInputConstraint` and assert their v13 identities differ while their v12 preimages collide (the collision is the pre-fix demonstration; its disappearance is the fix's evidence). Same for one unused symbol binding. Bind 14 then 15 through one packaged program and assert every identity byte-equal. Corrupt the folded slice's framing in a forged preimage and show the digest moves. Confirm a static program's v13 identity folds exactly the empty subject's bytes and that no-environment and empty-environment stay one spelling.

**Option D — typed deferral (status quo).** Keep `named-output-symbolic` and `SymbolicInterfaceExtent` standing; the deliver chain's wall stays at program assembly; no identity domain moves; the association arms stay production-unreachable but tested.
- *Strongest counterargument.* It leaves the entire admitted-population investment — schedule formation, binding, selection, lowering, the p0 association — idling behind a wall this ticket exists to lift, with no new information expected to arrive that would change the representation answer; and both refusal sites carry stale supporting prose whose repair is awkward while the decision is open.
- *What would reverse it (i.e., justify choosing it now).* A pending decision that is about to restructure the artifact's carried subjects — e.g. if the live composition-model packet or the contraction migration were expected to move the semantic-subject run's shape — would make packaging now a double migration; on current evidence the contraction migration moves identity values, not the subject structure.
- *Perturbations that would test it.* The existing ones: the delivered `the_admitted_symbolic_population_declines_at_program_assembly_not_schedule` and the trybuild golden hold the wall's exact text.

**The narrower spelling (ticket option 3) is dominated and not presented as frontier.** At the artifact layer, folding only referenced binding rows would regress the accepted v17 subject — it falsifies the pinned `an unused retained environment is identity-bearing` and reintroduces the collision that step exists to prevent. At the kernel-program layer alone, folding only the rows the live operands reference leaves constraint-differing programs conflated (the same witness-misattribution defect as transitive-only) unless constraints over referenced symbols ride along, at which point the slice needs its own reachability computation whose silent under-approximation is a new conflation path; its one advantage — kernel-program identity stability under unrelated environment edits — never materializes downstream because every packaged, cached, or shipped object already keys on the artifact's complete retained subject. Worse than A on correctness-completeness and maintainability, better on nothing Tom weighs; excluded from the frontier by gate rule 5. The narrower **fail-closed slice** variant (package only constraint-free, fully-referenced environments; refuse the rest by name) is likewise dominated: it buys the same conflation-freedom A buys, but by population restriction instead of representation, adds a new named refusal class over machinery that already works (the SCT constraint carrier and its preflight evaluation), and still requires the forced wire step — so it postpones rather than avoids the only structural cost.

### Comparison of the frontier (gate rule 4)

Both survivors are top-tier on correctness and fail-closed strictness — A because representation becomes total and checked, D because nothing ships at all. On long-term maintainability A is strictly better than continuing to hold the wall (the stale-prose debt, the unreachable tested arms, and the deliver chain's dependency all resolve), at the cost of one coordinated identity migration performed at a base the implementation must re-derive. On compatibility the movement is total but cheap: pre-production, lockstep codec, no external consumers, and the delta rule already forces pin recomputation on the merged tree. Host runtime and memory are unaffected in any measurable way (a domain-prefixed slice of tens of bytes per identity preimage). Kernel performance is untouched by construction. The unsupported population is unchanged by both: everything outside the admitted population keeps its named refusal, and A additionally leaves the broader symbolic vocabulary representable-but-refused rather than unrepresentable.

### Recommendation and the one question

Recommend **Option A**. It is the only option that discharges the ticket's stated invariant as a property of the type at both layers — the subject is never unrepresented (total fold at the kernel program, v17 carrier at the artifact, sourced spelling at the interface) and the live extent value never enters identity (unchanged negative controls) — and its only real cost is an identity migration this repository's rules already make routine.

**Question for Tom:** For packaging the admitted symbolic population, do you accept the complete-subject spelling — `tiler.kernel-program` steps v12→v13 folding the total shape-environment subject beside the semantic graph, and the artifact interface gains the unconditional per-axis sourced entry (major manifest and artifact-domain step, exact numbers rederived at the implementation base), with the operand row and all value-exclusion invariants unchanged — or do you keep the typed decline at `named-output-symbolic` as the recorded outcome? (Recommended: accept; the strongest reason not to is deferring the identity migration until the concurrent contraction migration lands, which is sequencing rather than substance and can be honoured by ordering the carrier after it.)
