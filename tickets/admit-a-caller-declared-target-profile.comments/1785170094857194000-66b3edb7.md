Survey before implementation, recorded so the next session starts from facts rather than repeating it. Nothing was changed; the claim is released.

**This is an identity-bearing refactor, which is what makes it bigger than it reads.** The target profile is encoded into `VerifiedRequestSubject::canonical_explain_subject_bytes` — key, all five quantitative bounds, then every honourability row through `DeclaredBehaviour::encode_declaration` — and `Compilation::target_profile_descriptor` carries those bytes out to the producer, which turns them into a `TargetProfileDescriptorDigest` inside the artifact. **The governed profile's canonical bytes must come out byte-identical**, or every artifact identity and cache entry moves. The pin is the producer's two-process determinism test plus the serial-sum artifact identity; treat any movement there as a finding, never a rebaseline.

**Three independent sites reject a non-governed profile, not one.** `verify_request` (`request.rs`, `UnsupportedCapability { phase: "target", rule: "prototype-target-neutral-baseline-v1" }`), `VerifiedCompilationRequest::for_target` (`request.rs`, `UnverifiedTargetSelection`, which re-checks every listed profile independently), and the physical schedule verifier at `physical.rs:507`, which folds it into an `intrinsic("request-subject", …)` refusal. All three must become validation rather than equality-with-a-constant, and the third is easy to miss because it reads as a subject-authority check.

**The type is `Copy` with `&'static` fields and cannot stay that way.** `PrototypeTargetProfile { key: &'static str, …, numerical: &'static [DeclaredBehaviour] }` derives `Clone, Copy, Debug, Eq, PartialEq`. A caller-declared profile needs an owned key and owned rows, so `Copy` goes and the ripple reaches roughly 24 mentions in `request.rs` and 6 in `physical.rs`, several of which pass it by value today.

**The public vocabulary question, and what it does *not* decide.** Declaring honourability needs `NumericalDimension`, `DimensionBehaviour`, and `HonouringMeans` reachable by a caller; all three are `pub(crate)` in the private `honourability` module. `DimensionBehaviour` wraps `SubnormalMode` and `NumericalPermission`, which are already public in `tiler-ir`.

Promoting them does **not** settle the three-way siting question `express-metal-honourability-in-the-shared-form` carries, and the reason is worth stating so nobody concludes otherwise: `tiler-metal` cannot reach a vocabulary published by `tiler-compiler` without a new `tiler-metal → tiler-compiler` dependency edge, which does not exist and would be its own architectural decision. So promotion enables an *orchestrator* that already depends on both — the prototype producer does — to construct a profile, which is that ticket's second candidate siting. It leaves the first (`tiler-ir` owns the vocabulary) and third (a new crate) open.

**Suggested order.** Owned type and the `Copy` ripple first, with the governed profile's canonical bytes asserted unchanged before anything else moves; then the three rejection sites into one validation; then the public builder and its diagnostics. The byte-identity assertion belongs first because it is the thing every later step could silently break.
