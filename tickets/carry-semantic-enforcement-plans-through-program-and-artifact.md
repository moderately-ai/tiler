## User-visible outcome

Every residual semantic value obligation on the real strict-affine `Quantize` candidate is either proved or assigned a complete host enforcement plan, and that plan survives selected-plan, verified-program, artifact, codec, cache, and explain boundaries without caller restatement or identity loss.

## Implementation keys

- Consume instantiated residual obligations from the semantic program and attach each to its exact protected operation occurrence, logical subject/view, and first consuming physical stage. A route-global untyped list is prohibited.
- Model proof-elided and first host-scan enforcement as distinct physical dispositions over identical semantic meaning. Keep device pre-scan and transactional execution named unsupported until a real provider can populate every required field.
- Bind obligation identity, predicate/evaluator revision, witness dependency, exact resolved type, ordered component roles/maps, selected checker provider/revision, observability/coherence requirements, hard resource limits, stable error schema, and cost inputs into selected-plan and kernel-program identity.
- Keep dynamic bytes, addresses, value versions, and execution coherence epochs out of static artifact/cache identity. Encode the static dependency schema that the runtime witness must later satisfy.
- Add builder-owned insertion and verified read-only views on `VerifiedKernelProgram`; artifact construction derives the enforcement record from that verified authority. Do not add fields to `BindingSpec` or accept caller-declared ABI facts.
- Project the required records through artifact model, builder, verification, canonical codec, decoded views, neutral manifest required-feature/schema validation, and explain output. Reject dangling, duplicate, out-of-order, unknown, or oversized records before allocation or routing.
- Select hard feasibility before cost. Missing logical-view reconstruction, host observability, coherence, checker revision, or resource capacity is a typed pre-routing refusal, not infinite cost.
- Advance selected-plan, kernel-program, artifact-program, manifest, and explain identities only when their actual producer-filled vocabulary lands. Existing cache domains may retain their names only if their framed changed artifact facet proves separation.
- Correct artifact ABI prose that currently says semantic scale/zero-point/tail scans happen before routing: only structural/canonical preflight and checker preparation may occur there; tensor-value work begins after `RoutingCommit`.

## Adversarial evidence

- Encode/decode/re-encode is byte-identical; old readers fail closed on the new required feature/schema.
- Proof-elided and host-enforced plans share semantic identity but differ in physical/program/artifact identity.
- Independently perturb predicate, obligation, subject, view, resolved type, role/order, map, checker key/revision, observability, error schema, hard limit, protected stage, and mechanism; each changes identity or rejects as appropriate.
- Runtime payload/version changes do not alter static identity, while embedded constant bits do.
- Missing evaluator or host observability rejects before cost; an `Unknown` cost is never rewritten to zero.
- Unknown predicate/provider/schema versions, dangling references, duplicate ordinals, noncanonical ordering, and oversized counts all reject deterministically.
- Removing provider revision, protected-stage dependency, or a component map from canonical encoding makes a fault-injection test fail before restoration.

The public verified-program and decoded-artifact boundaries have Tom's required interface review; the real candidate's obligations reach an exact selected enforcement plan and round-trip through every static boundary; proof and residual dispositions are explained; older schemas fail closed; complete identity pins are recomputed on the merged tree; every new check is proven able to fail; targeted `tiler-ir`, `tiler-compiler`, and `tiler-artifact` tests and Clippy pass; `tkt lint`, `git diff --check`, and the batch gate pass.
