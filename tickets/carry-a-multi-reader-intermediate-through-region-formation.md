## User-visible outcome

`RegionGraph::with_realizations` derives a correct stage topology for a realization in which one published value is read by more than one stage, so the softmax's four-stage chain reaches region formation as one retained value with several readers rather than as several values.

## Why this exists

**Fact.** [`admit-a-handed-value-with-more-than-one-reader-in-the-region-sequence`](admit-a-handed-value-with-more-than-one-reader-in-the-region-sequence.md) widened `VerifiedIndexRegionSequence` so a published value may be read by any number of later stages. `StagedIntermediate` records one *read*: a value with two readers yields two records agreeing on `producer`, `producer_output`, `value_type`, `shape`, and `retained_through`, and differing in `consumer` and `consumer_input`.

**Fact.** `crates/tiler-compiler/src/region.rs`'s `with_realizations` walks `sequence.intermediates()` and, per record, appends one synthetic `GraphValue` and one `SyntheticIntermediate { value, producer_stage, consumer_stage }`. Under the widened vocabulary a value read twice therefore becomes **two synthetic values** with two producer/consumer edges, where the realization has one value with two readers. That misdescribes the topology: liveness, boundary derivation, and the staged identity domains would all see two independent intermediates.

**Fact — nothing is wrong today.** Every registered law publishes one value per non-final stage and every published value has exactly one reader, so the per-read walk and a per-value walk coincide record for record. `cargo nextest run --workspace` is green on the widening's own branch. This is a gap that opens when the first multi-reader law is registered, which is [`register-the-softmax-realization-law`](register-the-softmax-realization-law.md).

## Scope

Group the reads by published value before synthesizing. `SyntheticIntermediate` needs a reader list (or the topology needs a separate per-value record), and `StagedIntermediate::retained_through` is the checked span to carry rather than a re-derivation. Whatever lands must say what the two staged compiler identity domains — `tiler.compiler.index-refinement-content.staged.v1\0` and `tiler.compiler.index-refinement-occurrence.staged.v1\0` — encode for a value with several readers, and must leave every one-reader binding's bytes unchanged. The 26 distinct 16-hex and 6 distinct 64-hex pins over `crates/tiler-compiler` that [`accept-the-multi-region-index-realization-surface`](accept-the-multi-region-index-realization-surface.md) surveyed are the population to re-survey.

## Non-goals

Registering the softmax's law, and widening the sequence vocabulary further. Both are elsewhere.

## Closes when

A multi-reader realization forms a stage topology carrying one synthetic value per published value with all its readers, the staged identity domains state what they encode for it, and every one-reader binding's identity is unchanged byte for byte.

## Outcome — 2026-08-06

**Fact — the record shape, and the alternative it beat.** `SyntheticIntermediate` in `crates/tiler-compiler/src/region.rs` is now one record per *published value*: `{ value, producer_stage, readers: Vec<u32>, retained_through }`. The reader list lives on the record rather than in a separate per-read relation because every consumer asks a question about one published value and its whole reader set — the producing atom's successors are all of them (`node_successors`), a reading atom's one predecessor is their producer (`node_predecessors`), the value leaves a region exactly when *any* reader stays outside and enters it exactly when a covered stage is one of them (`region_shape`). A per-read side table would answer none of those without joining back to the value it belongs to, and that missing join *is* the defect. `readers` is ascending and distinct: two boundaries of one stage reading one value are two reads by one atom, and the topology's atoms are stages.

**Fact — the grouping key, and why no one-reader binding's bytes move.** Records are grouped by `StagedIntermediate::producer`, which names the value because a non-final stage publishes exactly one. Groups are kept in first-read order, so for a chain in which every published value has one reader — every chain either registered staged law spells — the appended `GraphValue`s, their `synthetic_site` indices, and their ordinals are exactly what the per-read walk produced. Ordering groups by producer stage instead would have been the other defensible choice and was rejected for exactly this: it renumbers a legal one-reader chain whose later stage reads an older value first.

**Fact — the carried span.** `StagedIntermediate::retained_through` is copied onto the record rather than re-derived, and `RegionGraph::attach_stage_topology` refuses (`RegionError::Structure { rule: "intermediate-retention" }`) when the carried span is not the last reader it grouped, and (`"intermediate-identity"`) when two records under one producer disagree on type, shape, or span. The grouping key is only the value's name if every record under it describes one value, so that premise is checked rather than assumed.

**Fact — what the identity domains encode for a value with several readers.** Stated at each encoding site, not only here.

- `tiler.compiler.region-content.v1\0` (`append_stage_trailer`, `region.rs`): the value is written **once**, as one canonical site — its occurrence's canonical position and its *published-value* index, under `canonical_value`'s tag `3` — followed by its type and shape. Never one entry per read. Injective for one occurrence because published values are numbered densely from zero in one pass.
- `tiler.compiler.region-occurrence.v1\0`: embeds those content bytes length-framed and lists the same value once more in whichever boundary group it crossed. Neither domain carries a reader count and neither needs one: *which* stages read a published value follows from the per-atom stage list both encodings already pin. So a candidate whose covered stages read one published value twice encodes as one crossing, which is what it is. Neither domain string steps, because per-read and per-value synthesis agree value for value and index for index on every one-reader chain.
- `tiler.compiler.index-refinement-content.staged.v1\0` (`legality.rs`): **nothing of its own.** It names no intermediate at all. It carries the chain's `CanonicalIndexRegionSequenceIdentity` plus one reached-authority block per stage, and reader multiplicity lives entirely inside the first: the sequence encoder writes each stage's declared source list, so a value read by two stages appears as an `Intermediate(p)` entry in each reading stage's list at that stage's own boundary position. The per-stage authority blocks are indexed by stage, so a stage reading one value at two boundaries contributes one — reading a value twice does not change which scalar operations the stage reached.
- `tiler.compiler.index-refinement-occurrence.staged.v1\0`: likewise nothing of its own — content bytes plus the semantic site, receipt identity, provider, and one admission pair per *stage*. Readers reach these bytes only through the embedded sequence identity.

Both `legality.rs` domains are therefore unchanged by this branch in code as well as in bytes; only their documentation gained the statement.

**Measurement — the checks can say no.** Both new tests were watched failing against perturbations of the fix, each applied to a file backup and reverted from it.

1. *Per-read synthesis restored* (grouping removed, `retained_through: consumer_stage`): `one_published_value_read_by_two_stages_is_one_synthetic_value` fails `left: 4, right: 3` on the record count, and `a_two_reader_intermediate_crosses_each_region_boundary_once` fails with the retained synthetic values `left: [4, 5]` against `right: [3, 4]` — value `4` being the *second* copy of the per-point value, the one the covered reader never read. That is the defect stated as bytes: the region would export a different value than the one it fed internally. The `rms_norm` staged tests stayed green under this perturbation, which is the ticket's "nothing is wrong today" restated as evidence.
2. *Retention cross-check pointed at the first reader instead of the last*: both new tests fail with `Structure { rule: "intermediate-retention" }`, so the carried span is genuinely compared against the grouped readers and the comparison discriminates on a multi-reader value.

**Fact — the regression fixture, and why it is hand built.** `RegionGraph::with_staged_realization` is a `#[cfg(test)]` seam taking a `VerifiedIndexRegionSequence` directly; it and the production `with_realizations` both build the topology through the one `attach_stage_topology`, so a test drives the production derivation rather than a copy. The fixture attaches the softmax's four-stage shape — reads `[(0,1), (1,2), (1,3), (2,3)]` over three published values, the sequence layer's `the_softmax_staging_publishing_the_exponentials_chains` topology — to a `[3, 4]` multiply occurrence, built from a fold region and a row-pointwise region. The softmax's own law is registered concurrently and by someone else; `crates/tiler-ir` is untouched here.

**Fact — one bounded remainder, filed rather than taken.** [`count-a-handed-value-live-across-a-stage-that-does-not-read-it`](count-a-handed-value-live-across-a-stage-that-does-not-read-it.md), `deferred`. `region_shape` skips a handed value at a covered stage that neither publishes nor reads it, so a value spanning that stage is absent from `live_values`. The span needed to answer it is now carried, no law spells such a gap today, and counting it is not obviously right — a region would report a live value in neither its boundary inputs nor its retained outputs, and the alternative reading (thread it through as a pass-through boundary) changes boundary derivation and therefore region identity, which is a shape decision rather than a counter fix.
