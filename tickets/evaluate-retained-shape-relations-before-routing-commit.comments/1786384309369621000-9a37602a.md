Pre-edit audit at exact base `e9ba7be7` found a purpose-changing false Fact and stopped without edits. A fixed-interface semantic program can retain a distinct nonempty `ShapeEnv`; kernel and artifact builders check only static interface shapes, then artifact projection drops the fifth `SemanticIdentity::shape_environment` subject. Distinct low-level programs can therefore already collapse to one artifact identity. Runtime receives `AbiFacts` but no retained relation table, and its dependency on `tiler-artifact` must not become a dependency on `tiler-ir` under ADR 0081. A complete fix requires a governed schema/identity step and a consequential public decoded evaluation/refusal boundary, so Tom authority is required. Strongest recommendation: encode a canonical retained-relation/source projection privately in `tiler-artifact`, reject unsupported relation/source variants exhaustively, and accept only `DecodedArtifact::evaluate_retained_shape_relations(&AbiFacts) -> Result<(), RetainedShapeRelationFailure>` plus a non-exhaustive typed failure enum. This preserves runtime dependency direction and keeps ShapeEnv/solver types private. Counterpoint: full fifth-subject carriage avoids projection-drift obligations and wins if artifact identity must preserve every ShapeEnv distinction rather than only artifact-observable obligations.
