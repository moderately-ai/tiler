## User-visible outcome

An artifact that declares a live input-axis operand is tied to the same symbolic axis in the semantic program and its carried shape environment. A fixed semantic interface cannot be executed under a different live shape while retaining the fixed program's coverage or identity.

## Exact gap and per-Fact audit at `f3e1efd3b3b4f896976b326e6a3d993147206cd3`

- **Verified.** `crates/tiler-artifact/src/program/builder.rs` `read_semantic_interface` calls `static_interface_shape`, whose `SymbolicSemanticInterface` arm refuses every symbolic interface. Only a fixed `Shape` can be published today.
- **Verified.** The same file's `derive_extent_operands` proves that a kernel operand maps to a program input and that its axis is inside the fixed rank. It does not prove that the semantic axis is symbolic or that the operand names the program's carried `ShapeEnv` source.
- **Verified.** `crates/tiler-runtime/tests/adapter_route/fixture.rs` constructs `semantic_program()` with `input_shape() == Shape::from_dims([2, 3])`; `one_live_extent_payload_and_pipeline_indexes_dense_f32_at_two_n` then binds axis 1 to 14 and 15. The test passes while executing meanings outside that fixed semantic graph.
- **Verified.** The old draft `9a8f53c9` cannot repair this: it carried no artifact row, and the current split ports are strictly additive over it. The defect is in the live artifact's semantic authority, not a missing conflict port.

Reproduce the current wrong-positive with `cargo test -p tiler-runtime --test adapter_route one_live_extent_payload_and_pipeline_indexes_dense_f32_at_two_n -- --exact --nocapture`. The pass is failure evidence: a static `[2,3]` subject is accepted for `[2,14]` and `[2,15]` execution.

## Required work

- First make the current static-semantic/live-axis combination fail closed. Do not retain a compatibility path that lets a fixed semantic axis acquire a caller-selected extent.
- After [`admit-symbolic-extents-through-schedule-formation`](admit-symbolic-extents-through-schedule-formation.md) establishes the schedule carrier, associate each artifact extent operand with the exact source-bearing semantic input axis and the program's one shape environment. Reject a static axis, a foreign symbol/environment, an inferred or output axis, and a scheduled live axis not present in the semantic interface.
- Carry the source-bearing interface through every construction, validation, schema, coverage, and identity site required for one true semantic `[2,N]` artifact. Do not encode the bound value or specialize identity on 14/15.
- Re-audit whether `{ key, axis, value_type }` is sufficient envelope authority once the semantic source is present. If symbol identity or another public/schema field is required, produce the labelled draft and update Tom's packet; do not smuggle it into the accepted row.
- Remove the static `[2,3]` worked example once the symbolic subject exists. The example must exercise the general association rather than define it.

## Required evidence

- Static `[2,3]` plus a live operand on axis 1 refuses at artifact construction, with the subject perturbed and assertion unchanged.
- A semantic `[2,N]`, its schedule, kernel operand, artifact row, and shape environment all name one source. Swapped symbols/environments, a static axis, wrong axis, and missing source each refuse at their owning layer.
- Coverage and every semantic/artifact/payload identity are equal across bindings of 14 and 15, while a genuinely different symbolic program or a baked neighbour differs.
- Exact schema/domain blast radius, targeted IR/artifact/runtime tests, Clippy, rustdoc, `tkt lint`, `git diff --check`, exact-base guard, and the required repository gate.

## Public boundary and stop condition

This is a semantic-interface, artifact-schema, and identity decision. Use Sol and independent review. If the existing `DecodedExtentOperand` row cannot identify the governing semantic source without widening a public type or schema, stop at a tested labelled draft and update [`accept-the-live-extent-artifact-envelope-row`](accept-the-live-extent-artifact-envelope-row.md) with a Pareto-complete packet before dependent implementation proceeds.

## Closes when

No fixed semantic graph can execute under a different bound extent, and one true symbolic semantic subject carries the same source through schedule, artifact, coverage, identity, and runtime binding.

## Delivery record — 2026-08-18

**Fail-close at artifact construction (live production behaviour).** `derive_extent_operands` now associates every surviving operand row with the artifact's own semantic subject through `check_extent_operand_association` (`crates/tiler-artifact/src/program/builder.rs`): the interface's authored per-axis extent sources are retained beside the narrowed static column (`SemanticInterface::input_extent_sources`, projected by `semantic_input_extent_sources`), and the environment authority is the artifact's own `RetainedShapeEnvironment::bindings()`. A fixed axis refuses as `ArtifactBuildError::ExtentOperandStaticAxis { entry, key, axis, extent }` — the p0 fail-close, naming the exact fixed extent. The former wrong-positive now refuses with exactly `ExtentOperandStaticAxis { entry: 0, key: "input", axis: 1, extent: 3 }`, asserted through the artifact fixture (`a_live_operand_over_a_fixed_semantic_axis_refuses_at_artifact_construction`, with the fused static sibling as the passing control) and through the runtime suite's own fixture path (`the_live_extent_member_refuses_at_artifact_construction`, via new fallible `try_assemble`); the contraction spelling refuses identically (`"left"`, axis 1, extent 3 artifact-side and extent 1 runtime-side).

**The association (the general rule, independent of the packaged representation).** For a symbolic axis the operand must name the exact source-bearing axis of the program's one environment: the axis's symbol unbound in the artifact's retained environment refuses `ExtentOperandForeignSymbol`; a symbol rooted at a static value, interface parameter, or target property refuses `ExtentOperandUnsourcedSymbol` (rendered source carried); a symbol rooted at a *different* input dimension — an inferred equal-shaped occurrence — refuses `ExtentOperandSourceMismatch { root_key, root_axis }`, the same root-not-first-input rule the accepted schedule marker follows; an axis outside the semantic rank refuses `ExtentOperandAxis`; the existing `ExtentOperandUnbound` keeps owning output/non-input accesses. `SourcedExtent` is `#[non_exhaustive]` in this crate, so an unassociated future source kind falls closed into `ExtentOperandUnsourcedSymbol` rather than into either arm. The symbolic arms are exercised against real verified symbolic semantic programs (`SemanticProgramBuilder::try_standard_with_shape_environment` + `input_sourced`, mirroring the compiler's admitted-population authoring) through the same crate-private derivation `push_variant` runs; they become production-reachable exactly when packaging lifts the interface refusal, and are inherited rather than re-derived there.

**Decode-side half.** `check_extent_operand_static_axes` (`crates/tiler-artifact/src/program/codec/validate.rs`) refuses every declared row on decoded bytes as `ArtifactCodecError::ExtentOperandStaticAxis { key, axis, extent }`, because the decoded interface grammar states only literal extents. It runs deliberately after `check_extent_operands` and `check_entry_mappings`, so the done-ticket structural negatives (`NonCanonicalOrder`, `DuplicateItem`, `ExtentOperandAxis`, `ExtentOperandType`, `EntryTransportCardinality`, `ExtentOperandTransport`) stay reachable — verified by keeping their forgery tests green — and a structurally sound, correctly transported row is the one that reaches the association refusal (`a_well_placed_live_extent_row_over_the_static_interface_is_refused`, on forged bytes no builder wrote).

**Schema/domain blast radius, argued from the codec grammar.** None. `tiler.artifact-program.v20` / manifest 20.0 do not step: no wire field moves, no byte is written differently, and no encodable byte string is reinterpreted — a formerly decodable population (envelopes carrying operand rows over the literal-extent interface grammar) becomes refused by validation, which is the layer this contract already assigns that job ("parse success never implies executable validity"). No identity pin moved: the whole workspace passes with no pinned identity, golden, or byte-count edit, and `empty_extent_lists_do_not_move_previously_encodable_artifact_bytes` still asserts the v20 domain with empty lists writing nothing. `docs/artifact-abi.md` carries the dated correction under the envelope-row draft paragraph.

**Worked-example rework (population enumerated).** tiler-artifact: the live envelope round-trip, contraction-guard round-trip, zero-extent guard, two-N indexing, C1 selection, and capacity-pool tests are replaced by the two construction refusals, the five-arm association suite, `the_association_refuses_every_fixed_axis_by_its_own_extent` (not specialized on axis 1), and `baking_neighbouring_extents_mints_distinct_artifact_subjects` (the surviving baked half); `live_extent_two_n_artifact` became `extent_precondition_artifact` over the fused program, keeping the host-side disagreement refusal (`UnboundInputExtent` on the unbound inner axis) testable on a static subject, since a launch precondition may legitimately read a bound extent. tiler-runtime: the two-N execution, zero-extent route, contraction preflight pair, host-side disagreement, and both C1 tests are replaced by the two refusal tests; the determinism rank case now selects between `FusedPropertyGuarded` (guard `SELECTION_PROPERTY_KEY ≡ 0 (mod 16)`, a live-device target property the caller binds) and `Fused`, preserving its subject — rank moves, digest and environment hold — without pretending a fixed input axis varies. `PackagedPlan::LiveExtentAligned` and the live guard variants were removed with their only consumers. The withdrawn execution/addressing/pipeline-identity evidence is owned by the reopened [`prove-one-live-extent-artifact-payload-and-pipeline-at-two-n`](prove-one-live-extent-artifact-payload-and-pipeline-at-two-n.md) umbrella, to rerun over the true symbolic subject after packaging.

**Recorded split (stop condition exercised).** The "one true semantic `[2, N]` artifact" half — equal artifact/payload identity across bindings 14 and 15, and the packaged one-source agreement through schedule, artifact row, coverage, and runtime binding — requires the packaged symbolic interface representation that [`package-the-admitted-live-schedule-into-a-symbolic-kernel-program`](package-the-admitted-live-schedule-into-a-symbolic-kernel-program.md) owns as Tom's packet (`SymbolicSemanticInterface` at `ArtifactProgramBuilder::new` and `SymbolicInterfaceExtent` at the shared kernel-program builder both stand deliberately unlifted). Delivered instead: the fail-closed half everywhere executable (construction and decode), plus the association shape that does not depend on the representation, wired into `push_variant` so the packaging landing activates the symbolic arms without new derivation. Semantic identity across bindings is trivially binding-independent (a bound value is an invocation fact, not a program fact — the schedule ticket's identity evidence stands); the baked-neighbour separation is delivered now. The kernel-program layer still admits a live operand over its (necessarily static) subject; that object is not executable — construction and decode both refuse before any route — and its interface handling is exactly what the packaging packet rebuilds, so the layer's own association lands there rather than being pre-empted here.

**Runtime observation, recorded not expanded.** `preflight` accepts bound input-extent facts that contradict the static interface (e.g. `bind_sct(15, 14, …)` over `[2, 3]` in the retained-relation tests). After this fail-close those facts feed only guards, launch preconditions, and retained relations — never an addressed byte or a payload operand — so no wrong meaning executes; whether preflight should also cross-check facts against the published interface is a separate question left to the runtime owners.

**Envelope-row sufficiency re-audit (the release trigger `accept-the-live-extent-artifact-envelope-row` holds on).** `{ key, axis, value_type }` remains the minimum complete row once the semantic source is present, and no public or schema field is required — so no labelled draft widening and no item-9 packet change. Independent derivation from the grammar: the artifact carries exactly one shape-environment subject (retained fifth-subject bytes, folded into identity), and under the association a row is valid only when the interface axis it names is symbolic and its symbol roots at exactly that `(key, axis)` in that one environment — so the environment subject plus the named axis *determine* the governing symbol, and a symbol-identity field on the row would be a second spelling of one fact, able to disagree with the authority it restates (the defect class the packet's elimination rules already exclude). Coverage, identity, and unsupported-population consequences: the row's population is empty until packaging (fail-closed both sides), a nonempty declaration remains a new subject rather than a reinterpretation, and the packaged symbolic interface representation — the one place a genuinely new public/schema surface can arise — is the packaging packet's own question, on which the envelope acceptance already transitively waits through this ticket.
