Implement reviewed verified target-neutral KernelProgram IR: stage DAG, exact
selected scheduled/KIR refinements, checked values/views/allocations and
lifetimes/handoffs, named outputs, dependencies, and complete coverage. This is
compiler execution intent, not the artifact manifest or codec. Tom reviews
consequential public boundaries before acceptance.

Carry the ADR 0072 layers explicitly: semantic graph identity, bound
refinements/implementations and complete coverage in program identity. The
artifact-facing projection owns packaged admission/provider provenance and
routing/ABI representation.

Any consequential public or cross-crate crate, module, trait, type, or call-site boundary remains a draft until Tom reviews and accepts the exact implementation commit. This ticket does not preselect that interface.

## Module-placement note (coordinator, 2026-07-23)

Per ADR 0070 the target-neutral kernel-program IR belongs in `tiler-ir` as its own
module, `tiler_ir::program`, alongside the existing `tiler_ir::index`. Build it there
rather than growing `tiler-compiler/src/physical.rs`, which currently holds the
bounded serial-Sum prototype's schedule/kernel/program types in one ~1,300-line
file. Extract only your layer's concern, keep the serial-Sum path green, and
leave the shared `physical.rs` no larger than you found it (ideally smaller).
This keeps the crate's public surface modular so later layer work can proceed
without one monolith as a shared merge point; it is architecture ADR 0070
already mandates, not extra scope.

## Outcome

**Completed 2026-07-24 (implementation landed; ticket remains `in-progress` pending Tom's review of the new public namespace).**

**Fact — what exists.** `tiler_ir::program` is a new public module in `tiler-ir` (`handles.rs`, `error.rs`, `model.rs`, `builder.rs`, `verify.rs`, `mod.rs`, `tests.rs`; 4 299 lines including 1 352 lines of tests). It owns the target-neutral kernel-program IR: an acyclic stage DAG whose stages bind exact `tiler_ir::kernel::VerifiedKernel` refinements, checked materialized values, byte views, and storage allocations with derived lifetimes and explicit storage handoffs, typed dependency edges, an ordered list of named outputs, and complete semantic coverage. Construction is the ADR 0071 discipline: a public transactional `KernelProgramBuilder` with private storage, insertion-time checks for every locally decidable invariant, and a consuming `build()` that runs whole-program verification and returns an opaque `VerifiedKernelProgram` or the intact builder with typed diagnostics. `VerifiedKernelProgram`'s fields are module-private and it offers no mutation, thawing, or unchecked constructor.

**Fact — the semantic subject is unforgeable.** `KernelProgramBuilder::new` takes a `&SemanticProgram`, not a producer-declared subject. The builder captures that program's canonical `SemanticGraphIdentity`, its operation count, and its named input/output interface with shapes. Complete coverage therefore means "every output-reachable operation of *this* verified graph, covered exactly once", named-output coverage means "every declared semantic output published exactly once", and a materialized value claiming a program input must name a declared input key with that input's exact shape. None of these can be satisfied by declaring a convenient subject.

**Fact — the ADR 0072 layers in identity.** `CanonicalKernelProgramIdentity` is a domain-tagged (`tiler.kernel-program.v1\0`), length-prefixed encoding of exactly three ADR 0072 subjects plus the structure that binds them: (1) the canonical `SemanticGraphIdentity` of the realized program; (2) each stage's `CanonicalKernelIdentity`, which already folds the `CanonicalScheduledRegionIdentity` it refines — so a change at any structural layer moves program identity; (3) each stage's covered semantic occurrences, proven to be a disjoint partition of the whole graph. Materialized values, views, allocations, typed dependencies, and named outputs are folded in alongside. It deliberately **excludes** packaged admission, selected-provider provenance, and the artifact's routing and ABI representation, which the artifact-facing projection owns.

**Fact — identity is ordinal-free by content-key canonicalization.** Every cross-reference in the encoding is a domain-tagged canonical *content key*, never an arena position: a stage key is its kernel identity plus its coverage; a value key is its role, origin, shape, element type, derived byte count, alignment, memory space, and its defining stage key plus write position; a view key is its base value key plus byte window; an allocation key is its storage facts plus the sorted keys of the values it binds. Entity categories are emitted in ascending key order. The verifier proves each category's keys are pairwise distinct and rejects a collision as `AmbiguousCanonicalKey` rather than resolving it by position, so the induced canonical order is total and the encoding is injective. The canonical single-stream `execution_order()` is a topological order broken by the same content keys, so it too is independent of insertion.

**Fact — what whole-program verification proves, in phase order.** Non-empty program; unique writer per internally produced value and no write to an externally bound input (`MissingWriter`, `MultipleWriters`, `ExternalValueWritten`); complete coverage of the bound graph (`IncompleteCoverage`); unambiguous canonical keys; every dependency edge states an obligation its two stages actually realize (`MisattributedDependency`) and every read of an internally produced value carries its explicit data edge (`MissingDataDependency`); acyclicity (`DependencyCycle`); no unused value, view, or allocation; the baseline aliasing contract, under which only internal temporaries may share storage (`ForbiddenAlias`); the conservative reuse contract — disjoint lifetimes in canonical order, an explicit `StorageHandoff` from the old value's final user to the new value's writer, and dependency *reachability* (not merely a position in one linearization) from every user of the old value to that writer (`ReuseLifetimeOverlap`, `ReuseMissingHandoff`, `ReuseLiveAlias`); complete named-output coverage (`MissingNamedOutput`, `UnboundOutputValue`); and the governed identity byte bound.

**Fact — what it deliberately does not prove.** That a stage's bound kernel computes the semantic operations its stage claims to cover. Coverage here is a structural completeness and disjointness obligation over one exact graph; semantic-equivalence evidence remains compiler-owned refinement evidence (ADR 0071), and the module documentation says so in both `mod.rs` and `verify.rs` so the layer cannot be misread as supplying it.

**Fact — the extraction.** The bounded prototype's program types were in `crates/tiler-compiler/src/program.rs`, not in `physical.rs` (see the premise correction below). `program.rs` shrank from 1 876 to 1 067 lines (-809) with 418 lines of tests moved to `program/tests.rs`; `physical.rs` is byte-identical at 1 055 lines. The compiler's `KernelProgram` now holds one private `VerifiedKernelProgram` plus the four layers the shared IR does not yet own — the host preflight expression graph, the bounded entry ABI, the routing-commit contract, and the artifact construction plan. Deleted as now-duplicated: the compiler's own `ProgramStage`, `StageValueAccess`, `Dependency`, `DependencyReason`, `BufferPlan`, `MaterializedValue`, `Allocation`, `AllocationId`, `MemorySpace`, `ValueRole`, `AllocationOwnership`, `ProgramOutput`, the `ProgramError::Dependency` variant, and the whole `verify_storage`/`verify_fused_storage`/`verify_program_structure` family with their stage-id, value-id, allocation-id, dependency, alias, and output-coverage rules. `ProgramError` gained `CoreConstruction` and `CoreVerification` variants that preserve the shared layer's typed error through `Error::source()`. The serial-Sum path is unchanged: all 427 workspace tests pass, including the end-to-end `compile()` portfolio and explain-trace assertions.

**Fact — a strengthened check fell out of the extraction.** The old ABI verifier compared an entry binding's `accessible_bytes` host expression against a `HostExprId` stored on the compiler's own `MaterializedValue`, i.e. against another compiler-declared number. It now evaluates that expression and compares it against the shared value's `required_bytes()`, which the shared builder *derives* from the declared shape and element type. A producer can no longer declare a byte count its own shape contradicts.

**Measurement.** `uv run --locked python scripts/check_repository.py` passes (documentation validate over 176 records, 148 Python tests, ShellCheck, ticketsplease lint, and the complete Rust sub-gate: `fmt --check`, strict Clippy over all targets, development and optimized tests, doctests, warning-free rustdoc, immutable locks). `cargo nextest run --workspace`: 427 tests, 427 passed. `git diff --check`: clean. Host: macOS arm64, `nightly-2026-07-19`.

**Fact — the tests.** 19 tests in `tiler_ir::program::tests` plus one module doctest. Verified-product construction and read-back; identity determinism and independence of declaration order (arenas and stages declared in reverse); identity unchanged when the transient planning `RegionId` changes; identity changed by each ADR 0072 layer in isolation — the semantic-graph layer (two graphs differing in one constant, over identical bound kernels, coverage, and structure), the bound-refinement layer (one graph, one coverage split, one structure, a different selected kernel), and the coverage layer (one graph, one pair of kernels, two different complete partitions). Negative tests: incomplete coverage, coverage claimed twice, a read without its data edge, a dependency naming an obligation its stages cannot realize, a dependency cycle, storage reuse without an explicit handoff, an output sharing storage, an unused view, an unused allocation, indistinguishable canonical keys, a value with no writer and a value with two writers, a missing named output, a stage access disagreeing with its kernel signature in arity, tensor role, access mode, or addressed extent, a view escaping its value, an output key outside the bound interface, an input key outside the bound interface, a repeated input claim, a role/origin contradiction, and five distinct cross-program handle rejections (value, stage, view, allocation, and a foreign value through a view). The compiler retains 7 tests for the layers it still owns.

**Premise correction — the ticket's module-placement note is stale.** It states that `crates/tiler-compiler/src/physical.rs` "currently holds the bounded serial-Sum prototype's schedule/kernel/program types in one ~1,300-line file". At this ticket's base commit `882b10b` that is no longer true: `912bb11` moved the schedule types to `tiler_ir::schedule` and `6b76801` moved the kernel types to `tiler_ir::kernel`, and the program types have lived in a separate `crates/tiler-compiler/src/program.rs` throughout. `physical.rs` is 1 055 lines and holds only compiler-owned refinements — semantic-occurrence binding, request-subject binding, and target feasibility. The note's *intent* (build in `tiler-ir`, do not grow the compiler monolith, extract this layer's concern, keep the serial-Sum path green) was followed against `program.rs`, which is where this layer's concern actually was; `physical.rs` was not touched at all.

**Open tension — ADR 0068 and ADR 0072 place ABI, guards, and routing inside this layer, and this ticket excludes them.** ADR 0070 assigns `program` in `tiler-ir` "`AbiExpr`, pure checked evaluation, stage and buffer plans, verified kernel programs, and verified program portfolios"; ADR 0068 places the `AbiExpr` domain type, its validation, identity, and authoritative pure evaluation with the executable-program representations in `tiler-ir`; and ADR 0072 states that "a complete program identity covers the semantic graph, bound region implementations, coverage, dependencies, materializations, buffers, ABI, guards, and routing". This ticket's body and the coordinator's brief both scope ABI, guards, and routing to the artifact-facing projection instead. The implementation follows the ticket, so `CanonicalKernelProgramIdentity` is **not yet** the complete program identity ADR 0072 describes: it omits the ABI, the applicability guard, and the routing contract, which remain compiler-owned in `tiler-compiler/src/program.rs`. This is recorded rather than hidden. Closing it needs one of: (a) an `AbiExpr` slice that moves host expressions, entry contracts, and routing into `tiler_ir::program` and bumps the identity domain tag to `v2`, or (b) an explicit superseding decision narrowing ADR 0068/0072. Recommendation: (a), because ADR 0068's stated reason — that owning `KernelProgram` in `tiler-ir` while owning its expression type elsewhere leaves the program dependent on an external side table for verification and identity — is exactly the state this commit leaves behind. Also unresolved by this ticket: `VerifiedProgramPortfolio`, which ADR 0071 names alongside `VerifiedKernelProgram` and which nothing here implements.

**Closed 2026-07-25 by `complete-program-identity-with-abi-guards-and-routing`, taking option (a).** The ABI expression arena, the applicability guard, the per-stage entry ABI, and a per-program routing-commit lifecycle now live in `tiler_ir::program` and are folded into `tiler.kernel-program.v2`. The one part of "routing" that did *not* move is a portfolio's variant priority, which is a relation among variants and which a single program has no rank to carry; see that ticket's Outcome. `VerifiedProgramPortfolio` remains unimplemented, so the second half of this paragraph still stands.

**Proposal — bounded-profile restrictions that fail closed and would need widening.** Each rejects explicitly rather than approximating: exactly one materialization per value (recomputation, which the buffer-planning research permits, would need two materialized values and is not representable); a read requires a *direct* data edge from its writer rather than mere reachability; views are canonically deduplicated, so two consumers of one window share one view; two entities with equal canonical keys are rejected instead of being disambiguated by position; `MemorySpace` has only `Device`; a materialized value's byte count is derived from a static `Shape`, so symbolic extents will need the accepted `ShapeEnv` authority before this layer can carry them. `ExternalValueWritten` is currently unreachable through the public builder — the stage/kernel tensor-role check rejects a write to an input-role value first — and is retained as a defensive whole-program rule; it is the one diagnostic in the module without a test that can reach it.

**Inference — why the storage-reuse path is tested with a synthetic two-chain fixture.** The bounded schedule profile admits only `Input -> Intermediate` (pointwise), `Intermediate -> Output` (reduction), and `Input -> Output` (fused) regions, so no chain of stages can produce two temporaries whose lifetimes are disjoint within a single serial-sum program. The reuse, handoff, cycle, and multi-output rules are therefore exercised by a two-input two-output semantic graph with two independent chains sharing one temporary allocation. This is a real verified program built from real verified kernels; only the coverage attribution is structural, which is exactly the claim this layer makes.
