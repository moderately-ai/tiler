Record, as a **proposed** ADR, the conventions a public Tiler API must satisfy.
The point is to make conformance mechanically checkable so that a public surface
which follows the conventions needs no bespoke design debate, and only genuine
deviations need a decision.

## Why now (evidence, not speculation)

These conventions are not invented here; the codebase already follows them, but
nowhere states them, so each new surface re-litigates them by review. Observed
across the authorities landed so far: four independent agents converged on the
same private-draft authority shape (`pub(crate)` module plus a module-level
`#![allow(dead_code, reason = …)]` until it is wired into `compile()`), matching
the earlier `explain`/`feasibility` precedent, without being instructed to. Over
the same period, per-case public-boundary review caught essentially one
substantive issue — missing `#[non_exhaustive]` on enums and output records
documented as growing — which is a *convention gap*, exactly the class a written
rule catches systematically and a human review catches only by luck.

## Conventions to record (proposal — each open to revision)

Draw them from the landed surfaces rather than from theory:

- **Errors are typed and non-erasing.** Distinct failure kinds stay distinct
  variants; generics over each layer's concrete error types rather than
  `Box<dyn Error>` (see `CheckedBuildError<Admission, Verification>`).
- **Identity types are opaque**, expose canonical bytes via `as_bytes()`, and any
  short digest is presentation-only (`key()`), never an equality or dedup input.
- **Canonical encodings are length-prefixed, domain-separated, exclude transient
  ordinals, and match enums exhaustively** so a new variant is a compile error
  rather than a silent identity collision (this is the trap
  `extend-canonical-identity-encodings-for-reserved-variants` fixes).
- **Construction is a transactional builder plus a consuming `build()`** that
  returns an opaque verified product which cannot be forged or thawed; a
  closure convenience must delegate to that same path.
- **`#[non_exhaustive]` on any public enum or output record documented as
  growing** (owned as work by `harden-public-enums-non-exhaustive`).
- **Verified products expose no `pub` fields**; leaf value-data descriptors may,
  and the ADR should state which is intended where (see the schedule-vs-index
  inconsistency recorded on `unify-schedule-index-region-with-verified-index-region`).

No code, contract, or `AGENTS.md` text changed.

**Fact.** The ADR records seven conventions, each verified against merged source at base `b642007` rather than taken from this ticket on trust: typed non-erasing errors (`CheckedBuildError<Admission, Verification>` in `crates/tiler-ir/src/convenience.rs`; `IndexBuildError::ScalarAuthority(Arc<ScalarRegistryError>)` with a preserving `source()` in `crates/tiler-ir/src/index/error.rs`; no `anyhow`/`thiserror` dependency and no `Box<dyn Error>` in any library signature); opaque byte identities read only through `as_bytes()` with presentation-only digest labels (`RegionContentIdentity::key()` in `crates/tiler-compiler/src/region.rs`); domain-separated, length-prefixed, ordinal-free, exhaustively-matched canonical encodings (`encode_identity` and the `TAG_*`/irrefutable-let destructuring in `crates/tiler-ir/src/schedule/model.rs`; `b"tiler.<subject>.v<N>\0"` tags at every derived-identity site in the workspace); transactional builder plus consuming `build()` yielding an unforgeable verified product, with the closure convenience delegating to that same path (`IndexRegionBuilder::build_with` → `build_checked` → `Self::build`, pinned by the `trybuild` fixtures `tests/index-region/fail/forge_verified.rs` and `tests/index-region/fail/closure_cannot_build.rs`); `#[non_exhaustive]` on growth-expecting public enums and output records but deliberately not on caller-constructed input records; verified products with no `pub` fields, with the leaf value-data descriptor exception stated; and the crate-private draft-authority staging rule.

**Fact — a ticket premise corrected.** This ticket states that four independent agents converged on the private-draft authority shape "without being instructed to". The artifact is real (six `tiler-compiler` modules, each a private `mod` with `pub(crate)` items and a module-level `#![allow(dead_code, reason = "…")]`), but the convergence was not independent and each agent recorded that it was copying: `prototype-fusion-legality-and-numerical-proof` cites "`explain.rs`'s private-draft precedent", `prototype-physical-implementation-frontier` cites "the sibling `feasibility` and `fusion_legality` authorities", `prototype-region-cover-enumeration` cites "the sibling `fusion_legality`/`frontier` private drafts", and `prototype-complete-physical-plan-selection` cites "the `cover`/`frontier`/`fusion_legality` convention". The ADR states this correction explicitly and does not rest on the independence premise.

**Fact — a second ticket premise refined.** This ticket's shorthand "any short digest is presentation-only (`key()`)" cannot be used as the marker for the rule: `key()` is overloaded. In `tiler-compiler` (`region.rs`, `cover.rs`, `selection.rs`) it returns a `String` digest label; in `tiler-ir` (`index/scalar.rs`, `index/model.rs`, `semantic/registry.rs`, `semantic/operation.rs`, `semantic/interface.rs`) it returns a borrowed *stable semantic key* (`&ScalarOpKey`, `&OpKey`, `&OutputKey`) that is meaning, is compared, and is encoded into identity. The ADR states the convention by role rather than by accessor name and leaves the naming collision as an open question.

**Fact — a third refinement found in source.** The blanket form "identity types have no public constructor" is falsified by `SemanticOccurrenceIdentity::from_bytes` and `NumericalContractIdentity::from_key` in `crates/tiler-compiler/src/legality.rs`. Reading them shows the rule is narrower and more useful: an identity a crate *derives* has no public constructor, while an identity a crate *receives* at a boundary may have a wrapping constructor that documents the bytes as opaque and never re-derived locally. The ADR records the refined form.

**Fact — two encoder deviations recorded.** `encode_identity` in `crates/tiler-ir/src/schedule/model.rs` opens with `b"tiler.schedule.v1"` without the NUL terminator used at every other derived-identity site, and `push_numerical` writes `profile_key` NUL-terminated rather than length-prefixed. Neither is ambiguous today (fixed constant tag, fixed-width following fields, `&'static str` key), and the ADR proposes the uniform form rather than asserting a defect.

**Inference.** Writing the conventions down is worth more than the "independent convergence" framing suggested, not less: a rule propagated only by imitation degrades the first time a worker reads a non-conforming sibling, and it gives a reviewer nothing to cite. Six of the seven conventions are checkable by reading the item; only the leaf-descriptor exception needs judgement about whether a record carries a cross-field invariant.

**Proposal (open, deliberately unsettled).** The ADR leaves four open questions rather than picking winners: the `tiler_ir::schedule` (pub fields) versus `tiler_ir::index` (view accessors) descriptor-accessor style, owned by `unify-schedule-index-region-with-verified-index-region`; whether `applies_to` should also name `tiler.contract.optimizer` once the reviewed compiler facade exists (omitted now rather than claiming authority this record has not earned); a distinct spelling for presentation-only digest labels, with no owner assigned; and whether any part of the conformance check should be mechanized. The two known non-conforming areas keep their existing owners, `harden-public-enums-non-exhaustive` and `extend-canonical-identity-encodings-for-reserved-variants`.
