## User-visible outcome

Tom accepts or rejects the exact public spelling of a schedule-local input coordinate: either retain an explicit dense ordinal on each `TensorRole::Input`, or make the role fieldless and use ordered access/kernel-buffer positions plus an explicit ordinal only for references outside those lists. Both survivors keep declared-input association in the compiler-owned schedule-to-program binding and preserve `InputKey` as interface authority. Rejection leaves the current contradiction fail-closed behind the blocked symbolic schedule path; it does not authorize either existing meaning by default.

## Exact-current-base Facts — 2026-08-14, `bbbf936ad3d8170ec601cd26eda5235cc2ac1d6b`

- **Fact — the defining public type is unambiguously region-local.** `crates/tiler-ir/src/schedule/handles.rs`, anchor `The ordinal is *region-local and positional*`, requires the dense prefix `0..n`, explicitly denies interface-key and semantic-value authority, and assigns named-input binding to program-stage accesses.
- **Fact — pointwise expressions require that exact local meaning.** `crates/tiler-ir/src/schedule/pointwise.rs` and `pointwise_bf16.rs`, anchors `input_ordinals_are_dense` and `SparseInputOrdinals`, use `InputOrdinal` to number scalar-expression leaves and reject a gap. `request.rs`, anchor `numbers its leaves by the position of the read`, mints those ordinals from read-list positions, not declared program ordinals.
- **Fact — `TensorRole::Input` and intrinsic schedule verification assign the opposite meaning.** `crates/tiler-ir/src/schedule/model.rs`, anchor `Which declared input tensor this access binds`, calls the field a declared program-input ordinal. `builder.rs`, anchor `The ordinals need not be the dense prefix`, admits sparse roles such as `0, 1, 7` and says an epilogue needs that population.
- **Fact — one schedule already needs both facts.** `builder.rs`, anchor `A read's position and its boundary role are separate facts`, states that leaf/access position and declared tensor association differ. A pointwise epilogue can have local leaves `0, 1` while the second read comes from declared input `2`; repeated mapped reads can also give two local leaves to one declared input. One number cannot truthfully denote both coordinates.
- **Fact — the compiler preserves the declared meaning through physical scheduling.** `crates/tiler-compiler/src/physical.rs`, anchor `The recognized ordinal, not the first declared input`, copies recognized declared ordinals into `TensorRole::Input`. Its helper tests project `0, 1, 7`; the end-to-end positive admits the later declared input `1`, while forged `0` and `7` roles refuse under `request-binding`.
- **Fact — intrinsic schedule identity independently admits and encodes sparse roles.** `crates/tiler-ir/src/schedule/builder.rs`, anchors `two distinct ascending program ordinals need not be dense` and `the input ordinal is part of scheduled-region identity`, admits sparse contraction roles and proves a nonzero input role changes canonical scheduled-region identity.
- **Fact — compiler program assembly, not artifact construction, is the direct interface lookup.** `crates/tiler-compiler/src/program.rs`, anchor `AssemblyBinding::Input(ordinal)`, converts `TensorRole::Input.ordinal` directly to a semantic program input index. The parent ticket's prior statement that actual mapping is positional only through artifact stage accesses is therefore false.
- **Fact — artifact live-extent mapping already follows the correct layer boundary.** `crates/tiler-artifact/src/program/builder.rs`, anchor `maps that tensor through the stage access`, matches the kernel buffer position to the parallel program-stage access and reads `MaterializedOrigin::ProgramInput { key }`. The public interface authority is the resulting `InputKey`, not the schedule ordinal.
- **Fact — the compiler already retains both facts, but program assembly does not project them.** `request.rs::VerifiedRequestSubject` retains a `NormalizedProgramSubject`; its pointwise, contraction, epilogue, staged, and serial-sum projections retain ordered reads and declared read ordinals while their scalar expressions retain dense local leaves. `verify_schedule_with_feasibility` proves `verify_region_subject_binding` and then stores a clone of that exact subject in `physical.rs::VerifiedScheduledRegion`. `CoverAssembly::from_plan` has no accessor/projection from the retained authority and therefore reuses the schedule field as a declared index.
- **Fact — every current standalone role carrier has, or can retain, a separate exact coordinate.** Schedule accesses are ordered; bounds and ownership records are linked by witness IDs; structured-kernel buffers are ordered and expose typed buffer handles; program stage accesses are positional; artifact construction zips the exact kernel-buffer/stage-access lists; and opaque-call bindings carry governed parameter names. Compiler-private contributor/pass records still use bare `TensorRole`, but they are derived from normalized ordered reads and can carry that local position without a new public authority. A fieldless role therefore need not mean an untyped search for “the first input.”
- **Fact — canonical schedule identity must exclude declared interface naming.** `schedule/handles.rs` says renaming caller inputs must not change the kernel. `region.rs`, anchor `Region *content* identity canonicalizes`, separates reusable content from occurrence/boundary bindings. Encoding declared ordinal `7` into the shared schedule and kernel makes the same local computation over a differently declared interface a different schedule, conflating content with program binding.
- **Fact — relevant source did not drift from the prerequisite's original audit base.** The IR/compiler/artifact files named by the reproduction command are byte-identical between `a660ed618446ade55234993b835e75e26d44921c` and this base. The ticket and graph moved; the authority-bearing source did not.
- **Inference — this is a public meaning and identity decision, not a documentation repair.** Making roles dense invalidates currently accepted sparse public schedules and changes their canonical schedule/kernel bytes. Keeping sparse roles retains an interface coordinate in shared schedule identity. Either outcome is consequential and requires Tom.

## Invariants every correct answer preserves

- Scalar-expression input ordinals remain dense local leaf coordinates, and every leaf is bound exactly once to its access position.
- Declared program-input association remains explicit and checked. A subset, epilogue, contraction, fold, or repeated mapped read is never rebound by guessing that local position equals declaration position.
- `InputKey` remains the interface authority. Shared schedule/kernel IR contains no semantic key, caller name, `ShapeEnv`, or program-declaration coordinate.
- A stage-access reorder that disagrees with the checked local-to-program association refuses; it cannot silently bind a different input or live extent.
- Canonical schedule and kernel identity encode local computation. Whole-program/stage identity separately encodes the declared `InputKey`/materialized-value association.
- Existing dense-prefix schedules whose local and declared positions happen to coincide retain their exact bytes unless an independently justified identity-domain migration is required. Sparse schedules receive a governed migration rather than retaining ambiguous bytes.
- No symbolic extent, source-bound live access, artifact schema, or new supported family is admitted by this decision.

## Option 1 — keep an explicit dense local ordinal on `TensorRole::Input`: survivor

**Exact surface.** Keep the public `InputOrdinal` newtype and its existing dense region-local definition. Change `TensorRole::Input { ordinal }`, pointwise scalar leaves, kernel buffer roles, live input-extent parameters, and every intrinsic validator/encoder to use that one meaning. A region with `n` input-buffer accesses uses local ordinals `0..n`; two differently mapped reads of one declared input occupy distinct local positions. No public declared-input ordinal is added to shared schedule or kernel IR.

The compiler projects the local-to-declared association from the `VerifiedRequestSubject` already retained inside each `VerifiedScheduledRegion`. Physical request binding already proves that subject against the exact region before storing it; the implementation adds one compiler-private, typed projection/helper so `CoverAssembly` can consume the same checked authority and create `AssemblyBinding::Input(declared_index)`. Program construction then binds the resulting stage access to the materialized program input and its `InputKey`. Artifact construction continues following buffer position through that checked stage access. Neither compiler nor artifact may fall back to local-equals-declared coincidence. No second retained per-access vector is part of the accepted design; adding a cache later requires evidence that projection cost is material and a proof that it cannot disagree with the stored subject.

**Correctness and strictness.** This assigns one coordinate to one type. Expression leaves, access roles, proof roles, kernel buffers, and live parameters share a dense local namespace; the compiler-owned association is the only conversion to program inputs. Missing, duplicate, out-of-range, reordered, or request-inconsistent associations fail before plan retention or program construction. A region reading declared inputs `1` and `7` carries local roles `0` and `1`, plus a checked compiler association `[1, 7]`; repeated mapped reads may carry `[0, 1] -> [7, 7]` when the recognized relations distinguish them.

**Maintainability and public compatibility.** The public type keeps the meaning already stated at its definition and used by both scalar-expression vocabularies. Every shared-IR consumer sees one local coordinate; program-interface knowledge stays in the compiler/program layer accepted by ADR 0070. This is source- and behavior-breaking for hand-built sparse `TensorRole::Input` schedules and for compiler tests that currently treat the field as declared. Tiler is pre-production and has no accepted external compatibility obligation, but the replacement must still be atomic across IR, compiler, artifact, Metal, build, conformance, runtime fixtures, docs, and tests.

**Host/runtime and memory.** Schedule and kernel storage remain one `u32` per input role. Intrinsic dense validation stays linear in access count. The request subject and its ordered declared reads are already retained, so the accepted design adds no proposal-resident vector or authority copy. Program assembly performs one bounded linear projection from the selected region's semantic members/local access position to that stored subject. No search, provider, candidate, or kernel-runtime population grows. A benchmark can still reverse the no-cache implementation choice if this projection becomes material, but it cannot reverse the public local-ordinal model.

**Identity and schema.** Dense-prefix schedules retain their local ordinal bytes. Current sparse schedules normalize to dense local bytes and may intentionally collapse when their computation is identical; the compiler proposal/program identity must remain distinct through the checked stage/InputKey association. The implementation must independently derive whether schedule/kernel identity versions require a step for the retired sparse interpretation, update every pin/ledger that owns that answer, and prove no dense subject moved. Artifact schema does not change: stage materialized origins already carry the `InputKey`. No semantic, artifact-envelope, or cache identity may derive interface meaning from the local ordinal.

**Strongest counterargument.** Projecting a binding from the recursive normalized request subject makes assembly depend on a helper that understands every recognized family, while the current direct lookup is one integer conversion. The current lookup obtains that simplicity by putting program-interface identity into reusable shared schedule IR and contradicting the scalar leaf type. The helper is not a second authority: physical binding has already proved and retained the request subject, assembly reads that same value, and artifact construction resolves the resulting materialized origin. Keep the family traversal in one compiler-private projection rather than restating it in `CoverAssembly`; add cached state only if measured projection cost justifies the duplication and a reconstruction check pins equality.

**Reversal evidence and negative controls.** Reverse this recommendation only if a full prototype shows no compiler-owned checked association can survive plan selection/assembly without adding a broader public program-stage surface, or if accepted ADRs are superseded to make declared interface position part of schedule content identity. Tests must independently perturb: a local role gap; an expression leaf/access mismatch; the declared mapping with local roles fixed; stage-access order with the mapping fixed; two local reads mapped to one declared input; sparse declared inputs `1` and `7`; schedule/kernel identity under caller input renaming; and program/artifact identity under changed `InputKey` binding.

## Option 2 — add a declared-input ordinal to shared schedule roles: eliminated

The strongest version separates the types: keep local `InputOrdinal` for expression leaves and add `DeclaredInputOrdinal` to `TensorRole::Input`, with validators proving each access position binds one declared coordinate. This is mechanically correct and preserves current sparse role bytes if the newtype uses the same encoding. It is nevertheless eliminated because declared interface order becomes shared schedule/kernel content: renaming or embedding the same region in a wider interface changes canonical schedule identity despite identical local computation. It also still requires stage-access validation to reach `InputKey`, so it duplicates rather than removes the program binding authority. Compared with option 1 it is worse on architectural correctness, identity canonicality, public surface, and maintenance; its only benefit is preserving an interpretation that conflicts with the accepted layer boundary.

Its strongest counterargument is direct assembly and migration compatibility. It returns to the frontier only if Tom explicitly supersedes ADR 0070's reusable schedule-content separation and makes declared interface position part of schedule meaning.

## Option 3 — make `TensorRole::Input` fieldless and use the ordered access coordinate: survivor

**Exact surface.** Completely replace `TensorRole::Input { ordinal: InputOrdinal }` with fieldless `TensorRole::Input`. Retain `InputOrdinal` as the dense region-local coordinate for pointwise expression leaves, reduction topology references, and any schedule relation that must point at one ordered read from outside the access list. An access's local coordinate is its position in the ordered read run; kernel lowering preserves that order in its buffer list and uses `KernelBufferId`/`VerifiedBufferId` internally. Replace accepted `InputExtentParameter { tensor, axis }` with an exact local reference such as `InputExtentParameter { input: InputOrdinal, axis }`; declaration verifies that position names an input access, and artifact construction maps the corresponding kernel buffer/stage access to `InputKey`. Bounds and ownership records already link to exact accesses by witness IDs; their fieldless tensor role remains a category check, not a coordinate guess.

The compiler uses the same typed projection of the retained `VerifiedRequestSubject` as option 1, keyed by ordered access position, to produce declared `AssemblyBinding::Input` entries. Repeated mapped reads of one declared input are distinct local positions mapping to the same declared ordinal. An epilogue's staged read occupies its own local position and fails if an input-only extent/reference points at it.

**Correctness and strictness.** Local role-versus-position disagreement becomes unrepresentable: there is one ordered coordinate rather than an access position plus a repeated ordinal to compare. Every out-of-list reference remains explicit and typed, so no consumer guesses “first input” or scans for an indistinguishable role. Missing/out-of-range references, an extent pointing at an intermediate, a reordered stage binding, and a changed declared association all fail at their owning checked boundary.

**Maintenance and compatibility.** This makes `TensorRole` classify input/intermediate/output while ordered carriers own identity among members of a role. It removes a redundant field and the invalid sparse-role state, but interpreting an isolated input role no longer identifies one buffer; consumers that need identity must carry the access/buffer coordinate explicitly. The replacement is broader than option 1: every `TensorRole::Input` constructor and total match changes, the already-accepted `InputExtentParameter` surface changes, and schedule/kernel/artifact consumers migrate atomically. In pre-production that one-time compatibility cost is admissible, not free.

**Host/runtime and memory.** Ordered access and buffer positions already exist. Removing the input payload deletes four encoded ordinal bytes per input-role occurrence and can reduce the Rust layout of role-bearing records, but exact `size_of`/RSS effects depend on enum and enclosing-struct padding and must be measured rather than promised. Explicit live references retain one `u32` coordinate, replacing rather than duplicating the old role payload. Validation stays linear, the request-subject projection is the same bounded assembly work as option 1, and no search/candidate/kernel-runtime population grows.

**Identity and schema.** Every input-bearing schedule/kernel identity changes because the role encoding loses its ordinal payload; schedule and kernel identity domains must step, and all pins/ledgers migrate. The new encoding is more canonical because ordered position is the sole local coordinate and cannot disagree with a repeated role ordinal. Program/stage identity still distinguishes declared `InputKey` bindings through the checked association. Changing `InputExtentParameter` requires an explicit kernel-program/artifact codec migration even if its semantic payload remains one local `u32` plus an axis; old bytes cannot be reinterpreted silently. Semantic program and artifact-envelope schemas remain outside this decision.

**Strongest counterargument and reversal evidence.** The wider public/identity/codec migration may buy no in-memory reduction after padding, and fieldless roles are less self-describing when logged or carried alone. Prefer option 1 if a complete consumer prototype finds a correctness-bearing standalone role with no ordered owner or typed handle, or if exact layout/encoding measurements show the redundancy cost is immaterial and Tom prioritizes dense-corpus byte continuity. Prefer this option if the prototype closes every standalone reference with existing access/buffer/witness handles and shows the fieldless model materially simplifies invalid-state validation or retained/encoded size.

**Negative controls.** Perturb an input reference to an intermediate position; reorder access and stage-buffer lists independently; repeat one declared input under two mapped local positions; drop a bounds witness; swap an `InputExtentParameter` position; and change only the declared subject mapping. Each unchanged assertion must name the owning coordinate mismatch. Census every standalone `TensorRole` consumer and make one deliberately omit its companion coordinate so the census/test fails.

## Option 4 — rename the public type to `RegionInputOrdinal`: eliminated as dominated

A complete rename can make the locality visible in every call site, but the existing type's defining docs, constructor, and use in scalar expressions already carry that exact meaning. Renaming changes every consumer and public spelling without improving validation, authority, identity, memory, or unsupported populations over option 1. The defect is the contradictory use in `TensorRole` and compiler binding, not an underspecified type name.

## Option 5 — retain the contradiction or make only sparse schedules fail while deferring the association: eliminated from the final frontier

The current compiler's request-binding checks keep its own declared-role schedules from silently rebinding, but the public type still has two incompatible meanings and declared interface position remains folded into shared schedule identity. Leaving that state in place resolves neither the contract nor the identity conflation. A temporary dense-role refusal is correct but cannot compile subset/epilogue/fold/contraction populations until the checked association exists and does not satisfy the prerequisite. It is a safe implementation staging step within the selected survivor, never a completed outcome or independent public model. Typed deferral remains the state of downstream symbolic work while this decision is open; it is not a truthful resolution of the already-public contradiction.

## Frontier and recommendation

Options 1 and 3 remain nondominated and both make the coordinate uniformly region-local. Option 1 preserves the accepted variant shape and dense-corpus bytes, but retains a redundant role ordinal and a verifier obligation to prove it agrees with access position. Option 3 makes that disagreement unrepresentable and removes encoded redundancy, but changes every input-role construction and identity plus the accepted live-extent parameter/codec surface; its Rust-layout benefit remains measurement-dependent. Both use the same already-retained request authority and add only the missing typed projection into assembly.

The concrete question for Tom is: **preserve the explicit local ordinal on `TensorRole::Input` for narrower migration and dense-byte continuity (Option 1), or make the role fieldless and pay the complete pre-production identity/codec migration for one positional authority (Option 3)?** The recommendation is Option 3: the source census identifies an existing ordered, witnessed, handled, or named coordinate at every current carrier, and pre-production policy favors removing redundant invalid states over preserving internal bytes. Option 1 is the strongest counterpoint when dense-corpus identity continuity matters more than the permanent duplicate coordinate. Exact layout measurement remains reversal evidence about the size benefit, not a missing correctness prerequisite. Rejection keeps the reconciliation and symbolic schedule path blocked; it does not select declared schedule ordinals or validate the current mixed meaning.
