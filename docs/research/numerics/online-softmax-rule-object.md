## Outcome

**A rewrite rule is not a rule plus a dimension set. It is a rule plus a *dimension function of the scheduled fold tree*, and the tree that decides the dimensions is a strictly richer object than the pair the bound is priced from.** Five results carry that, and the third was not anticipated by any prior record.

**Inference — the rule object has the shape the compile path already uses, and the live reassociation rule is its template rather than an analogy.** `OrderedReassociationRule::evaluate` (`crates/tiler-compiler/src/normalize.rs:699`) takes a program and a resolved contract and returns a vector of independently classified `RewriteAssessment`s — `Semantic`, `Numerical`, `Configuration` — each accepted or declined with a stable reason key. That is [ADR 0014](../../decisions/0014-reassociation-vs-permutation.md)'s two-fact structure on the compile path. The online-softmax rule is the same object with three additions: a bound, a shape parameter, and a *set* of numerical assessments where the reassociation rule has one.

**Inference — the capability layer is an append to an existing count-then-tag list, and the vocabulary addition is free at the identity domain while the first declaration is not.** `OperationAlgebraicCapabilities::encode` (`crates/tiler-ir/src/semantic/operation.rs:948`) writes a count of declared laws followed by one tag byte per law; with no law declared it writes eight zero bytes and nothing else. So a second, *parameterized* law changes no existing definition's bytes until an operation declares it. Part 1 derives what the payload must be for the append to stay injective, and what refuses a malformed equation.

**Inference — the dimension set is shape-dependent, and a rule must therefore declare a function rather than a set.** [The tree-fold record](tree-fold-online-softmax-bound.md) establishes that the sequential online fold consumes distributivity and elementary-function identity while any other merge tree additionally consumes reassociation. **So R2's consumed set is not a property of R2.** Part 3 eliminates the three alternatives — declare the union, split into two rules, declare only the sequential set — and derives the declaration's obligations. **And the shape parameter the dimension function needs is not the one the bound needs:** `(D, h2)` prices the rewrite, but `h2 = V - 1` does not distinguish the canonical left-deep chain from any other caterpillar, and only the canonical one avoids reassociation. The rule must be handed the tree.

**Inference — five of the six admission obligations refuse today, and only one of the five refuses for want of a permission.** Part 4 discharges or refuses each explicitly. Obligation 6 — ADR 0101 decision 7's, the sixth — is the only one that discharges cleanly, for all three fold shapes, and it discharges from an invariant of the fold rather than from any field of the accuracy contract. Obligation 1 refuses on the subnormal clause, on a registered fact about the pinned workload, and **that refusal is independent of both permissions**: even the both-admitted corner of the elementary-identity record's four-outcome table does not make this rewrite reachable on an ordinary attention row without a proved value precondition.

**Correction — 2026-08-06, under [`close-the-eps-exp-open-axis-in-the-rule-object-record`](../../../tickets/close-the-eps-exp-open-axis-in-the-rule-object-record.md): obligation 2 is no longer one of the five.** [`expose-the-numeric-elementary-accuracy-a-parametric-bound-can-instantiate`](../../../tickets/expose-the-numeric-elementary-accuracy-a-parametric-bound-can-instantiate.md) landed `elementary_relative_accuracy` (`crates/tiler-compiler/src/target/accuracy.rs:990`), so the target authority now answers the numeric question and the tally is four refusals — obligations 1, 3, 4, and 5 — beside obligation 6's clean discharge and obligation 2's conditional one. **The sentence above about obligation 1 is unaffected and is the reason the correction changes nothing about reachability**: the number arrives carrying the region it holds over, and that region is obligation 1's subnormal clause seen from the accuracy side rather than a second condition. Part 4's obligation 2 carries the reading and the per-family numbers.

**Inference — the refusal ADR 0101 decision 6 requires is fully expressible in today's explain vocabulary, and the one thing missing is quantitative.** Part 5 derives the production site exactly: `record_rewrite_assessment` (`crates/tiler-compiler/src/normalize.rs:609`) turns each declined `Numerical` assessment into an `ExplainEvent::Check` at `ExplainStage::NumericalLegality` with `RejectionClass::NumericalIllegal`, which `ExplainEvent::disposition` (`crates/tiler-compiler/src/explain.rs:817-825`) maps to `ExplainDisposition::RejectedNumerical`. The elementary-identity record's Part 7 block is not a string in the tree and must not become one: it is the *rendering* of one declined assessment per missing dimension. What cannot be carried today is the price — `FactValue` (`crates/tiler-compiler/src/explain.rs:376`) has no exact-rational variant — and that gap fires only under an admission.

## Part 1 — The capability spelling for a declared functional equation

[ADR 0101](../../decisions/0101-treat-elementary-function-identities-as-a-fourth-numerical-dimension.md) decision 3 places the per-function content in "an operation-owned identity-encoded capability" declaring "the functional equation it satisfies, with that equation's real-domain side condition". This part derives what that costs and what refuses a malformed one. It executes none of it.

### The subject is a subordinate evaluation, not the operation

**Fact — the operation that would declare the equation does not name the function the equation is about.** `tiler::softmax-f32@1` is one atomic key over six elementary steps, and `crates/tiler-ir/src/semantic/softmax.rs:6` records that the graph "admits none of a `Maximum` reduction, a general `Exp`, or a general `Divide` as a semantic key". The exponential that satisfies `exp(a) exp(b) = exp(a + b)` is *subordinate* to the key.

**Fact — the registry already carries a subordinate evaluation's contract inside an operation's own facts, and there is exactly one such evaluation per family.** `SOFTMAX_F32_FACT_EXPONENTIAL_ACCURACY_CONTRACT` (`crates/tiler-ir/src/semantic/softmax.rs:252`) writes `softmax_f32_exponential_accuracy_contract()`'s canonical value into the definition facts, "so that ADR 0016's requirement … is satisfied by the registry's own definition projection rather than by a second authority beside it". `required_elementary_accuracy` (`crates/tiler-compiler/src/target/accuracy.rs:739`) has three arms — `tiler::silu-f32@1`, `tiler::rms-norm-f32@1`, `tiler::softmax-f32@1` — and each names one subordinate evaluation.

**Proposal — the capability's subject is bound to the accuracy contract's subject, and that binding is what refuses a malformed declaration.** A functional-equation capability names the same subordinate evaluation the operation's registered accuracy contract governs, identified the same way rather than by a second name. Three refusals follow and each is a real one:

1. **An equation whose subject is not a subordinate evaluation the operation's own accuracy contract governs is refused at registration.** Without the binding, an operation could declare an equation about a function it does not evaluate, and no later authority would notice: the contract and the capability would be two independent strings in one fact record.
2. **An operation declaring an equation the vocabulary does not enumerate cannot be constructed.** The equation is an enumerated identifier — not free text — because a rule matches on it and because two spellings of one equation would otherwise be two capabilities with the same meaning and different identity bytes.
3. **A rule requesting an equation the operation does not declare is declined by its own semantic guard**, with a reason key parallel to the live `semantic.ordered-associativity-undeclared` (`crates/tiler-compiler/src/normalize.rs:720`). ADR 0014's rule that "a missing declaration is unknown, never evidence that the inverse law holds" (`crates/tiler-ir/src/semantic/operation.rs:918`) carries over unchanged.

### The side condition is typed, not prose, because two obligations consult it

**Inference.** ADR 0101 decision 3 requires the declaration to carry the equation's real-domain side condition, and [the elementary-identity record's](elementary-identity-rewrite-dimension.md) Part 2 derives that a side condition is a value-domain fact under [ADR 0021](../../decisions/0021-validated-value-assumptions.md)'s provenance classes. Part 4 below shows both obligation 5 and obligation 6 *read* it: obligation 6 proves the rewritten arguments lie inside the accuracy clause's declared domain, and obligation 5 discharges the precondition the bound consults. **A prose side condition cannot be read by either**, so the payload is a typed value-domain predicate over the evaluation's operands, in the same vocabulary the accuracy contract's `AccuracyDomainClause` already uses for its intervals. For the exponential the predicate is vacuous — the equation holds on all of `R` — and that is itself the information a rule needs, because a vacuously-satisfied side condition is what makes the exponential's identity cheaper to consume than the logarithm's.

### What a parameterized law costs the encoding, by per-tag injectivity

**Fact — the encoding is a count-prefixed list of law tags, and the count frames laws rather than bytes.** `OperationAlgebraicCapabilities::encode` (`crates/tiler-ir/src/semantic/operation.rs:948`) is `push_len(output, usize::from(self.ordered_associativity))` followed by `output.push(0x01)` when the flag is set. `push_len` (`crates/tiler-ir/src/identity.rs:84`) writes eight big-endian bytes. `algebraic_capabilities_have_a_canonical_positive_tag` (`:1731`) pins both renderings: `none()` is `0_u64.to_be_bytes()` and the declared form is that concatenated with `[0x01]`.

**Fact — the encoder is one-way and feeds the definition projection.** `encode_operation_definition` (`crates/tiler-ir/src/semantic/registry.rs:2828`) calls `definition.algebraic_capabilities().encode(output)` at `:2840`, between the canonical facts and the conformance identity; `encode_definition_projection` (`:1780`) prefixes `tiler.semantic-definition-projection.v5\0` and frames the operation list. There is no decoder, so what has to hold is injectivity, not parseability.

**Inference — the append is injective per tag if and only if the parameterized payload is self-delimiting.** Two capability sets collide only if they render the same byte string. The count differs when the number of declared laws differs. At equal counts the tag sequence is compared position by position: a bare law contributes one byte and a parameterized law contributes its tag plus its payload, so a reader walking the sequence knows from the tag whether a payload follows — provided the payload frames its own length, which `push_slice` and `CanonicalValue::encode` both do and a raw byte run does not. **That is the whole condition, and it is the per-tag injectivity reasoning AGENTS.md requires at each encoding site rather than an appeal to the gate staying green.** A payload written as an unframed run would let one law's trailing bytes and the next law's tag exchange places, which is a collision between two structurally distinct capability sets.

**Inference — the vocabulary addition moves no identity and the first declaration moves one.** With no law declared, `encode` writes `push_len(0)` and stops, so adding a second law to the struct changes not one byte of any currently registered definition. **The identity-domain step is the declaration on `tiler::softmax-f32@1`, not the widening**, and it is a step: that operation's definition bytes move, so `tiler.semantic-definition-projection.v5` changes for every program containing a softmax, which feeds the registry snapshot identity the compiler's explain request qualifier pins. Two things are consequently true and are stated separately because they are decided by different owners: the *byte-level* fact that today's renderings are unchanged, and the *convention* question of whether the projection's version tag steps for a rendering the vocabulary admits but no definition uses. **This record does not answer the second and does not execute either**; it states the boundary so that whoever lands the declaration lands it whole — the version at its owning layer, the ledger documents in the same commit, and every pinned identity recomputed on the tree the step lands into.

## Part 2 — The rule object, worked on R1 and R2

[The flash-class record's](../program-planning/flash-class-capability-set.md) five-rule table is the Proposal this part works. R3 is cited where the tree form differs and is not derived here; R4 is out of scope by the ticket's non-goals, its schedule half being a filed deferral.

### R1 is not a rule object over the registered vocabulary, and saying why is the derivation

**Fact — R1's subject is two `exp` occurrences and the graph has none.** The table states R1 as `exp(x−m′)·exp(m′−m) → exp(x−m)` under a running maximum, consuming elementary-function identity alone. [The elementary-identity record's](elementary-identity-rewrite-dimension.md) Part 6 already checked exactly this candidate while searching for a caller not blocked by ADR 0095: "**A pure elementwise fold, `exp(a) * exp(b) → exp(a + b)` over two `Exp` occurrences.** Not statable: `crates/tiler-ir/src/semantic/softmax.rs:6` records that the graph 'admits none of a `Maximum` reduction, a general `Exp`, or a general `Divide` as a semantic key', so there is no occurrence to fold."

**Inference — so R1 is a lemma of R2's derivation rather than a sibling of it, and declaring it as a rule would double-count.** The telescoping step is the load-bearing step *inside* the online fold's price: [the certified-bounds record's](certified-bounds-as-rewrite-permissions.md) Part 2 Step 3 and [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 2 Step 2 both charge it once, in the `(1 + eps_exp)^D` factor and in the argument-perturbation telescoping. A separate R1 rule carrying its own bound, composed with R2 over the same program, would charge the same evaluations twice — and a rule whose bound over-charges is not conservative-and-safe, because two rules that each refuse are not the same object as one rule that admits at the correct price.

**Inference — R1 becomes a rule object exactly when a general `Exp` key is registered, and it is then the one rule in the table with no shape dependence.** Its dimension set would be `{elementary-function identity}` and nothing else: a two-occurrence elementwise fold regroups no contributor sequence, so no reassociation is consumed at any shape, and it distributes over no sum. Its bound would be per-site rather than parametric in a fold tree, because it has no fold. **That contrast is what makes Part 3's result visible**: shape-dependence is not a property of rewrites in general, it is a property of rewrites whose subject is a fold.

**Inference — the flash-class table's R1 row is therefore wrong in one word and the correction is out of this record's scopes.** It lists R1 as a rule with an owner for its bound; it is a step of R2's bound with no independently matchable subject. The same table's R3 row lists "the same two" dimensions as R2, which [the tree-fold record](tree-fold-online-softmax-bound.md) refutes — the tree form consumes three. Both rows sit under `research/program-planning`; [`correct-the-flash-class-rule-table-rows-this-record-refutes`](../../../tickets/correct-the-flash-class-rule-table-rows-this-record-refutes.md) owns them.

### R2, stated as the object the compile path would hold

**Proposal.** The rule object, in the shape `OrderedReassociationRule` already uses, with the three additions this rewrite forces.

```text
rule       tiler.algebraic/online-softmax-normalizer-fold-f32.v1
subject    the denominator sum fold of tiler::softmax-f32@1
requires   capability: the subordinate exponential declares exp(a)exp(b) = exp(a+b)
                       with a vacuous real-domain side condition
           shape:      the scheduled candidate's merge tree T over the row's contributors
dimensions consumed(T) = { distributivity, elementary-function identity }
                            when T is the canonical left-deep chain
                       = { distributivity, elementary-function identity, reassociation }
                            otherwise
bound      P(D, h2) = (1 + eps_exp)^D * (1 + gamma_{h2 + D}) / (1 + gamma_{h2}) - 1
           D  = rescale depth of T;  h2 = summation depth of the shape-matched baseline
           eps_exp from the target authority; u = 2^-24; both exact rationals
side conditions
           binary32 round-to-nearest-ties-to-even; no overflow; no subnormal
           intermediate; max exact; N * u < 1 with N = h2 + 2D
answer     Admit | Refuse | Undecided(reason), Undecided fail-closed
```

**Fact — every field above is read from a merged record rather than authored here.** The bound and its parameters are [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 2 Step 4 and Part 4; the side conditions are its Part 2 assumptions; the three-way answer with `Undecided` fail-closed and the never-a-cost placement are [the certified-bounds record's](certified-bounds-as-rewrite-permissions.md) Part 3.

**Inference — what the bound is parametric in, and where each parameter comes from.** `D` and `h2` are combinatorial properties of the scheduled fold tree, computable at compile time with no knowledge of any input value, which is the property that makes a per-rule closed form usable inside a search at all. `u` is a property of the arithmetic type the resolved contract names. `eps_exp` is the one parameter that must come from the target authority, and Part 4's obligation 2 is where it refused at this record's base — **since 2026-08-06 that authority answers, and what a rule receives is a number *with the region it holds over*, which Part 4's obligation 2 restates**. **The logit spread `A` is absent from the price and present in both folds' bounds**, which is why the price is instantiable and why the baseline must be shape-matched — quoting an unmatched baseline credits the rewrite for a permission the caller spent elsewhere, which [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 2 Step 4 measures as a `-2.88e-5` credit at `V = 512` and names as unsound in the admitting direction.

**Inference — where the bound's side conditions come from, and they come from three different places.** The rounding mode and the format are the resolved numerical contract's, per arithmetic type. `max` being exact is the operation's own registered fact, `SOFTMAX_F32_FACT_MAXIMUM_FOLD_LEGALITY` (`crates/tiler-ir/src/semantic/softmax.rs:577`). No overflow, no subnormal intermediate, and `N * u < 1` are properties of the *candidate*, of which the first and third are decidable from the shape and the domain and the second is not. **That the second is not decidable from the shape is the finding of Part 4.**

## Part 3 — How a rule declares a shape-dependent dimension set

This is the question no prior record asked, and it arrived with [the tree-fold record](tree-fold-online-softmax-bound.md).

**Fact — the same rewrite consumes two dimensions at one fold shape and three at another.** That record's Part 1 derives it: "expanding the tree fold over the reals yields the sum of the two-pass contributors *grouped by that tree* — distributivity and the elementary identity get exactly that far and no further … Reaching the pinned contributor order from a tree grouping is then precisely the move [the reduction contract's] allowed-trees table governs, and `SOFTMAX_F32_FACT_SUM_FOLD_ORDER` pins the strict left fold, so the regroup consumes the separately resolved reassociation permission." And: "Algorithm 3 is the *left-deep* merge tree, whose expansion is the left-deep grouping — the canonical one. It therefore needs no reassociation."

### The elimination

**Candidate A — declare the union always.** The rule declares `{distributivity, elementary-function identity, reassociation}` for every shape. **Eliminated, and it is the candidate a reviewer would wave through as the conservative one.** It refuses the sequential fold under a contract granting the first two, which is the wrong direction — a legal rewrite refused. Worse, its *refusal names a dimension the rewrite does not consume*, and that is the same false inference [ADR 0080](../../decisions/0080-treat-distributivity-as-a-third-numerical-dimension.md) item 5 and [ADR 0101](../../decisions/0101-treat-elementary-function-identities-as-a-fourth-numerical-dimension.md) decision 6 exist to prevent, run backwards: a caller told the sequential fold needs reassociation would grant reassociation and still be refused, and would have granted a freedom for nothing. Over-naming and under-naming are both defects in the same explanation.

**Candidate B — split R2 into two rules, one per shape class.** Two `RewriteRuleIdentity` values, two revisions, one bound formula. **Eliminated because it relocates the shape dependence rather than removing it.** The split point is not a property of either rule: which one matches is decided by the scheduled candidate's merge tree, so each rule needs a matching predicate that computes the same tree classification the dimension function would have computed. The split therefore buys nothing and costs a second identity, a second revision to keep in step, and two copies of one derivation — where `P(D, h2)` specializes to the sequential form *exactly*, checked in exact rational arithmetic at five contributor counts by that record's probe.

**Candidate C — declare the sequential set and check reassociation elsewhere.** **Eliminated on the refusal.** A tree-shaped candidate refused for two of its three missing dimensions implies that granting those two would suffice — precisely ADR 0101 decision 6's stated failure mode, which that decision widened ADR 0080 item 5 to cover.

**Result — a rule declares a dimension *function*, and its obligations are three.** The declaration's subject is the scheduled fold tree and its value is a dimension set.

1. **Totality over the declared shape domain.** A rule states the shapes it speaks about; a shape outside that domain is not a shape whose dimension set defaults to anything.
2. **An undeclared shape refuses rather than defaulting**, in the same direction every other silence in this system takes: [Numerical semantics](../../numerical-semantics.md#per-dimension-honourability-and-how-it-composes-with-feasibility) makes a dimension a profile does not speak to `Unknown` in ADR 0043's sense, and `Unknown` never reaches an executable frontier. A dimension function that returned the empty set for an unrecognized tree would be a rewrite authorized by silence.
3. **Monotonicity is not assumed.** Nothing establishes that a deeper or wider tree consumes a superset of a shallower one's dimensions, and a caller must not be able to infer one shape's authorization from another's. This is [ADR 0011](../../decisions/0011-per-operation-numerical-permissions.md)'s "one permission never implies another", applied across shapes of one rule rather than across dimensions of one contract.

### The consequence the accepted text already supports, and the one it does not

**Inference — ADR 0101 decision 6's subject is the rewrite instance, not the rule, and the shape dependence forces that reading.** The decision says "a rewrite consuming this dimension rejects, and the rejection names every missing dimension". If a rule's consumed set varies by shape, the only reading under which "every missing dimension" is well-defined is the per-candidate one. **The accepted wording already reads that way and no amendment is needed**; what this record adds is that the reading is now load-bearing rather than incidental.

**Inference — the shape parameter the bound needs and the shape parameter the dimension function needs are different objects, and this widens an open axis rather than closing it.** `(D, h2)` prices the rewrite and is sufficient for that: [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 4 derives that both are compile-time computable and that `V` alone is neither sufficient nor necessary. **But `(D, h2)` does not decide the dimension set.** `h2 = V - 1` says the summation tree is a chain; it does not say the chain is the canonical left-deep one in contributor order, and only the canonical one avoids reassociation, because `SOFTMAX_F32_FACT_SUM_FOLD_ORDER` (`crates/tiler-ir/src/semantic/softmax.rs:581`) pins "the strict left fold over the canonical contributor sequence, seeded at the first contributor". A caterpillar of the other orientation has the same `(D, h2)` and consumes reassociation. So the schedule must hand the rule the *tree*, from which the pair is derived, and [`carry-the-rescale-depth-a-parametric-bound-instantiates-from`](../../../tickets/carry-the-rescale-depth-a-parametric-bound-instantiates-from.md)'s stated scope — a rescale depth — is insufficient for the rule that would read it. That ticket carries a dated note recording this; it stays deferred, because the widening does not fire its trigger.

## Part 4 — The six admission obligations, each discharged or refused

[The certified-bounds record's](certified-bounds-as-rewrite-permissions.md) Part 3 states five; [ADR 0101](../../decisions/0101-treat-elementary-function-identities-as-a-fourth-numerical-dimension.md) decision 7 adds the sixth. Each is answered below for R2 at both fold shapes. **Five refuse. One discharges.**

**Correction — 2026-08-06. Obligation 2's verdict moved and no other did, so the tally is now four refusals, one conditional discharge, and one clean one.** Obligations 1, 3, 4, and 5 stand exactly as derived below; obligation 2 retrieves its number from the target authority and inherits obligation 1's undischarged condition rather than a second one; obligation 6 still discharges cleanly at all three shapes.

### Obligation 1 — side conditions discharged, never inherited: **refuses, and not for want of a permission**

**Inference — three of the five clauses discharge from the shape and the registered facts.** `N * u < 1` with `N = h2 + 2D` is arithmetic on the shape parameter; the tree-fold record notes it caps the sequential fold at `V <= 2^23` and is unreachable by a tree (`N = 18` at `V = 512`). Round-to-nearest-ties-to-even and the binary32 format are the resolved contract's. `max` exact is the operation's registered fact.

**Inference — no overflow discharges, and the argument is short enough to state.** `SOFTMAX_F32_EXPONENTIAL_ARGUMENT_CEILING_BITS` is `+0.0` (`crates/tiler-ir/src/semantic/softmax.rs:215`), whose doc states that the `FiniteOverflowRule` below it is "*vacuous* rather than absent: `e^t <= 1` on the whole admitted domain". Every exponential the fold evaluates — a contributor's and a rescale factor's alike — has a non-positive argument by the same monotonicity that discharges obligation 6, so every one is at most `1`, every rescale factor is at most `1`, and the accumulated `d` is at most the contributor count. No intermediate can overflow binary32 at any statable extent.

**Fact — no subnormal intermediate does *not* discharge, and the operation's own registered fact is the counterexample.** `SOFTMAX_F32_FACT_SUBNORMALS` (`crates/tiler-ir/src/semantic/softmax.rs:337`) records a **Measurement**: "this operation reaches a subnormal on an ordinary input … A contributor about 87 below the row maximum has an exponential of `0x00b33687`, a subnormal, and one about 104 below has exactly `+0.0`."

**Inference — so the clause the derivation needs is violated on ordinary attention rows, and the refusal is independent of both permissions.** The bound rests on the relative-error model that (2.5a) states, which [the certified-bounds record's](certified-bounds-as-rewrite-permissions.md) Part 2 says "does not hold there" and [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 2 restates as a refusal its probe performs rather than a caveat it reports. **The both-admitted corner of [the elementary-identity record's](elementary-identity-rewrite-dimension.md) Part 6 table therefore does not make this rewrite reachable on the pinned workload**; it makes it reachable "subject to the bound and the six obligations", and this is the obligation that then refuses. Stating that is not an argument for or against either permission — it is the fact that a decision to admit would not, by itself, deliver the rewrite.

**Inference — the precondition that would discharge it is a bound on the logit spread, and its threshold is arithmetic.** `exp(t)` is at least binary32's least normal `2^-126` exactly when `t >= -126 ln 2 = -87.3365…`, which is the value the registered fact's "about 87" reports from the other side. A proved `A < 87.33` would discharge the clause for the contributor terms. The partial sums are not exposed — at every step the running maximum is attained by some contributor already folded, whose term is `exp(0) = 1`, so `d >= 1` throughout — but the *rescaled product* `d_{j-1} · exp(m_{j-1} - m_j)` is, whenever the maximum jumps far enough, and a tree performs roughly twice as many such products as a chain (that record's Part 2 Step 5). **The complete precondition is therefore not simply "the spread is bounded" and this record does not close it**; [`derive-the-value-precondition-the-online-softmax-bound-needs-for-its-subnormal-clause`](../../../tickets/derive-the-value-precondition-the-online-softmax-bound-needs-for-its-subnormal-clause.md) owns it.

### Obligation 4 — the comparison is exact-rational, never a host float: **discharges as a pattern, and the type is not the one to reuse**

**Fact — the arithmetic exists in the right crate.** `ExactRational` is `tiler-ir`'s (`crates/tiler-ir/src/semantic/accuracy/rational.rs:175`), and `gamma_h` is a rational function of `h` and `u`.

**Fact — the three-way machinery is implemented, and it is one crate away from where the rule sits.** `ConformanceDecision` (`crates/tiler-reference/src/accuracy.rs:735`) is `Conforms`/`Violates`/`Undecided { reason }` with `conforms()` returning `false` for both of the latter — the fail-closed reading. `decide_predicate` (`:782`) compares a bracketed reference against an exact candidate. **Fact — `tiler-compiler` does not depend on `tiler-reference`:** `crates/tiler-compiler/Cargo.toml` lists `num-bigint`, `num-integer`, `num-traits`, and `tiler-ir`, and nothing else.

**Inference — so "reuse it" is right about the pattern and wrong about the type, and stating which is part of this ticket.** Adding a compiler-to-reference dependency would put the oracle crate on the compile path, and that crate's own module header calls its independence "the point of the crate": two oracles that shared a lowering "would agree with each other for reasons that say nothing about either being right". **Inference — and the two `Undecided`s are generated by different things, which is the sharper reason not to share the type.** In `decide_predicate`, `Undecided` arises from an enclosure straddling a tolerance, and `UndecidedConformance` (`crates/tiler-reference/src/accuracy.rs:663`) enumerates seven reasons in that vocabulary — `EnclosureTooWide`, `MetricUndefined`, `ReferenceNotProvablyNonzero`, and their siblings. **The admission rule's comparison needs no enclosure at all**: `P(D, h2)` is an exact rational given exact `eps_exp` and `u`, and the caller's tolerance is an exact rational, so the comparison is a two-way exact one. ### Obligation 6 (ADR 0101 decision 7) — the rewritten program's elementary arguments lie inside every accuracy clause's declared domain: **discharges, at all three shapes**

[The elementary-identity record's](elementary-identity-rewrite-dimension.md) Part 4 gives the argument as an observation a reader makes. This restates it as a step the rule performs, which is what the ticket asks for and what makes it checkable.

**The obligation, stated as the rule's own step.** For each elementary evaluation site the rewrite *creates*, the rule exhibits a witness that the argument lies inside every clause of the operation's registered accuracy contract. The clause is read from the registry rather than assumed: `SOFTMAX_F32_EXPONENTIAL_ARGUMENT_CEILING_BITS` is `+0.0` and the ordinary interval is `(-inf, +0.0]` (`crates/tiler-ir/src/semantic/softmax.rs:473`). A site for which no witness is produced fails the obligation; there is no default.

**The witness, per shape.**

- **Sequential (R2 at the canonical left-deep chain).** The rewrite creates two argument families, `x_j - m_j` and `m_{j-1} - m_j`. The running maximum is non-decreasing and includes `x_j`, so `x_j <= m_j` and `m_{j-1} <= m_j`, and both families are non-positive. Round-to-nearest of a non-positive real is non-positive, which is the same step the ceiling's own derivation takes.
- **Tree (R3's subject).** Along any root-to-leaf path of any merge tree the subtree maxima are non-decreasing *by nesting alone* — [the tree-fold record's](tree-fold-online-softmax-bound.md) Part 2 Step 2, which establishes that this holds "for a balanced tree, a caterpillar, a ragged block partition, a multi-round loop-carried accumulator, and any composition of them". So the same witness covers every tree, with no shape case analysis.
- **R1, were it ever statable.** `x <= m′ <= m` gives all three of `x − m′`, `m′ − m`, and `x − m` non-positive by the same invariant, and the rewrite *removes* a site rather than adding one.

**Inference — the obligation's check count scales with the tree while its argument does not.** A tree performs roughly `2(V−1)` rescale evaluations where a chain performs `V−1`, so the number of sites needing a witness roughly doubles — the same doubling obligation 1's subnormal clause takes, and for the same reason. The witness itself is one invariant regardless.

**Inference — this is the obligation whose absence is invisible in the contract's own fields, and the discharge is what makes it visible.** The clause's ceiling, tolerance, and metric do not move under the rewrite; what moves is whether the sentence justifying the ceiling is still true. A rewrite without this witness — a global rescale onto an earlier maximum, say — would place obligations on arguments the contract declares unreachable, with no field in which the difference could be seen. **Discharging it is therefore not a formality even though it succeeds here**: it is the only one of the six that would fail silently if omitted.

## Part 5 — The refusal, emitted rather than described

[ADR 0101](../../decisions/0101-treat-elementary-function-identities-as-a-fourth-numerical-dimension.md) decision 6 requires a rejection to name every missing dimension, the function, and the identity. [The elementary-identity record's](elementary-identity-rewrite-dimension.md) Part 7 quotes the exact wording as a checkable block. This part derives where that wording is produced and what carries it.

### The production site, read end to end

**Fact — the path exists and has four steps.**

1. A rule's `evaluate` returns `Vec<RewriteAssessment>` (`crates/tiler-compiler/src/normalize.rs:699-777`). `RewriteAssessment::declined` (`crates/tiler-compiler/src/rewrite.rs:174`) carries the rule identity, the class, and a `&'static str` reason key.
2. `record_rewrite_assessment` (`crates/tiler-compiler/src/normalize.rs:609`) maps `RewriteAssessmentClass::Numerical` to `ExplainStage::NumericalLegality`, the predicate `rewrite.numerically-legal`, and `RejectionClass::NumericalIllegal`; it builds `PredicateAssessment::disproved(predicate, ReasonCode::new(assessment.reason())?, EvidenceBasis::CheckedInvariant)` and attaches four facts — `rewrite-provider`, `rewrite-rule`, `rewrite-revision`, `assessment-reason`.
3. The record is written as `ExplainEvent::Check { stage, assessment, rejection }`.
4. `ExplainEvent::disposition` (`crates/tiler-compiler/src/explain.rs:817-825`) maps a `Check` whose assessment is `Disproved` and whose rejection is `NumericalIllegal` to `ExplainDisposition::RejectedNumerical`, which renders as `"rejected-numerical"` (`:2561`).

**Inference — so the Part 7 block is not a string in the tree and must not become one.** It is the *rendering* of a set of records. Making it a literal would put one refusal's prose inside a rule, where a second rule consuming the same dimensions would need a second copy, and where the dimension enumeration could disagree with the dimension function that produced it.

### What each element of the required wording is carried by

**Proposal — one declined `Numerical` assessment per missing dimension, and the channel already admits several.** `PreparedAlgebraicRule::assessments` is a `Vec`, and the live add rule already returns two assessments of two different classes; nothing in `record_rewrite_assessment` or in the writer restricts a class to one record. **So ADR 0101 decision 6's "names all of them" needs no widening of the explain channel** — it needs a rule that emits one record per missing dimension instead of one verdict, with reason keys in the shape the live rule already uses:

```text
numerical.distributivity-forbidden
numerical.elementary-identity-forbidden
numerical.reassociation-forbidden          (tree shapes only, per Part 3)
```

**Inference — the function and the identity are facts, not reason-key text.** ADR 0101 decision 6 requires the refusal to name the dimension, the function, and the identity, because "the dimension is one and the identities are many". `ExplainFact::new` takes a `FactKey` and a `FactValue::Identity(SubjectKey)` (`crates/tiler-compiler/src/explain.rs:376-397`), keys are bounded at 255 bytes with a forbidden-character check (`validate_key`, `:2756`), and up to 32 facts may attach to one assessment. So the elementary-identity record carries two additional facts beside the four the site already writes — the subordinate evaluation's identity and the equation's enumerated identifier — and the wording is reconstructible from the record set rather than quoted from it.

**Inference — the one thing that cannot be carried is the price, and it fires only under an admission.** `FactValue` has six variants — `Count`, `Bytes`, `Threads`, `Bindings`, `Boolean`, `Identity` — and `Quantity` (`:523`) has eight, none of them rational. [The certified-bounds record's](certified-bounds-as-rewrite-permissions.md) Part 4 item 5 states that a tolerance refusal must report "the stated tolerance, the derived price, and which of the five obligations failed — because 'refused' without the number is unactionable when the number is the whole point". **Under a continued decline the refusal is fully expressible today**: the rewrite is refused for missing dimensions, no price is computed, and there is no number to report. Under an admission the quantitative refusal needs an exact-rational fact value, which [`carry-an-exact-rational-quantity-in-the-explain-fact-vocabulary`](../../../tickets/carry-an-exact-rational-quantity-in-the-explain-fact-vocabulary.md) owns, filed `deferred` because its only trigger is the admission.

**Inference — and the refusal is per-candidate, not per-rule.** Part 3's dimension function makes the missing set a property of the scheduled candidate, so the emitted record set is computed after the shape is known. That is consistent with where the site already sits: `NumericalLegality` is a per-candidate stage and the assessments are recorded against a `SubjectRef`.
