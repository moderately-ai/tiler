# Complete model ingestion and execution

**Status:** durable design record for rung L6 of the language-model inference ladder. It is a research outcome, not a capability: nothing here registers an operation, admits a key, widens a budget, fixes a normative contract, or authorizes implementation. It moves no row of the [operation-family support matrix](../../roadmap.md#operation-family-support-matrix). What it delivers is the ingestion and execution contract for a complete supported model — the four boundaries stated one line each, the eliminations that fix each of them, the whole-model program shape with L5's D-13 closed, the exact refusals that stand between this design and a compiled model today, and twelve dependency-ordered delivery tickets. **Corrected 2026-08-04 under [`supersede-the-runtime-owned-kv-state-design`](../../../tickets/supersede-the-runtime-owned-kv-state-design.md):** this record inherited L5's runtime-owned state, and that owner is withdrawn — Tiler retains nothing between invocations, so the model cursor, its generations, and the poisoned status are the consumer's, delivery ticket 7 is withdrawn, and each affected sentence carries its own dated correction below. ## The four boundaries, one line each

**Proposal.** The ticket's four subjects, each stated so that it is falsifiable on its own and so that a reader can see immediately which side of the boundary a fact sits on.

- **Model description.** It never crosses. The architecture and every configuration value except the two varying extents enter as *literal extents and literal attributes in the region the consumer wrote*, fixed at expansion time; Tiler holds no `ModelDescription`, no architecture key, and no configuration record, and a second architecture is a second region rather than a second value.
- **Weights.** They cross as ordinary program inputs — the consumer's own tensor values, wrapped by the consumer's own [`TensorAdapter`](../../../crates/tiler/src/value.rs) — with no weight container, no checkpoint format, and no tensor-name vocabulary anywhere in Tiler; Tiler validates stored scalar, rank, declared literal extents, and symbol consistency, and validates nothing else about them.
- **Inputs.** The program's inputs are `[T]` token IDs at an admitted integer identity, the host-precomputed `cos` and `sin` rows, the host-built additive causal mask, the two-element `rope_sign` constant, and the cached `[8, C, 128]` key and value tensors per layer; the embedding gather stays *inside* the program, which is this record's explicit answer to the question the gather ticket handed it.
- **Logits.** One program output named `logits`, `[T, 151936]` F32, row-major dense, unnormalized, in the effective flush-to-zero contraction-free safe-math F32 realization — with no softmax, no temperature, no top-k, no argmax, no vocabulary masking, and no token; every one of those is the consumer's, and reading the value crosses ADR 0033's five-step device completion boundary.

## The model description is the region, not a datum

**Proposal — three candidates for where a supported model's architecture and configuration live.**

| Candidate | Survives? | Ground |
| --- | --- | --- |
| **M-A** — a typed `ModelDescription` in the compiler: an architecture key plus a configuration record | **No** | It makes an architecture part of compiler identity, which is the collapse the architectural contract forbids in its consumer-neutrality form: a `Qwen3` variant is a consumer's format promoted to compiler semantics, every new model is a compiler change, and the configuration record is a schema Tiler would owe validation, versioning, and canonical encoding for. It also contradicts an accepted decision rather than merely being expensive — [ADR 0069](../../decisions/0069-use-a-general-compilation-boundary.md) fixes one general entry point over a semantic program and explicitly rejects publishing the currently recognized graph shape as public compiler vocabulary. |
| **M-B** — a model-description *trait* the consumer implements, and the compiler drives | **No** | The trait's method set is the architecture surface under another name: something has to say that a model has layers, that a layer has an attention half, and that attention has a head dimension, and whatever says it has fixed what a transformer is at a consumer-neutral boundary. The dependency direction is also wrong — the compiler would call into the consumer during compilation, which is the inspection outside the macro invocation the accepted inline developer experience forbids. |
| **M-C** — the description is the consumer's; what crosses is a semantic program, its shape environment, and bound values | **Yes** | It is the boundary ADR 0069 already accepted, reached by the route that record recommended, and it is what the frontend already does: `tiler::tensor!` takes a region whose declared extents are literals and produces a `SemanticProgram`. **Fact —** `crates/tiler-macros/src/region.rs` refuses to substitute a representative extent for a symbolic one, "because a program built over invented extents would be a different program and its identity would name something no consumer wrote", which is the same principle applied one level down. |

**Inference — so the pinned checkpoint's `config.json` is split, and the split is exact.** L2 fixed that batch, hidden 1024, intermediate 3072, head dimension 128, head counts 16 and 8, layer count 28, and vocabulary 151,936 are static, and that exactly two extents vary. Under M-C every static value becomes a literal in the region text or a literal attribute on an operation — `rms_norm_eps = 1e-06` and the `0x3db504f3` scale included — and the two varying extents become the region's `sym T` and `sym S`. **Inference — the layer count is the one configuration value that must not enter any program**, because it is a repetition count over an identical subgraph rather than a shape: putting it inside makes a 28-layer and a 32-layer model two artifact identities for one computation, and leaving it outside makes it a consumer loop bound that costs nothing.

**Inference — this makes the checkpoint-versus-region disagreement a checked refusal rather than a silent wrong answer, and L1 already named the exact trap.** L1 records that `head_dim` is 128 while `hidden_size / num_attention_heads` is 64, and that "a planner that derives head width by division produces a silently wrong shape on this checkpoint". Under M-C a region compiled at the derived 64 binds a `[128]` `q_norm` weight and refuses by name: **Fact —** `BindError::LiteralExtentMismatch` carries the operand axis, the extent the region declared, and the extent the adapter reported, and `crates/tiler/src/expansion.rs:219` is the site that raises it. That refusal is implemented today, delivered by [`check-a-literal-operand-extent-against-the-supplied-value`](../../../tickets/check-a-literal-operand-extent-against-the-supplied-value.md).

**Proposal — and therefore the pinned model's program is a consumer, and consumers live outside `crates/`.** The first complete-model driver belongs beside `prototypes/candle-metal-adapter`, which is where the workspace already puts a consumer that must not become compiler vocabulary. This record requests no crate admission; that is Tom's regardless of how the derivation ran.

## Weights are ordinary program inputs, and the container is the consumer's map

**Proposal — three candidates for the weight container.**

| Candidate | Survives? | Ground |
| --- | --- | --- |
| **W-A** — one whole-model program taking all 310 weights as operands | **No** | Refused by an implemented budget before any argument about taste: **Fact —** `verify_program` at `crates/tiler-compiler/src/request.rs:1886` checks `check_budget("buffers", budgets.buffers, 4.max(program.input_count().saturating_add(1)))`, and the governed `buffers` budget is 4, so a program declaring more than three inputs is refused as `RequestError::BudgetExceeded`. It also cannot reach any consumer launch path; see *What refuses today* below. |
| **W-B** — a compiler-side `WeightSet` keyed by tensor name | **No** | It is a consumer format in disguise: the names are safetensors' names, the shape-and-dtype schema it would validate against *is* the model description M-A was eliminated for, and it duplicates the interface keys the region already declares. A second naming authority for one subject is the failure the corpus keeps eliminating. |
| **W-C** — each program declares only the weights it uses; the 310-entry map is the consumer's | **Yes** | The layer program declares eleven weight operands and the head program one; the consumer's model driver holds the map from checkpoint tensor name to interface key and supplies the right eleven per execution. Nothing in Tiler learns that a checkpoint exists, and the map is exactly the artefact a digest discipline can be attached to. |

**Fact — the arithmetic closes against L1's own budget, which is what makes W-C's partition checkable rather than asserted.** One layer's eleven weights are `w_input_layernorm` 4,096 B, `W_q` 8,388,608, `W_k` 4,194,304, `W_v` 4,194,304, `w_q_norm` 512, `w_k_norm` 512, `W_o` 8,388,608, `w_post_attention_layernorm` 4,096, `W_gate` 12,582,912, `W_up` 12,582,912, and `W_down` 12,582,912 — **62,923,776 bytes**, which is L1's 15,730,944 parameters per layer at four bytes. Twenty-eight layers is 1,761,865,728 B; the tied embedding matrix is 622,329,856 B and `model.norm` is 4,096 B; the total is **2,384,199,680 bytes**, exactly L1's F32 weight budget with nothing unaccounted for.

**Inference — the tied matrix is one bound value read by two programs, and the duplication it invites costs a stated number.** L1 records that the inventory contains no `lm_head.weight`, so one `[151936, 1024]` matrix serves the input gather and the output projection. Under W-C those are two programs, so the matrix is bound twice, read-only both times — which raises no aliasing question, because `verify_storage`'s `ForbiddenAlias` is about a program input and a program output sharing one allocation. What it does raise is a consumer obligation with no enforcer: binding two copies costs **622,329,856 bytes (0.5796 GiB)**, and nothing below the consumer can tell that the two bindings name one tensor.

### What Tiler validates, and the permutation it cannot see

**Fact — the implemented validation, in the order `bind_region` performs it.** Operand count against the region's declaration (`BindError::OperandCountMismatch`); the adapter's declared capabilities (`UnsupportedCapability`, and `AdapterCapability::DenseRowMajorStorage` is the storage property the first dispatch profile requires); rank (`RankMismatch`); stored scalar (`StorageScalarMismatch`); every axis the region fixed literally (`LiteralExtentMismatch`); and every pair of axes naming one symbol (`InconsistentExtent`, which names both axes and both extents). Each carries the operand's stable interface key rather than a position, because "operand 1 axis 0" is not something a consumer can locate in a region they wrote.

**Inference — and there is exactly one thing that validation cannot see, which is the weight analogue of L5's incorrect-position case and is quantitatively worse.** The checkpoint's 310 tensors fall into eight shape classes, and every member of a class is interchangeable as far as every check above is concerned:

| Shape | Count | Roles |
| --- | --- | --- |
| `[151936, 1024]` | 1 | the tied embedding |
| `[1024]` | 57 | 28 `input_layernorm`, 28 `post_attention_layernorm`, `model.norm` |
| `[2048, 1024]` | 28 | `q_proj` |
| `[1024, 1024]` | 56 | 28 `k_proj`, 28 `v_proj` |
| `[128]` | 56 | 28 `q_norm`, 28 `k_norm` |
| `[1024, 2048]` | 28 | `o_proj` |
| `[3072, 1024]` | 56 | 28 `gate_proj`, 28 `up_proj` |
| `[1024, 3072]` | 28 | `down_proj` |

**Inference — so swapping one layer's `k_proj` and `v_proj`, or binding layer 7's weights at layer 8, produces a correctly shaped, correctly typed, correctly dense tensor that every layer of Tiler accepts and that returns a plausible logit vector with a wrong argmax.** The number of shape-and-dtype-preserving bindings is `57! · 56!² · 28!⁴`, of which one is right; every other check in the stack is indifferent between them. This is a *stronger* statement than "unchecked": the checks that exist all pass.

**Proposal — the structural answer is the manifest, and it belongs to the consumer for a stated reason rather than by default.** The obligation L1 set is the manifested-by-digest discipline: the checkpoint is identified by revision and by a SHA-256 over its content bytes, and L1's own fixture producer "re-runs that verification on every invocation and stops rather than warns on a mismatch". A *weight binding manifest* extends that one step: a consumer-side record pairing each interface key with a checkpoint tensor name, its expected shape, and its expected stored scalar, checked total and injective against the checkpoint's own safetensors header, under a pinned file digest. **Inference — Tiler must not carry it, and the elimination is short.** Folding a per-tensor content digest into artifact identity would compile one artifact per checkpoint, which is worse than the per-decode-step compilation L5 already refuses. Carrying it as a runtime-validated fact under ADR 0021 would mean hashing 2.22 GiB per execution, or hashing once at model-state creation — and hashing once at creation *is* the consumer-side check, reached by a longer route. The manifest is therefore a consumer obligation, and what this design owes is that the obligation is named, checkable in one command against the pinned header, and able to fail.

### BF16 ingestion: host-side, and for a ground L2 did not have

**Proposal — three candidates, of which L2 recommended the second and asked this rung to refute or adopt it.**

| Candidate | Survives? | Ground |
| --- | --- | --- |
| **I-A** — the conversion is a Tiler semantic `Cast` inside the program | **No** | L2's grounds stand: the program becomes mixed-dtype, which forces a `Cast` family that has no key and forces BF16 from a recognized nominal identity to an arithmetic one, and buys no expressiveness because BF16 never participates in an executed arithmetic operation in this workload. **This record adds the decisive one, which is about *when* rather than about *what*.** An operation inside a program is evaluated on every execution of that program. Under the layer boundary below, a `Cast` on the eleven layer weights runs 28 times per forward pass and 252 times over the C1 row's nine passes — converting the 28 layers' 880,932,864 BF16 bytes into 1,761,865,728 F32 bytes on every token — against once at model load. No hoisting capability exists that could lift it out: a loop-invariant motion across program boundaries is not a rewrite Tiler can express, because the boundary is the consumer's loop. |
| **I-B** — host-side conversion at ingestion, before the value is wrapped | **Yes** | L1 records the conversion is exact for every finite BF16 value, since BF16 is a truncated F32. (**Correction — 2026-08-02.** This cell previously added "and even a BF16 subnormal widens to an F32 normal that the target's flush cannot touch"; that clause is false and is removed. BF16 shares binary32's exponent width, so widening preserves the subnormal class — measured exhaustively at [stage 5 of the BF16 conversion record](../numerics/bf16-computation-accumulator-and-conversion.md), 254 of 254 — and the qualified row's flush therefore *does* reach a widened BF16 subnormal. Nothing in I-B's elimination rested on the clause: the ground that carries it is exactness and the once-per-load-versus-once-per-execution argument below. See [the L8 corpus section](model-level-qualification.md#three-rows-deliberately-absent-with-the-ground-for-each).) The adapter then reports `StorageScalar::F32`, and a BF16-storage tensor refuses by name: **Fact —** `BindError::StorageScalarMismatch` carries the declared scalar and the reported one. **Measurement, inherited —** L7's control replaced all 197 weighted projections with their BF16 round trip and measured a maximum logit deviation of `0.000000e+00` over the 18 C1 positions, so widening loses nothing observable on the conformance row; that measurement qualifies one row and one checkpoint. |
| **I-C** — keep BF16 storage and let the contraction read it with F32 accumulation | **No** | No mixed-dtype contraction key exists and no BF16 arithmetic contract exists — the dtype ledger registers `tiler::bf16@1` as a nominal identity with no reference, no ABI, no kernel, and no operation signature admitting it. The accuracy motive is also already served: L7's control shows the F32 program over BF16-round-tripped weights is bit-identical at C1, so I-C would buy the halved weight residency at the price of a dtype vertical, and [`spike-bf16-through-the-second-dtype-seams`](../../../tickets/spike-bf16-through-the-second-dtype-seams.md) already owns that residency question separately. |

**Inference — L2's recommendation is adopted, and the ingestion cost is stated rather than hidden.** Host-side widening doubles the resident weight bytes from 1,192,099,840 to 2,384,199,680 and performs 596,049,920 widening conversions once per model load. That is the trade, and it is taken because the alternative performs the layer half of those conversions once per forward pass — nine times over the conformance row, and once per decoded token thereafter.

## The input boundary: the gather stays inside

[`admit-an-indirect-gather-family-for-tied-embedding-lookup`](../../../tickets/admit-an-indirect-gather-family-for-tied-embedding-lookup.md) states that if the product boundary moves so that embedding lookup happens consumer-side and Tiler receives materialized activations, the family stops being required — "and that is a decision for `design-model-ingestion-and-complete-execution` to make explicitly rather than a gap to leave open". It is made here.

| Candidate | Survives? | Ground |
| --- | --- | --- |
| **IN-A** — the program's input is `[T]` token IDs; the gather is inside | **Yes** | See the derivation below. |
| **IN-B** — the consumer gathers; the program's input is `[T, 1024]` activations | **No** | It is the cheaper option, and what it saves is not what it costs. |

**Inference — IN-B saves one capability and costs four things, and none of the four is a preference.** *First*, it does not remove the embedding matrix from the boundary: the tied matrix is still the vocabulary projection's weight, so the `[151936, 1024]` tensor crosses regardless and IN-B removes an operation while keeping the operand. *Second*, it does not save time: L2's ratio is one gather against 253 contractions per forward pass, so the gather's cost is negligible and its expressibility is the whole question. *Third*, it moves the bounds obligation to a layer that cannot state one. L2's typed refusal reads "a token ID outside `0..151936` refuses or is validated at a named enforcement boundary; it never reads out of bounds and never clamps"; under IN-B there is no named boundary, because the read happens in consumer code that Tiler neither compiles nor validates. *Fourth* and decisively, it makes the failure undetectable in exactly L5's shape: a wrong gather returns a `[T, 1024]` F32 tensor with the right shape, the right dtype, and the right accessible range, so every layer accepts it and the result is a plausible logit vector with a wrong argmax — and unlike the incorrect-position case there is not even a rotary table to blame.

**Inference — and IN-B would make the rung's own outcome false.** The ticket's user-visible outcome is that a consumer hands Tiler a supported model and receives logits. If the consumer performs the model's first operation, what it hands over is most of a model, and the boundary the outcome names does not exist.

**Fact — IN-A has a blocker at the ABI rather than at the semantics, and the two are separate.** The semantic layer already registers integer identities: `crates/tiler-ir/src/semantic/catalog.rs` registers `tiler::u8@1`, `tiler::u16@1`, `tiler::u32@1`, `tiler::i32@1`, and `tiler::i64@1` under ADR 0028, so a `[T]` index operand at `tiler::u32@1` has an admitted identity today. **Fact —** the runtime-value boundary has no carrier for it: `StorageScalar` in `crates/tiler-ir/src/program/model.rs:264` has exactly two variants, `U8` and `F32`. **Inference —** a vocabulary of 151,936 needs eighteen bits, so `U8` cannot carry a token ID; `F32` represents every integer below 2²⁴ exactly and would therefore *work*, and taking that route trades an admitted integer identity for a float-to-integer conversion contract under [ADR 0041](../../decisions/0041-separate-float-to-integer-conversion-families.md) at the one place in the program where an out-of-range value reads out of bounds. It is refused here and filed as a widening with its ABI-identity consequence stated: `StorageScalar::tag` participates in canonical encoding, so a third variant is an artifact-ABI change and therefore Tom's.

## The logits contract

**Proposal — the contract, and what is deliberately not in it.** The head program's single output is `logits`, shape `[T, 151936]`, `tiler::f32@1`, row-major contiguous, unpacked, in the one symbolic affinity's memory domain, produced by `Contract td,od->to` over `model.norm`'s result and the tied embedding matrix — with no softmax, no scale, no temperature, no top-k or top-p, no vocabulary mask, no argmax, and no token. **Inference — the exclusions are not a scope cut, they are three separate eliminations.** Sampling adds a randomness source no `OperationEffect` variant admits, and L1's exclusion table already records that `OperationEffect` is `Pure`-only and would have to widen first. A device-side argmax would need a max-with-index reduction family that does not exist and would have to pin the tie policy, which is a *policy* L1 declares — the greedy token is the lowest vocabulary index among all indices attaining the maximum — rather than a formula a family could carry. And it would save nothing: a host argmax reads 607,744 bytes per decode step against the 2,384,199,680 bytes of weight traffic the same step performs, which is 0.026%.

**Inference — the contract has two modes and they are not interchangeable, which is a feasibility statement rather than an optimization.** The conformance row needs every position: L1 records that the pinned reference's `logits_to_keep=0` becomes `slice(0, None)`, which is why C1 can retain all eighteen vectors at 10,939,392 bytes. A benchmark row needs only the final position, and the difference at B1-d prefill is **4,978,634,752 bytes against 607,744** — a saving of **4,978,027,008 bytes (4.6361 GiB)**, which is larger than the entire model's 2,384,199,680-byte F32 weight budget. **Inference — so L6 fires the sub-tensor-selection row's first trigger**, the one the support matrix states as "a prefill pass that needs only the final position's logits", and it fires it on residency rather than on convenience. The all-positions mode is what the conformance evidence needs and is expressible today once the projection exists; the final-position mode needs a family the corpus does not define.

## Whole-model composition: three programs, thirty executions, three identities

**Proposal — the partition, and the ground for each cut.** One forward pass over `T` new positions against `C` cached positions is three distinct semantic programs, executed thirty times.

| # | Program | Inputs | Outputs | Operations | Executions per forward pass |
| --- | --- | --- | --- | --- | --- |
| P1 | embedding gather | `token_ids [T]`, `W_embed [151936, 1024]` | `x0 [T, 1024]` | 1 | 1 |
| P2 | decoder layer | 18 — L4's twelve, L5's `k_cache` and `v_cache`, and the MLP's `w_post_attention_layernorm`, `W_gate`, `W_up`, `W_down` | 3 — `h_out [T, 1024]`, `k_rope [8, S, 128]`, `v_heads [8, S, 128]` | ≥ 51 | 28 |
| P3 | final norm and vocabulary projection | `h [T, 1024]`, `w_norm [1024]`, `W_embed [151936, 1024]` | `logits [T, 151936]` | 2 | 1 |

**Inference — the operation count for P2 is derived rather than estimated.** L4 counts the attention half's graph at "at least forty-four occurrences" — one normalization, three projections, three head splits, two per-head normalizations, ten nodes for each of the two rotary applications, four further structural nodes, the score contraction, a constant and a multiply, a broadcast and an add, the softmax, the value contraction, two nodes for the output merge, the output projection, and the residual add. The MLP half adds the post-attention normalization, three contractions, one SiLU, one multiply, and the second residual add, and L5's two concatenations are two more, so P2 carries at least fifty-one occurrences over at least twenty-one boundary values.

**Inference — three programs rather than one, and the ground is artifact-identity reuse rather than size.** Folding P1 into the first layer would make layer 0 a different artifact from layers 1–27, and folding P3 into the last would do the same at the other end: two identities for one computation, which is exactly the duplication L5 eliminated candidate P1 on. Keeping the ends separate makes the twenty-eight layer executions one artifact identity bound to twenty-eight different weight sets. **Inference — so the invariant a test can assert is exact:** the complete C1 run is nine forward passes of thirty executions, **270 executions over exactly three artifact identities**, and a build that produced a fourth would have specialized something it must not.

**Fact — no artifact carries the layer count, and that is the point.** `encode_identity` takes `&ArtifactEnvelope` and nothing else, as L5 records; the twenty-eight is a bound in the consumer's driver loop, and a checkpoint with thirty-two layers reuses P2's artifact unchanged.

### D-13 closed: the program boundary and the transaction boundary are two axes

L5 handed this rung a program-boundary and transaction-boundary question. Its numeric comparison assumed the now-rejected singular dense-allocation candidate: all twenty-eight candidate replacement allocations live for the token transaction, versus releasing one old allocation after each layer transaction. **Historical inference — within that candidate, the framing conflated two independent decisions.** A completion condition is per submission, so its lower-residency row required twenty-eight submissions and twenty-eight host completion observations per token. The arithmetic remains reproducible evidence about that candidate; it is not the current KV residency authority.

**Historical candidate grid, with the two axes separated.** These exact-live-allocation rows remain rejected-candidate evidence. [Dynamic KV physical-layout authority](../runtime/dynamic-kv-physical-layout.md) supplies the selected capacity-sized resource population and the current arithmetic immediately below the table.

**Survivor-independent inference.** Under the token transaction the twenty-eight layer executions share one ordered command stream, one terminal-success observation, and atomic publication of all 56 logical members. A layer transaction exposes mixed publication unless a separate recovery contract makes that state safe. The exact resource releases and residency delta are representation-dependent.

**Proposal — the design takes the per-layer program with the token transaction, and the derivation is not a fixed-layout cost comparison.** The program boundary is per-layer because it buys artifact reuse, layer-count independence, and a compiled program one twenty-eighth the size. The transaction boundary is the token because the architectural contract holds that an option exposing silently inconsistent or unrecoverable model state is a defect rather than an alternative. The selected pool's reservation delta is now explicit above, but arithmetic alone still does not establish a binding cost or make mixed-cursor recovery safe.

**Inference — L5's cursor-granularity rule is refined rather than contradicted.** What the rule protects is *observability*, not program size. A per-layer program boundary with **one model-level cursor and a generation per logical member**, published atomically after one observed terminal success, satisfies the same protection: no consumer can observe a partially advanced model, because all 56 logical members and the one cursor are replaced together. Independently advanced per-layer cursors stay forbidden; the physical resource count underneath each logical member is irrelevant to this rule.

## What refuses today, with exact numbers

**Inference — nothing in this design is buildable today, and the reasons are five separate refusals rather than one absence.** Each is stated with its exact site so that a reader can check whether it has moved.

1. **The deterministic budgets refuse all three programs.** **Fact —** `verify_program` at `crates/tiler-compiler/src/request.rs:1886` checks four resources against `DeterministicBudgets::governed()`: `semantic_values` 16 against `program.value_count()`, `semantic_operations` 8 against `program.operation_count()`, `regions` 3, `host_expression_nodes` 32, and `buffers` 4 against `4.max(program.input_count() + 1)`. **Inference —** P1 declares two inputs and one operation and passes every one; P3 declares three inputs and two operations and passes every one; **P2 exceeds three of the four** — eighteen inputs against a buffers actual of nineteen versus a limit of four, at least twenty-one values against sixteen, and at least fifty-one operations against eight. **Fact —** every budget is written into `VerifiedRequestSubject::canonical_bytes` (`request.rs:1193`–`1210`) and therefore into artifact identity, so widening one moves every artifact identity and every cache entry in the corpus, for programs that never approach the bound as much as for ones that do.
2. **The recognizer refuses all three, and it is a different refusal with a different remedy.** **Fact —** `select_supported_strategy` admits the bounded profile only, and `normalize_serial_sum` returns `mismatch("input-arity")` for `program.input_count() != 1`; a mismatch is `RequestError::UnsupportedCapability { phase, rule }`. The general compilation boundary's own 2026-07-31 correction states the position exactly: the entry point is general and "the admitted program subject is still the bounded one — a single input and a single output over an `f32` pointwise or scale-bias-then-strict-serial-sum shape". A budget widening does not admit a transformer; the families and their lowering capabilities do, and every one of them is at R1 or R2.
3. **The inline route refuses a symbolic region.** **Fact —** `crates/tiler-macros/src/aot.rs:365` returns `AotRefusal::SymbolicExtent` when the region carries no `SemanticProgram`, and its diagnostic says that a `deliver` statement "compiles the region ahead of time — which needs every extent to be known at expansion time". `T` and `S` are symbolic by construction, so no program in this design can state `deliver macos;` today. [`carry-symbolic-extents-into-the-semantic-program`](../../../tickets/carry-symbolic-extents-into-the-semantic-program.md) delivered the design that removes it, and its seventh delivery ticket, [`deliver-an-artifact-family-from-a-symbolic-region`](../../../tickets/deliver-an-artifact-family-from-a-symbolic-region.md), is the one this rung waits on.
4. **The facade cannot dispatch.** **Fact —** `select_embedded_route` in `crates/tiler/src/route.rs` walks the loader "exactly as far as a device-free caller can" and terminates at `RouteOutcome::NoDeviceAuthority`; `RouteOutcome::is_fallback` returns `true` for every variant, and the module documentation states that committing "would have committed to nothing" because the program work needs operand storage and a device object that `crates/tiler/src/value.rs` deliberately publishes neither of. [`route-an-embedded-artifact-through-a-consumer-storage-seam`](../../../tickets/route-an-embedded-artifact-through-a-consumer-storage-seam.md) carries that seam and is in progress. **This design composes with it and duplicates none of it:** every weight, every cache tensor, and the token IDs reach a dispatch through the same `TensorAdapter` the seam extends, and `AdapterCapability::DenseRowMajorStorage` is the capability the layer program requires of all eighteen of its operands.
5. **The Candle custom-op path cannot carry a decoder layer at all, and the gap is not marginal.** **Fact —** the landed adapter implements `CustomOp1` (`prototypes/candle-metal-adapter/src/wrapper.rs:548`) with `INPUT_KEY = "input"` and `OUTPUT_KEY = "result"` — one tensor input and one output — and the Candle integration contract states independently that "the initial integration supports at most three independent Tensor inputs" and that "Candle's current CustomOp return type does not represent multiple outputs". P2 needs eighteen inputs and three outputs. **Inference — so the first complete-model consumer is not the Candle custom-op wrapper**, and no amount of partitioning fixes it: a partition that fits `CustomOp1` is one operation per dispatch, and the three retained outputs the KV state needs have no return position at all. The route this design targets is the inline one with its storage seam; the Candle path remains the first *external consumer* proof and is not the model's launcher. Stating this is not a criticism of the adapter, which met its own subset exactly; it is the boundary its arity fixes.

**Inference — the honest ordering that follows.** Refusals 1 and 3 are widenings with owners; refusal 4 is in flight; refusal 5 is a boundary this record records rather than moves; and refusal 2 is the ladder itself — the families. Nothing here is partially built.

## Whole-model reference comparison and failure reporting

**Fact — the oracle is L1's and is not re-derived.** Five observables after prefill and after every decode step: logit agreement under a bounded-error level whose bound L8 owns and derives rather than assumes, greedy-token equality, the declared tie handling, termination as EOS 151643 or the row's budget and never implicitly, and plan determinism on the Tiler side alone. L1 also fixes the method: an error bound is a relation between two complete computations and is not the sum of per-operation tolerances, so nothing here composes one.

**Proposal — what this rung adds is that the model boundary can say *that* it disagrees and cannot say *where*, so two comparison surfaces are needed and they answer different questions.** The conformance surface is the five observables at the model boundary against the retained C1 fixture, and it is the pass or fail. The **attribution** surface is a per-execution comparison against the pinned reference's own intermediate values, and it is diagnosis rather than evidence: without it, a model-level disagreement is attributable to any of thirty executions, ten operation families, and four host computations at once.

**Inference — the attribution surface is small and cheap.** The C1 fixture retains logits; the reference can emit hidden states directly. Twenty-eight per-layer `h_out` tensors across the row cost `28 × 18 × 1024 × 4 = 2,064,384` bytes, and the post-RoPE `k_rope` and `v_heads` add `28 × 2 × 8 × 18 × 128 × 4 = 4,128,768` bytes — the same figure as L1's 18-position cache budget, because they are the same tensors. Both are regenerable local data under L1's retained-storage policy, and what is checked in beside them is the same small evidence L1 chose: a digest per tensor, plus the values needed for a bounded comparison.

**Proposal — four host computations join the comparison surface, and each is checkable in full.** L4 already recorded that the rotary tables do. This rung adds three more: the BF16-to-F32 widening of all 310 tensors, whose evidence is one digest over the widened bytes; the additive causal mask, whose two values L4 fixes as `0xff7fffff` and `0x80000000` and whose C1 prefill instance is 400 bytes; and the token IDs themselves, which L1 already retains. **Inference — the trade L2 accepted for the rotary tables generalizes**: removing a computation from the program moves it into the oracle's surface rather than out of the system, and the design's obligation is that each one is retained bit-exactly rather than assumed to agree.

**Measurement — the surface now exists, and every figure above was reproduced rather than only computed.** [`retain-the-c1-model-attribution-fixture`](../../../tickets/retain-the-c1-model-attribution-fixture.md) extended L1's own producer and its own evaluated F32 pass, so the intermediates belong to the execution that produced the retained logits rather than to a second run that would have had to prove it was the same one. The retained record is [the C1 conformance and attribution fixture](../../../spikes/program-planning/qwen3-conformance-fixture/README.md); the hidden states wrote exactly 2,064,384 bytes and the cache tensors exactly 4,128,768, the widened weight set is 310 tensors at 2,384,199,680 bytes with the widening bit-exact at every one, the prefill mask is 400 bytes carrying only the two admitted values, and the digest unit is one *position* of one tensor rather than one tensor — which is what resolves a disagreement to a pass as well as to a layer. **Inference — the surface is not yet a comparison.** Nothing has been compared against it, no Tiler execution exists to compare, and the record deliberately measures no deviation on it: whether a per-execution disagreement implies a model-level one, and by how much, is error propagation, and the bound remains [`design-model-level-qualification-and-optimization`](../../../tickets/design-model-level-qualification-and-optimization.md)'s.

**Fact — one retention detail the design had not foreseen, recorded because a reader would otherwise reach for the wrong API.** `output_hidden_states=True` does not return the twenty-eight `h_out` tensors this surface names. `Qwen3Model.forward` appends `hidden_states` at the top of each layer iteration and appends `self.norm(hidden_states)` after the loop, so the tuple is the embedding output, twenty-seven layer outputs, and the normed final state; layer 27's own `h_out` never appears in it. ## Typed refusals this design owes

Each is a place where a silent approximation would return a plausible tensor. Refusals L4 and L5 already own are not restated.

- A bound weight whose rank, stored scalar, or literal extent disagrees with the region's declaration refuses at the runtime-value boundary, before any route, naming the interface key and both values. **Implemented**, as `BindError`.
- A bound weight whose *identity* disagrees — a permutation within a shape class — is **not refused and cannot be**, and the design says so rather than inventing a check. The named enforcement boundary is the consumer's weight binding manifest, verified against the checkpoint's own header under a pinned digest, and the refusal is that the manifest stops rather than warns.
- A token ID outside `0..151936` refuses or is validated at a named enforcement boundary; it never clamps, never wraps, and never reads out of bounds. This refusal does not exist today and belongs to the gather family.
- A program input at an integer identity with no admitted storage carrier refuses at the runtime-value boundary rather than being carried as an F32 that happens to hold an integer.
- A model whose declared context exceeds `max_position_embeddings = 32768` refuses at the semantic layer. *Corrected 2026-08-04:* this bullet paired that with "one whose `C + T` exceeds a layer state's capacity refuses at the runtime instance", and the second half is withdrawn with the runtime-owned state — Tiler is handed one tensor per invocation and knows no capacity to compare against. The remaining refusal is unchanged, and the withdrawn one becomes the consumer's own bound on its own pool, checked before it binds.
- A forward pass in which any execution falls back after another execution's routing commit refuses rather than completing, naming both ordinals, because the result would compose two numerical contracts and report one.
- A post-commit failure at any of the thirty executions names the ordinal and the token in flight, makes no output of that execution observable, and is never silently retried. *Corrected 2026-08-04:* this read "poisons the *model* state … it never poisons a single layer state and leaves the others usable". Tiler holds no model state to poison. The obligation it protected splits cleanly and both halves stand: Tiler owes the typed failure with its ordinal and the withheld outputs, and the consumer owes advancing all 56 members and its cursor together or not at all, which is what makes "some layers advanced and others did not" unrepresentable on its side rather than refused on Tiler's.
- A build that produces more than one artifact identity for the twenty-eight layer executions is refused at artifact assembly, on the same ground L5 states for a per-decode-step compilation: it would have specialized on a quantity that is a binding rather than a program.
- A weights set bound at a stored scalar the region did not declare refuses by name, which is what makes host-side BF16 widening a checked step rather than a convention.
- A conformance comparison reported without naming the operations it covers is refused as a report, under the obligation the Candle contract's Diagnostics section already carries; a model-level claim covers thirty executions and four host computations, and saying so is part of the claim.

Performance evidence alone would not make the change safe.
- **D-17 — the storage carrier for an integer program input.** `StorageScalar` has `U8` and `F32`; the semantic layer registers `tiler::u32@1`. Widening the carrier is an artifact-ABI change because `StorageScalar::tag` participates in canonical encoding; carrying token IDs as `F32` avoids it and buys a float-to-integer conversion contract at the one operation whose out-of-range behaviour reads out of bounds. **Closes** with Tom, because it is a public boundary; the filed ticket carries both readings and this record's recommendation, which is the widening.
- **D-18 — whether the deterministic budgets are widened once, sized to the decoder-layer program, or grow with the profile.** Every budget is inside the request subject and therefore inside artifact identity, so each widening moves every artifact identity and every cache entry in the corpus — which makes the number of widenings a real cost and not a scheduling detail. The precedent is the split reduction, whose widening from two regions and three buffers to three and four was taken once and stated. **Closes** with Tom when the layer program's exact counts exist, which is delivery ticket 2 below.
